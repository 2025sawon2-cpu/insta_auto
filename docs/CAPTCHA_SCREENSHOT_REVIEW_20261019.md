# CAPTCHA 화면 캡처·독립 재검토·보관

2026-10-19 사용자 요청: 앞으로 CAPTCHA로 판정하면 스크린샷을 찍고 진짜 CAPTCHA인지 재검토해 저장한다.

## 반영한 동작

1. URL·본문의 인증 문구 탐지는 의심 신호로만 사용한다.
2. 현재 수집용 탭의 화면을 PNG로 저장하고 실제 파일 SHA를 계산한다. 새 창·프로필·계정으로 이동하지 않으며 인증을 풀거나 새 검색을 제출하지 않는다.
3. 캡처를 저장한 다음 내부 Codex 이미지 검토기에 전달한다. 검색 결과/영상 설명의 문구와 실제 인증창·슬라이더·퍼즐·체크박스를 구분하도록 독립 판단을 요청한다.
4. `captcha`(인증창 확인), `clear`(CAPTCHA 아님), `captcha_review_pending`(캡처/검토 실패 또는 미확정)을 구분한다. 확정 CAPTCHA만 인증 차단으로 저장하며, 오탐은 기록을 보존하고 정상 검색으로 이어간다. 미확정은 요청을 보류하지만 콘텐츠 실패나 검색 최소 완료 수에 넣지 않는다.
5. 캡처·탐지 문구/영역·플랫폼·검색어·시각·검토 결론/근거·원본 SHA와 영수증 SHA를 결속해 보관한다. 스크린샷이 바뀌거나 소실되면 이전 판정을 확정 근거로 재사용하지 않는다.

저장 위치: `data/captcha_reviews/{provider}/{입력키}/{캡처ID}/`

- `screen.png`: 당시 실제 화면 원본
- `evidence.json`: 캡처 시각·파일 SHA·URL·검색어·탐지 근거
- `review-*.json`: 모델 호출 전 저장한 검토 대기 기록
- `result-*.json`: 독립 이미지 검토 결과와 근거
- 캡처 자체가 실패하면 `capture-pending.json`에 실패 유형을 남기고 CAPTCHA로 확정하지 않는다.

이 파일은 Git 제외 로컬 자료이며 기존 Cloudflare 비교 페이지에 공개하지 않는다. 쿠키/인증 헤더를 수집하지 않는다. URL 검색 인자는 검색용 항목만 기록한다. 스크린샷에 보이는 계정 UI는 로컬 증거에 포함될 수 있다.

## 연결 범위와 복구

`captcha_review.py`를 `browser_search.py`의 일반 검색·늦게 나타난 인증 의심 처리, 저장된 인증 기록 재확인, `source_access_preflight.py`, 명시 검색/세션 확인에 연결했다. 검색 manifest와 이력 병합은 검토 영수증 포인터를 보존한다. 429·로그인·검색 결과 없음은 CAPTCHA와 구분한다. HTTP 응답만 있고 화면 캡처가 불가능한 indexed 경로도 CAPTCHA 확정 대신 재검토 대기로 분류한다.

같은 탭/검색/본문/검토 영역의 유효한 캡처·검토는 재사용하여 단순 준비 점검마다 같은 모델을 실행하지 않는다. 사용자의 명시 세션 저장/재확인은 새 검토를 허용하며 이전 캡처와 결과는 보존한다. 검토 도중 URL·인증 문구/영역이 바뀌면 캡처의 검토 결과는 남기되 현재 화면의 확정 판정으로 적용하지 않는다.

제작실·플랫폼 로그인 화면에도 `인증 의심 화면 재검토 대기` 표시를 추가했다. 과거 완료/중지 작업은 이 코드 적용만으로 재개하지 않았다.

## 검증

- 관련 회귀 **238개 통과**. 마지막 탐지 문구 상수 통합 후 핵심26개도 통과했다(중복 검증이므로 합산하지 않는다).
- 실제 PNG 저장 후 모델 호출, 확정/오탐/미확정, 캡처 실패, 모델 실패, 잘못된 응답, 이미지 변조, 이력 포인터 보존, 페이지 변경, 명시 재확인, 로그인/429 구분을 검사했다.
- 실제 writing 큐의 이미지 파일 전달 경로까지 검사했다. 초기 실측에서 잘못된 이미지 첨부 형식 때문에 모델이 이미지를 받지 못한 문제를 발견했고 `inlineData` 전달로 고친 뒤 해당 회귀를 추가했다. 초기 미확정 영수증도 보존했다.
- 변경한 JS3파일의 `node --check` 통과 및 운영 HTTP200/새 상태 표시 문자열 제공을 확인했다.

**실제 현재 화면 검증:** 같은 기존 TikTok 키티 검색 탭을 이동·검색 없이 캡처해 실제 공식 모델에 전달했다. 8.87초 후 `not_captcha / visible_challenge=false`로 판정했다. 근거는 검색 탭·상품 영상 썸네일·사용자/팔로우 UI가 보이고 인증창/퍼즐/슬라이더가 없다는 것이다. 원 PNG SHA는 `e02eab9b613f5b1918d5259dc14b2c07dc09a0e47cbe401ed3249f768786d781`, 결과 영수증 SHA는 `da7586b68471701d8ee7cb3ca62acdc2509e3160fa982d6602c4ef9435edf1f1`이다.

실제 증거: `data/captcha_reviews/tiktok/77f1830a6dae41d96c09/13268a45b1/screen.png` 및 `result-a4792f5f.json`. 요약은 `data/captcha-review-20261019/live-review-result.json`. 실제 플랫폼 CAPTCHA 발생을 유도하지 않았으며, 확정 양성/실패 분기는 격리된 이미지·검토기 테스트로 검증했다. 이번 실제 확인이 과거 자동 판정의 진위를 소급 증명하지는 않는다.
