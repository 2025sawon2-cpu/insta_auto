# 십대 폰트와 첫 프레임 썸네일

현재 글꼴·문구·표지 판정은 [RULES](../hotpost/writing/RULES.md)가 원본이다.
아래는 스타일 이행 및 개별 영상 검증 이력이다. 초기 폰트 대체나 후킹 문장
자동 복사 설명은 신규 기본값이 아니며, 현재 본문 십대·표지 KCC간판체와 별도
썸네일 문구를 적용한다. 리소스 ID·실제 글꼴명·그림자 단위 설명은 구현 참고로 보존한다.

2026-10-10 제작 규칙 변경. 사진 게시물 제작은 계속 비활성화한다.

- CapCut 9.5의 폰트 목록에서 `십대`를 직접 적용해 저장된 리소스를 확인했다. 리소스 ID는 `6841117356756832776`, 파일은 `DSDSRefinedLetterM.ttf`다. MP4 ASS에서는 실제 family `DSRefinedLetter M`을 사용해야 한다. `DSRefinedLetter`로 요청하면 Arial·맑은 고딕으로 대체된다. 실제 FFmpeg 로그에서 `DSVWrittingM` 선택을 확인했다.
- 본문 자막 그림자 흐림은 UI 60%, 썸네일은 80%다. CapCut에서 UI 60%를 직접 저장하니 `shadow_smoothing=1.8`, 스타일 그림자의 `diffuse=0.1`이었다. 현재 버전의 대응은 `smoothing=3×비율`, `diffuse=비율/6`이며 80%는 각각 2.4와 0.133333이다. MP4는 별도 흐림 그림자 레이어를 사용한다. 그림자의 이동 거리와 흐림을 혼동하지 않는다.
- 첫 프레임 하나만 하이라이트 이미지로 교체한다. 30fps에서 약 0.033초다. 썸네일 동안 본문 자막은 숨긴다. 두 줄 문구는 음성 대본과 별도 `cover_spec.lines`에 보존하며 음성과 대본 해시를 바꾸지 않는다.
- 실제 사용되는 모든 소스 구간에 분산된 후보를 추출하고, 제품과 핵심 동작을 실제 프레임으로 확인한다. 선택된 소스 해시와 시간은 실제 사용 구간에 있어야 한다. 자동 선명도 순위는 의미 검토를 완료한 것으로 기록하지 않는다.
- 썸네일은 흰색·노란색 두 줄, 굵기 보강, 이탤릭과 −8° 회전, 검은 외곽선과 흐림 그림자다. 오래된 완성본과 타임라인의 스타일은 보존한다. 신규 타임라인에는 새 스타일을 기본 적용한다. 폰트 캐시가 없는 PC에는 상태를 명시하고 기존 폰트로 안전하게 처리한다.
- 썸네일 요약 문구가 제공되면 그대로 사용한다. 제공되지 않은 신규 작업은 승인된 첫 후킹 문장 전체를 두 줄로 나눈다. 별도 의미 요약 모델이 자동 집필했다고 표시하지 않는다.

## 두 영상 검증

`tools/build_typography_rework.py`는 Auto CapCut을 별도 Python 프로세스로 호출한다. `prepare → preview → render → qa → attach` 순서다. 수동 검토를 끝내기 전 `attach`는 거부한다.

`DeNb4AsSgGw`, `DeOhQMSzm5N`의 새 버전은 `new-edit-v4-font-cover`다. 원본 대본·음성·소스 사용 구간을 보존했다. 이전 완성본의 오디오 스트림을 그대로 복사해 디코딩된 음성 및 효과음 해시가 같고, 프레임 수도 같다. 전체 디코딩 검사와 첫 두 프레임·분산된 본문 프레임의 시각 검토를 완료했다. 관련 회귀 검사 39개가 통과했다.

Portable CapCut 프로젝트에는 썸네일 텍스트 두 줄이 별도 편집 가능한 트랙으로 들어간다. 두 트랙의 시작 0, 길이 33,333µs와 본문/썸네일 그림자 값 및 폰트 리소스를 검사했다. 사용자의 CapCut 프로젝트 레지스트리는 변경하지 않았다. MP4는 FFmpeg/Pillow 렌더 결과이며, CapCut 자체 내보내기와 픽셀 단위 일치는 검증하지 않았다.

`tools/share_typography_rework.py`는 원본 왼쪽·완성본 오른쪽, 이전 버전 전환, 썸네일 전후 보기와 다운로드를 제공한다. 별도 8789 포트의 파일 허용 목록 서버를 Cloudflare로 공개한다. 영상 범위 응답 및 다운로드 헤더를 검사하며 Studio API는 공개하지 않는다. 기존 비교 서버와 링크는 보존한다. 임시 링크는 PC·터널 실행 중에만 유효하다.

운영 영수증은 Git 제외 `data/two-typography-rework-share.json`, 프레임·폰트 UI 근거와 각 버전의 `verification.json`은 `data/source-quality-rework-20261010/`에 보존한다. 앱 내 브라우저의 새 비교 URL 열기는 브라우저 권한 정책에서 거부되어 화면 레이아웃 검토는 미완료다. HTTP 응답과 실제 렌더된 영상 프레임 검사는 완료했다.

## 2026-10-11 도현 썸네일

새 제작 계획의 썸네일 기본 폰트는 공식 Do Hyeon(도현)이다. Auto CapCut의
`auto_capcut/assets/fonts/DoHyeon-Regular.ttf`와 OFL 라이선스를 함께 보존한다.
본문 십대와 썸네일 도현을 별도 계획·렌더·네이티브 텍스트 트랙에 적용한다.
폰트 파일이 없으면 임의 대체하지 않는다. 과거 완성본을 일괄 변경하지 않는다.

TikTok 재제작 3편은 도현 두 줄 문구, 첫 1프레임 썸네일, 본문 60%·썸네일 80%
그림자 흐림을 검사했다. 각 영상의 실제 출력 첫 두 프레임과 분산된 본문 10개
프레임을 확인했다. 파일홀더 예시본의 다른 제품 안내는 썸네일 이미지와 본문 별도
트랙에 함께 반영한다. 같은 표시가 MP4와 편집 가능한 네이티브 프로젝트에 남는다.

대본은 공식 Codex CLI로 이번 묶음에 3안씩 생성·검토해 저장했다. 이 묶음의 실행은
일반 자동 제작 전체에 3안 생성 계약을 구현했다는 뜻이 아니다.
# 2026-10-11 썸네일 미지원 기호 수정

도현 파일은 U+00B7 중간점을 지원하지 않아 패딩 썸네일의 `흰 몸판·검은 어깨`가 네모로 렌더링됐다. 실제 비교 페이지에서 발견했고 Pillow에서 중간점의 마스크·경계·advance가 미지원 문자 모양과 동일함을 확인했다. `studio_cover.paint`는 이제 해당 모양을 검사해 문자와 코드포인트를 포함한 수정 안내를 반환한다. Unicode 전체 지원을 보증하는 cmap 검사는 아니다.

새 표시 버전은 `흰 몸판에 검은 어깨 / 다른 걸로 바꾸라고?`다. 도현·기울기·80% 그림자, 본문 십대·60%, 첫 1프레임을 유지했다. 원고·음성 메타데이터·선택 장면·클립 페이로드·첫 본문 클립·자막·효과음·디코드된 완성본 오디오가 이전본과 동일함을 검증했다. 실제 커버와 12장 검토 프레임을 확인했으며, 후킹 성과와 전체 품질 통과를 뜻하지 않는다. 기존 편집·음성·대본·작업 기록과 공유 링크는 보존한다.
