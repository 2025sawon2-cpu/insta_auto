# PC별 완성 영상 저장

저장 위치는 각 사용자 PC에서 정한다. 개인 드라이브/공유 폴더 경로는 `local/video-storage.json`과 `local/VIDEO_STORAGE.md`에만 기록한다. `/local/`은 Git에서 제외하며 원격 저장소에는 실제 경로나 개인 규칙을 올리지 않는다. 다른 PC에 이 설정을 자동 복제하지 않는다. Git worktree에서는 원래 clone의 로컬 설정을 공유한다.

## 최초 설정

저장할 절대 경로를 정하고 이 저장소의 Python 환경으로 다음을 실행한다. 지정 폴더가 없으면 만든다. 예시의 경로는 해당 PC에서 정한 경로로 바꾼다.

```powershell
python -m hotpost.publication_export configure 'D:\MyVideos'
```

설정이 없는 PC에서는 다른 사용자의 경로를 추측해 저장하지 않는다. 사용자가 경로를 정하기 전에는 프로젝트 안의 원본을 보존하고 개인 폴더 저장이 미설정임을 알린다.

## 영상 작업의 완료 절차

에이전트는 영상 작업 시작·세션 재개·완료·썸네일 변경 완료 시 이 문서와 실제 로컬 규칙을 읽는다. 현재 결과에 결속한 최종 QA 후, 완료 보고 전에 아래 저장 도구를 실행한다. 제작 코드에서 직접 연동할 때도 `save_current`를 같은 완료 지점에서 호출한다. 이 규칙은 완료 후 에이전트가 실행하는 절차이며 별도 상주 감시기나 제작실 실행기를 재가동하지 않는다.

```powershell
python -m hotpost.publication_export save POST_SHORTCODE --topic '간단한주제명' --qa-record '현재-task-run/final-qa.json'
```

- `local/video-storage.json`의 `topics`에 게시물 shortcode별 주제명을 적으면 `--topic`을 생략할 수 있다. 명시한 주제명이 우선한다. 주제명은 24자 이내로 정리하고 파일명 금지 문자는 제거한다.
- 한국 시간으로 저장일 `YYYY-MM-DD` 폴더를 만든다. 파일명은 `YYYYMMDD_주제명.mp4`, `YYYYMMDD_주제명_썸네일.png`다. 썸네일은 실제 적용본의 이미지 확장자를 유지한다.
- 주제명은 그 영상의 확정된 내용이 바로 드러나는 짧은 이름으로 정한다. 최종 MP4와 **지정 후 실제 적용까지 확인한 썸네일**은 같은 날짜 폴더에 같은 `YYYYMMDD_주제명`을 파일명 앞부분으로 써서 함께 저장한다. 게시물 코드나 순위만으로 주제명을 대신하지 않는다.
- `PostPreparation.source`가 선택한 검증된 완료본과 현재 실제 적용된 표지를 복사한다. 화면에서 고르기만 하고 반영하지 않은 문구로 표지를 새로 만들지 않는다. 영상은 H.264/yuv420p와 AAC 호환 여부를 확인하며 재인코딩하지 않는다.
- `--qa-record`는 [제작자의 현재 파일 QA](WORKFLOW.md#현재-파일에-결속한-제작자-qa-기록) JSON이다. 저장 도구는 현재 run/edit·실제 영상·적용 표지와 QA 기록이 맞는지 복사 전후 검사한다. 새로운 썸네일을 반영했으면 바뀐 최종 파일을 다시 검토하고 기록을 갱신한다. 기술적으로 저장 가능한 기존 파일이라도 QA 기록 없이 새 저장 완료로 처리하지 않는다.
- 원본은 그대로 보존한다. 같은 파일 쌍은 `already_saved`로 확인하고, 같은 이름의 다른 내용은 덮어쓰지 않고 `_02`, `_03` 번호를 붙인다. 복사 전후 SHA256과 현재 결과의 버전을 확인한다.
- 저장 드라이브 연결/권한/용량/검증 실패 시 저장 완료로 보고하지 않는다. 영상 제작 성공과 개인 폴더 저장 성공을 구분하고 원본을 보존한다. `.video-export.lock`이 남아 있으면 실제 저장 프로세스와 중단 여부를 확인하고 처리하며 무조건 지우지 않는다.

저장 도구는 영상 제작·수집·TTS·실제 게시를 실행하지 않는다. 과거 전체 완료본을 일괄 복사하는 작업은 별도 요청이 있을 때만 수행한다.

Git worktree의 개발용 data 폴더에는 운영 완료 자료가 없을 수 있다. 실제 완료 자료를 보유한 원래 작업 폴더의 Python 환경에서 저장하거나 명시적으로 그 data 경로를 지정한다. 빈 개발용 DB를 완성본으로 대신하지 않는다.

## 2026-10-23 적용·검증

작업 브랜치 `feat/local-video-storage-20261023`, 기준 main `0d70439`. 같은 버전의 `COLLABORATION.md` 원문을 확인하고 기존 미커밋 작업을 보존했다. 저장 경로는 이 PC의 Git 제외 로컬 파일에만 기록했다. 검증된 현재 완성본 한 건과 실제 적용 썸네일을 개인 저장소에 복사하고 SHA256 일치를 확인했다. 반복 실행은 `already_saved`, 다른 내용의 동일 이름은 기존 파일을 보존하는 번호 추가로 처리한다.

관련 Python 36검사 통과. 날짜의 한국 시간 변환·개인 설정 보존·두 파일 검증·기존 파일/다른 에이전트 잠금 보존·복사 손상·진행 중 완료본 교체·미완료/표지 누락 거부·호환되지 않는 영상 거부를 확인했다. 저장 규칙은 완료 후 에이전트가 실행하는 절차이며 상주 감시/서버 재시작/기존 제작실 변경은 없다. 개인 경로와 실제 저장 증거는 로컬에 보존한다.
