# 핵심 제품 우선 수집·배치 v6 — 2026-10-19

> 역사적 구현 기록: 보존된 v6 자동 제작 run의 당시 계약과 검증이다. 현재 소스 선정은 [SOURCE_WORKFLOW.md](SOURCE_WORKFLOW.md)의 컷 역할 기준을 따른다. 이 문서의 핵심 제품 5개 우선·핵심/보조 전환을 현재 제작에 새로 적용하지 않는다.

## 사용자 승인과 변경 범위

관련 원본 합계5·핵심1로 수집을 끝내지 않고, 이번 영상의 핵심 제품 원본을 다양하게 확보·사용한 뒤 확인된 부족분만 보조영상으로 채운다. 신규 제작 정책은 v6이며 저장된 v1~v5 run은 이전하지 않는다. 기존 완료·중지 작업은 이 코드 변경으로 재개하지 않는다.

영어5·중국어5의 실제 고유 핵심 검색, 최종 본문 서로 다른 관련 원본 최소5, 대본 우선 집필, 개인 목소리, 정상 속도 연장·반복·몽타주 허용은 유지한다. 음성·대본을 재생성하거나 기존 결과물을 덮어쓰는 변경이 아니다.

## 구현한 흐름

1. **제품 정체성 검토:** v6 기능 검토는 `featured_product_identity`와 실제 관찰 근거를 추가한다. 중심 브랜드/모델/구조가 다르면 기능이 비슷해도 핵심으로 세지 않는다. 브랜드 없는 주제에 브랜드를 요구하거나 모든 부가 특징·색상·동작을 강제하지 않는다. 실제 후보 화면과 그 후보에 결속된 출처 제목을 함께 볼 수 있으며, 검색어 또는 원작 설명만으로 후보의 브랜드를 확정하지 않는다. 출처 제목은 성능 보증이 아니다.
2. **핵심/관련 제품/맥락 분리:** `source_core_priority.py`가 현재 제품·레퍼런스의 검토 근거로 역할을 판정한다. 다른 run에서도 제품·원작 SHA·원문이 같으면 픽셀 정체성 검토를 재사용할 수 있지만, 검색과 부족 근거는 현재 run에 별도로 결속한다.
3. **수집 목표:** 핵심 실제 원본5를 우선 목표로 한다. 관련5·핵심1이고 실제 검색10개를 충족해도 수집 준비가 되지 않으며 검색 횟수만 채우는 경로로 바뀌지 않는다. 받은 작은 묶음의 남은 검토는 마쳐 여섯 번째 유효 핵심도 버리지 않는다.
4. **후보 순서:** 실제 제목에서 핵심 조건이 확인되는 후보를 다운로드·검토 우선순위에서 올린다. 제목만으로 승인하지 않는다. v6는 플랫폼별 선호보다 그 근거를 우선한다.
5. **추가 탐색 범위:** 원래 독립 승인된 핵심 전용 명사구 전체(기본 제품명·확인된 부가 특징 변형)와 실제 접근 가능한 플랫폼/이미지 범위로 유한 계획을 기록한다. 다른 플랫폼의 미사용 범위를 이어 찾는다. 실행한 경로·접근 불가로 제외한 경로는 구분한다. 인터넷 전체 소진을 주장하지 않는다.
6. **부족 판정:** 계획의 경로들이 현재 점검에서 실제 소진됐고, 현재 run 핵심 영어5·중국어5와 수신 소스 검토가 끝난 경우에만 `core_fallback`을 기록한다. 계획한 경로의 CAPTCHA/로그인/429/판독 대기/미사용 범위는 부족으로 전환하지 않는다. 핵심0은 보조로 완성할 수 없다.
7. **분리된 보조 수집:** 부족 근거가 있는데 관련 원본 수도 부족하면, 이미 독립 승인된 제품 명사의 범위로 별도 보조 검색을 수행한다. 이 단계의 실제 검색 영수증에는 `search_purpose=support`를 남기며 핵심 영어/중국어 최소 실적에는 세지 않는다. 임의 리액션 검색어나 제품 사실을 새로 만들어 넣지 않는다.
8. **매칭 후보 보존:** 핵심 부모 원본을 다양하게 남기도록 장면 순위 요청을 바꾸고 신규 핵심 계약에서 최대12개 후보를 보존한다. 실제 반대 동작·제품 오인·특징별 제외를 제거해서 숫자를 채우지 않는다.
9. **배치:** 자막/음성과 분리된 화면 컷에서 배치 가능한 핵심 원본 수를 먼저 확보한다. 전체 선택은 핵심 다양성, 보조 노출 최소화, 기존 편집 비용의 순서로 비교한다. 필요한 경우 승인 구간 내에서 화면 컷을 나눈다. 후보·증거 구간·타임라인상 불가능한 핵심 수를 새 하드게이트로 강제하지 않는다. 단일 원본 반복보다 쓸 수 있는 서로 다른 핵심 원본을 우선한다.
10. **완성 검증:** 핵심 역할과 원본 SHA, 사용 수, 핵심 본문 노출 비중, 미사용 핵심과 사유, 보조 컷의 사유를 최종 계획/품질 보고에 남긴다. 새로운 정책 필드가 JSON 경계에서 사라지거나 선택 후 변경되면 통과시키지 않는다.

## 중복과 검토 비용

- 원본 SHA·출처·부모 파생 관계의 중복 검사는 유지한다.
- v6의 시각 중복은 비슷한 제품 프레임 두 장만으로 탈락시키지 않는다. 4개 이상의 같은 수 샘플에서 90% 이상이 순서별 근접 해시를 갖고 길이도 가까운 경우에만 재인코딩 중복으로 취급한다. 다른 길이·다른 촬영 구도가 두 장만 비슷한 경우를 중복 처리하지 않는 회귀 검사를 추가했다.
- 이 역시 샘플 기반 휴리스틱이며 모든 재편집·부분 재업로드를 완벽하게 식별한다는 의미는 아니다.
- 기존 동일 픽셀 검토·수신 묶음 캐시를 재사용한다. 회차별 핵심 수 증감·검색 범위 수·보조 전환과 실행시간을 저장한다. 실행시간은 모델 대기를 포함하며 병행 대본/음성과 단순 합산하지 않는다.

## 제작시간 영향과 측정

핵심1로 끝내던 제작보다 검색·검토가 늘 수 있다. 기존 영어5·중국어5를 이중 비용으로 계산하지 않는다. TikTok 추가 검색/상세 열기6·12·20회는 현재30초 간격상 대략3·6·10분 규모의 간격 비용이 발생할 수 있으며 다운로드·검토·외부 대기는 별도다. 대본/음성과 겹치는 시간은 전체 시간에 중복 합산하지 않는다.

다음 실제 제작에서 비교할 값: 핵심 확보 수/실사용 수/노출 비중, 보조 전환 사유, 추가 검색 범위·유효 핵심 원본당 비용, 수집 총시간, 큐/접근 대기, 편집 이후 재수집·재렌더링, 전체 경과시간. 이번 구현 시험만으로 실제 제품 제작시간 단축률을 주장하지 않는다.

## 검증 범위와 남는 한계

이 작업은 로직·격리 실행·배치 회귀 검증이다. 새 실제 제품 영상을 외부 검색부터 제작하지 않았으며 실제 플랫폼의 핵심5 확보나 새 완성 영상 품질·실측 제작시간은 아직 증명하지 않았다.

추가 탐색은 현재 브라우저가 구현한 실제 범위에 한한다. 지원하지 않는 다음 페이지/커서 탐색을 수행한 것으로 기록하지 않는다. 출처에 없는 현지 명칭을 모델이 임의 생성하는 무한 확장도 추가하지 않는다. 보조 검색은 승인 제품 명사 기반이며 별도의 새로운 리액션 검색어 생성기는 이번 변경에 포함하지 않는다.

자동 배치는 제한된 후보/탐색 안의 결과이며 모든 편집 조합의 절대 최적을 보장하지 않는다. 모든 원본을 짧게 끼워 넣는 방식이나 모든 대사에 직접 시연을 강요하는 기준은 추가하지 않았다. 기존 연속 재생·청감 전체 검수의 한계는 이번 변경으로 해결됐다고 주장하지 않는다.
