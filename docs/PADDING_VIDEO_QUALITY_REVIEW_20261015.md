## 4. 확인된 결함과 원인

### P0. 중국어 마스크가 컷 첫 프레임에 적용되지 않는다

관련 코드: `auto_capcut/auto_capcut/core/studio_render.py:256` 및 `studio_masks.py:77`, `:128`.

렌더러는 ffprobe의 `best_effort_timestamp_time` 문자열을 float로 읽는다. 마스크 코드는 승인된 명목 프레임 번호를 이 실제 시간표로 옮긴 뒤, `gte(t, start - 1e-7)`로 시작 여부를 판정한다. 실제 concat 시간축을 사용하는 설계는 맞지만 ffprobe의 소수 표기 반올림 오차가 `1e-7`보다 클 수 있다.

| 출력 프레임 | 실제 마스크 입력 PTS / time base | 실제 입력 시각 | 저장 시각에서 epsilon을 뺀 시작 임계값 |
|---|---|---:|---:|
| 70 | 35825 / 15360 | 2.332356770833… | 2.332356900 |
| 388 | 198641 / 15360 | 12.932356770833… | 12.932356900 |

두 경우 실제 프레임 시각이 임계값보다 작아 해당 프레임이 마스크 적용에서 빠진다. 495개 입력 프레임의 ffprobe 소수 시각은 저장된 `mask_application_clock.frame_pts`와 대응함을 확인했다. 최종 CFR 출력의 2.333333초를 마스크 전 입력 시각과 혼동하면 원인을 놓친다.

이번 노출은 자막 위치를 전혀 찾지 못한 사례가 아니다. 바로 다음 프레임에 같은 영역의 마스크가 적용된다. 따라서 단순히 블러 강도나 검출 상자를 키우는 처방은 맞지 않는다. 모든 마스크를 무조건 2프레임 앞당기는 처방도 이전 컷을 오염시킬 수 있다.

### P0. 검수가 첫 프레임을 보지 않고 통과한다

관련 코드: `hotpost/daily_quality.py:394`.

컷별 상세 표본은 길이의 12%, 50%, 88%다. 2.333초에 시작하는 컷의 첫 QA 표본은 2.412533초, 12.933초에 시작하는 컷의 첫 표본은 13.047467초다. 둘 다 노출이 사라진 뒤다. 전체 영상 디코드 성공과 파일 SHA 일치는 디코딩 가능성·산출물 동일성을 확인할 뿐 마스크 품질을 확인하지 않는다.

최종 QA에는 `visual_repeat_detection_complete=false`도 기록되어 있다. 이는 정직한 범위 표기지만, 전체 품질 통과를 해석할 때 그 한계를 함께 다뤄야 한다. 숫자 임계값만으로 통과/실패시키자는 뜻은 아니다. 명확한 한 프레임 노출은 픽셀 검사로, 매력·흐름은 전체 편집을 보는 별도 검수로 잡아야 한다.

근거 없는 장면 이동을 막는 목적은 타당하다. 문제는 **선택 전 탐색 범위 제한과 선택 후 검증 결과 고정이 섞여 있다는 것**이다. 최종 승인된 계획을 렌더러가 바꾸지 못하게 고정하는 것은 유지하되, 전체 반복감을 고치는 작업에서는 앞 단계의 관련 장면 묶음까지 다시 선택할 수 있어야 한다.

### P1. 구도·화질·마스크 모양의 평가가 약하다

초록 패딩 원본은 720×960이다. 9:16 중앙 채움 시 약 540×960이 남아 가로 약 25%가 잘리고, 1080×1920 출력으로 약 2배 확대된다. 화면 위쪽 천장 비중이 크고 옷은 하단에 몰리며 동작 중 흐림도 있다. 원본의 춤이 주목을 끌 수는 있지만 제품 중심 구도로서 항상 좋은 선택은 아니다.

`source_presentation.py:96`의 사용 가능/동작 보존 판단만으로 좋은 구도 순위를 결정하기 어렵다. `source_mask_review.py:211`의 제안은 표본에서 찾은 상자를 승인 구간 전체에 적용하므로 서로 다른 시점의 영역이 겹쳐 넓은 블러로 남을 수 있다. 실제 선택 구간에서 필요한 영역과 제품을 가리는 정도를 함께 평가해야 한다. 이 패딩의 큰 블러가 전부 불필요하다는 판정은 하지 않았다.

### 단계 1 — 마스크 시간축과 경계 검증을 함께 수정

수정 범위: AutoCapCut `studio_render.py`, `studio_masks.py`, 해당 테스트. Hotpost `daily_quality.py` 및 검수 결과 계약.

1. ffprobe의 정수 `best_effort_timestamp`와 스트림 `time_base`를 보존한다. 승인 구간은 먼저 전역 프레임의 반열린 범위 `[start_frame, end_frame)`로 확정한다. 원본 PTS → 선택 구간 → concat 프레임 → 최종 출력 프레임의 연결을 기록한다.
2. FFmpeg의 시간 기반 enable을 유지한다면 인접 정수 PTS 사이의 중간값으로 경계를 정해 정확히 의도한 프레임 집합을 선택하도록 한다. 첫 프레임·마지막 끝 경계는 별도 정의한다. 시간을 재기준화한다면 해당 변환을 명시하고 검증한다. 상수 epsilon 확대나 overlay별 `n`에 대한 추측으로 대체하지 않는다.
3. 마스크 사각형·강도·적용 프레임과 최종 파일 SHA를 검수 영수증에 묶는다. 기존 소수 시간표 캐시와 새 계약의 버전을 구분한다. 과거 완료본은 재렌더하거나 상태를 바꾸지 않는다.
4. 컷·마스크 시작/끝마다 `k-1,k,k+1` 출력 프레임과 표지 0번을 검사한다. 마스크 경계가 컷 중간이면 그 경계도 포함한다. 선택 구간 내 문자 변화는 별도 표본/검사 범위로 다룬다.
5. 합성 영상에 프레임 번호와 고대비 문자를 넣어 독립적인 기대 적용 집합을 만든다. 정수 PTS, 소수 반올림의 양·음 방향, 여러 사각형, 연속 컷, 1프레임 구간, VFR 입력, 표지/본문 전환을 실제 FFmpeg로 검증한다. 생성한 enable 문자열을 다시 계산하는 테스트만으로 끝내지 않는다.

완료 기준: 현 패딩의 70·388번을 포함해 마스크가 필요한 첫/마지막 프레임에서 글자가 드러나지 않고, 앞뒤 다른 컷에 마스크가 번지지 않는다. **수정 전 영상은 새 검수에서 실패해야 한다.** 동일 경로를 쓰는 표지·본문 및 실제 내보내기 결과의 동등성도 확인한다. 테스트 통과와 경계 픽셀 비교를 함께 제출한다.

### 단계 2 — 소스 파일 평가를 실제 사용 구간 평가로 확장

수정 범위: `source_presentation.py`, 소스 관찰/장면 데이터 계약, `source_overlay_review.py`, `scene_requirements.py`, 선택기에 전달되는 shot 필드.

1. 구간별로 제품 등장, 제품 종류·맥락 역할, 관찰 가능한 정보(정면 핏/옆모습/퀼팅/지퍼 등), 촬영 환경·동작 군집, 구도, 유효 해상도, 블러가 제품을 덮는 정도를 기록한다. 모델 판단에는 근거 프레임/구간과 불확실성을 붙인다.
2. 파일의 `core` 등급이 제품 없는 준비 구간으로 상속되지 않게 한다. `product_support`는 관련 제품이 실제 등장하는 이야기 지원과 일반 분위기·비교 화면을 구별하도록 계약을 정리한다. 맥락 화면은 허용하되 제품 다양성 확보로 계산하지 않는다.
3. 기존 소스 12개부터 재평가한다. 원본 전체를 고밀도로 재분석하기보다 후보 구간과 장면 전환을 우선 조사한다. 기존 승인 범위 밖의 유용한 구간은 새 근거를 확보한 후 사용할 수 있게 한다.
4. 서로 다른 업로드라도 같은 장면이면 같은 시각 군집으로 처리한다. 반대로 같은 원본의 다른 각도·기능은 새로운 정보로 인정한다. 수치만으로 강제 탈락시키지 않는다.

완료 기준: `42ac`의 패딩 없는 첫 구간이 제품 착장 근거로 자동 승인되지 않는다. 니트 외투는 일반 맥락으로 남고 패딩 디테일의 대체 근거가 되지 않는다. 미사용 소스별로 선택/탈락 이유가 남아 추가 수집 필요성을 설명할 수 있다.

### 단계 3 — 전체 흐름을 고칠 수 있는 편집 선택 구조

수정 범위: `scene_requirements.py`, 편집 계획 생성부, AutoCapCut `studio_diversity.py`, 필요 시 `studio_timeline.py`의 자막/시각 장면 연결.

1. 자막 cue와 영상 컷을 반드시 1:1로 묶지 않는다. 여러 cue를 하나의 자연스러운 장면으로 보여주거나, 제품 소개 흐름에 맞춰 컷을 배치한다. 승인된 음성·문장과 총시간은 보존한다.
2. 대사 수준의 필수 증거, 제품 식별, 마스크 승인, 사용자 잠금을 강한 제약으로 유지한다. 기존 컷 보존은 국소 수정의 기본값으로 두되, 반복·흐름 결함에서는 관련 비트 묶음의 재선택을 허용한다. 마스크만 고치는 작업에는 이를 적용하지 않는다.
3. 의미에 맞고 검토된 후보를 선택 전까지 여러 개 유지한다. 이 패딩처럼 전 비트 후보가 1개인 요청에는 ‘다양성 최적화 완료’라고 기록하지 말고 선택 자유도가 없음을 진단한다.
4. 새 제품 정보, 장면 전환의 자연스러움, 제품 가시성, 구도·선명도, 같은 동작 군집의 연속 노출을 함께 비교한다. 원본 점유율과 시간 재사용은 보조 지표다. 일정 원본 개수·컷 개수·최대 점유율을 모든 영상에 일괄 강제하지 않는다.
5. 전역 후보 계획을 고른 뒤 필수 근거 프레임이 실제 선택 구간 안에 들어오는지 검증하고 고정한다. 렌더 단계의 재선택으로 승인 계획이 바뀌지 않게 한다. 탐색 예산 소진과 실제 후보 부재도 구별한다.

완료 기준: 이 패딩의 3.0~8.867초를 같은 춤 영상으로 계속 채우는 선택과 제품 착장·디테일을 섞은 선택을 실제 비교한다. 선택기 로그가 새로 얻은 제품 정보와 포기한 후보를 설명해야 한다. 단순히 6번째 파일을 추가하는 것은 완료가 아니다.

### 단계 4 — 최종 구도와 블러의 시각 품질 개선

수정 범위: `source_presentation.py`, `source_mask_review.py`, 크롭/마스크 변환 계약 및 AutoCapCut 렌더 입력.

1. 출력 크롭 후 제품이 보이는 면적·위치, 잘리는 신체/제품 부분, 유효 해상도와 동작 흐림을 평가한다. 중앙 고정 크롭에서 벗어나려면 실제 구간의 제품 위치를 근거로 검토된 정적 크롭 또는 안정적인 추적 경로를 사용한다.
2. 마스크는 선택 구간의 실제 문자 지속 시간과 위치에 맞춘다. 불필요한 전체 구간 상자 누적을 줄이고 크롭 변환 후의 상자를 확인한다. 강도는 읽을 수 없을 만큼 유지하되 제품 가림을 줄일 수 있는 다른 프레임·원본을 우선 비교한다.
3. 크롭/마스크 변경은 근거 계약을 바꾸므로 해당 구간의 검수를 갱신한다. 제품 보존보다 화면 채우기를 우선하는 과도한 확대, 결함을 숨기는 장식 효과를 기본 해결책으로 삼지 않는다.

완료 기준: 초록 패딩 컷의 천장 위주 구도와 보라색 패딩의 큰 블러를 수정 전후로 비교한다. 개선 가능한 경우 제품 형태가 더 잘 보이고 문자는 다시 드러나지 않아야 한다. 원본 해상도 부족으로 개선할 수 없는 구간은 그 이유와 대체 여부를 기록한다.

### 단계 5 — 동일 패딩으로 다시 검증하고 결과를 제출

초기 재편집 방향은 다음과 같다. 시간은 지침이며 문장별 고정 배치가 아니다.

| 영상 구간 | 편집 목적 |
|---|---|
| 도입 약 0~3초 | 비교/상황을 짧게 설명하고 패딩 주인공을 빠르게 인지시키기 |
| 약 3~7초 | 패딩 전체 핏·색감·착장 보여주기. 같은 방 팔 동작만 이어붙이지 않기 |
| 약 7~12초 | 확보된 실제 옆모습·퀼팅·지퍼·착장 변화 등 새로운 정보 전달 |
| 약 12~16.5초 | 가장 좋은 패딩 착장 또는 제품 화면으로 마무리와 댓글 유도 연결 |

확보되지 않은 기능·성능이나 직접 시연을 꾸며내지 않는다. 모든 컷을 같은 SKU로 강제하지 않으며, 관련 제품의 이야기 지원을 허용하는 기존 합의를 유지한다. 다만 비교용 타 브랜드나 니트가 추천 제품의 대표 화면으로 읽히지 않도록 전체 맥락을 검토한다.

Sol 제출물은 별도 경로의 새 MP4와 편집 계획, 수정 전후 경계 비교, 실제 사용 구간 목록, 제품 표현·구도 비교, 테스트 결과다. 기존 완성본·작업 이력은 보존한다. 새 검수에는 기술적 정확성(마스크/타이밍/산출물 연결)과 편집 품질(제품의 매력/흐름/새 정보)을 나눠 기록한다. 과거 통과 상태나 `replay=0`만으로 후자를 대신하지 않는다.

최종 확인에서는 전체 재생과 청취도 수행하고, 하지 못한 항목은 명시한다. 기존 원작의 매력 기준 및 별도 샘플로 회귀를 확인하되, 이 패딩 한 편에만 맞춘 획일적 컷 수·원본 수 규칙을 도입하지 않는다.

## 6. 구현 순서와 범위

**단계 1 → 단계 2 → 단계 3 → 단계 4 → 단계 5** 순서다. 먼저 결함을 검출하는 실패 재현을 고정하고 시간축을 고친다. 그다음 구간의 의미를 정확히 전달하고 재편집 탐색을 열어 실제 구성을 개선한다. 화질/블러 작업은 그 선택된 구간을 대상으로 수행한다.

이전 일반 감사에서 Hotpost 관련 143개, AutoCapCut 관련 51개 기존 테스트가 통과했다. 이 결과는 해당 시점의 회귀 점검이며, **지금 확인한 패딩 결함이 없다는 증거는 아니다.** 이번 계획 작성에서는 제품 코드를 바꾸지 않았으므로 테스트를 중복 실행하지 않았다. 후속 구현에서는 새 실패 재현과 변경 범위의 회귀 검증이 필요하다.

검색어, DB 복구, 작업 정합성 문제는 이전 일반 감사의 별도 항목으로 남긴다. 그것들이 이번 패딩의 중국어 누출이나 빈약한 화면 구성의 직접 원인이라고 섞지 않는다. 이번 구현의 완료 판단은 **이 패딩에서 사용자가 실제로 본 결함이 사라지고 제품을 보여주는 영상으로 개선됐는가**다.
