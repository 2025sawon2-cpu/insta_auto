# 두 PC의 AI 에이전트 협업 규칙

2026-10-26 사용자 최신 지시 반영. VoiceBench와 insta_auto에 동일하게 적용한다.

## 규칙 원본

- 협업 정책은 이 문서에서 관리한다. AGENTS.md에는 문서 위치·재확인 시점·우선순위만 둔다. 두 저장소의 공통 정책은 같은 내용으로 유지한다.
- 작업 시작, 세션 재개·컨텍스트 압축 후, 수정 범위 확장, 사용자가 요청한 Git 변경 작업 직전에 실제 원문을 다시 읽는다. 기억이나 대화 요약으로 대신하지 않는다.
- 재개 메모에는 작업 브랜치·기준 커밋·문서 버전(commit 또는 SHA)·진행 단계·미해결 사항·필요한 내용 소실 동의를 남긴다. 비밀정보는 넣지 않는다. 문서를 읽을 수 없으면 변경·병합·push 전에 원문을 확보한다.
- 파일 분리만으로 누락이나 오판이 완전히 차단되지는 않으므로 실제 검사와 원격 반영 확인을 유지한다.

## 병행 개발

- 두 사람이 서로 다른 PC의 AI 에이전트를 사용하며 모두 저장소 전체를 수정할 수 있다. 같은 저장소·파일의 독립적인 작업도 병행한다. 고정 담당자나 파일 선점은 두지 않는다.
- **GitHub 이슈를 만들지 않으며, 이슈 생성·갱신·종료를 협업 절차로 사용하지 않는다. PR 생성과 별도 PR 리뷰도 필수 절차가 아니다.** 기존 이슈 이력은 삭제하지 않는다.
- 현재 작업 폴더의 로컬 기준과 기존 변경을 확인해 수정·검증한다. 작업 격리가 필요하면 독립 폴더를 사용하되 Git 브랜치 생성이나 병합을 자동으로 수행하지 않는다. 원래 작업 폴더의 미커밋 변경을 초기화·이동·혼입하지 않는다.
- 수정 파일은 작업 중 늘어날 수 있다. 관련 작업 브랜치와 변경을 확인하고 같은 함수의 동작·API·DB·설정 계약이 겹치면 양쪽 의도를 보존해 통합한다.
- 다른 PC의 미커밋 변경은 보이지 않는다는 점을 고려한다. 사용자가 Git 반영을 요청한 경우에만 해당 범위에서 기준 브랜치·통합 내용을 확인하고, 브랜치 이름과 커밋 메시지에 목적을 분명히 남긴다. 미완성 변경을 main에 반영하지 않는다.

## 의견을 구하는 경우

- **main 통합 과정에서 사용자 또는 상대 작업자가 만든 기존 코드·기능·문서의 실질적인 내용이 없어지거나 축소될 때만 협업 관련 의견을 구한다.** 적용 전에 없어질 대상·이유·영향·대안을 구체적으로 설명하고 명시적 동의를 받는다.
- 구현의 교체·줄 이동·동작을 유지하는 정리와 실제 내용 소실을 구분한다. 삭제 줄이 있다는 이유만으로 확인을 요구하지 않는다. 이미 같은 대상·범위로 승인받았다면 근거를 남기고 다시 묻지 않는다.
- 상대 코드를 통째로 버리거나 ours/theirs를 일괄 선택해 충돌을 처리하지 않는다. 사용자가 요청한 통합 범위에서는 내용을 보존하는 충돌 해결을 AI가 처리하고 같은 범위의 승인을 반복해서 묻지 않는다.

## 로컬 완료와 사용자의 Git 반영

1. AI는 요청된 파일을 로컬에 수정하고 필요한 검증을 마친 뒤 변경 내용·검사·남은 제한을 보고한다. 로컬 작업 완료에 커밋이나 원격 반영을 요구하지 않는다.
2. Git 반영은 사용자가 필요할 때 직접 한다. AI는 작업 완료를 이유로 staging·commit·브랜치 생성·merge·push·PR 생성이나 원격 동기화를 자동 수행하지 않는다. 상태·diff·이력 등 필요한 읽기 전용 Git 확인은 사용할 수 있다.
3. 사용자가 Git 작업을 AI에게 명시적으로 요청한 경우에만 그 대상과 범위 안에서 수행한다. Git 반영을 하지 않았다는 이유로 인증 설정·push 재시도·원격 반영을 필수 후속 작업으로 만들지 않는다.
4. 기존 커밋·미푸시 변경·다른 작업·개인 음성·세션·인증정보·모델·로컬 DB·생성 미디어·복구 백업을 보존한다. 명시적으로 요청된 Git 작업에서도 현재 범위 밖의 자료를 섞거나 강제 push·강제 덮어쓰기·검사 실패 무시를 하지 않는다.
5. 이슈는 만들거나 관리하지 않는다. 원격 결과 확인은 사용자가 요청한 Git 작업의 범위에 포함될 때 수행한다.

## 기존 작업과 운영 보호

로컬 코드 수정·Git 반영·운영 적용은 구분한다. 파일 수정이나 사용자가 요청한 Git 작업은 배포·서비스 재시작·제작·수집·예약·모델·휴대폰 제어·실제 게시 재개를 허용하지 않는다. 기존 사용자 중지, 개인 자료 보존, 서비스 간 API 경계, 프로젝트별 품질 규칙을 유지한다. 실제 운영 확인이 작업의 완료 조건이면 그 확인 전에는 전체 완료로 보고하지 않는다.

이 최신 지시는 이전 자동 커밋·자동 push 규칙과 과거 작업 기록의 미푸시 후속 의무를 대체한다. 과거 작업 이력과 기존 Git 상태는 당시 기록으로 보존한다.
