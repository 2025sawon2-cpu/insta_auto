## 중지·복구와 기존 이력

- 검토 입력은 같은 폴더의 불변 batch manifest로 저장한다. 상대 파일 경로를 유지하고 파일/manifest/검토 SHA·제품·원본·run을 결속한다. 모델 대기·중지 전까지의 검토를 다음 claim에서 재사용한다.
- 현재 claim 소유권을 모델 호출 전후와 상태 수용 시 확인한다. 음성이 검토 중 완성되어 요구 분량이 늘어나면 이미 받은 나머지를 먼저 검토한다. 검토 중 제품·원본이 바뀌면 수용을 보류한다.
- 최신 수동 소스 제외를 과거 검토로 덮어쓰지 않는다. 같은 소스를 재검토했을 때 최신 검토 메타데이터로 분량을 계산하되 현재 수동 제외는 우선한다.
- cover-only 조건이 맞지 않으면 정상 전체 렌더로 진행한다. 교체 결과는 입력/출력 SHA 영수증이 맞을 때만 재사용한다. 기존 영상은 덮어쓰지 않는다. 새 영상은 정상 최종 QA를 계속 거치며, 이번 격리 MP4를 운영 승인본으로 등록하지 않았다.

## 운영 적용과 보존 확인

14:32에 두 서비스를 적용한 뒤 공통 검색 계획의 마지막 보강분을 포함해 14:35 메인만 한 번 더 유휴 재시작했다. 최종 메인 **PID 12148 / 8775**, VoiceBench **PID 32340 / 8765**. 새 프로세스에서 메인 42개·VoiceBench 5개 모듈을 실제 import하고 디스크 SHA와 대조한 영수증을 저장했다. 별도 렌더러 진입점 SHA도 기록했다.

정확한 이전 PID·생성시각·부모·실행 파일·작업 폴더·포트 소유와 queued/running 0을 확인한 뒤 해당 서비스만 재시작했다. 기존 개인 참조 SHA `03ce9e220fa8d6fb26aecaf12fee5bf9beb1a165e8fcc4cefa3a2dd0cbdb2917`, ZONOS2 Q8 개인 기본 음성, 서버 고정 Seed 13 정책을 유지했다. 음성 새 생성 요청은 보내지 않았다.

본체 55개 작업 raw state·3개 기존 완성 MP4·설정 SHA가 기준선과 같고, 재시작 전후 본체 tasks/jobs/events/automatic_runs/outbox 및 VoiceBench 전체 데이터 테이블 hash도 동일하다. 수집 Chrome **PID 9600 / 7076**의 생성시각까지 동일하다. 과거 완료/중지 작업을 재개하지 않았고 기존 비교 서버·터널을 종료하지 않았다.

서버의 정적 HTTP 200과 VoiceBench ready=true/개인 기본/대기열0을 확인했다. 최초 전체 작업목록 HTTP probe는 55개 과거 작업 요약의 응답을 짧은 client timeout 안에 받지 못했다. 반복 probe를 중단하고 정적 HTTP+SQLite 전체 SHA로 수용 검사를 완료했다. 이 probe는 제작 상태를 변경하지 않았다. 작업목록 응답 성능 개선은 이번 수집 개선의 완료 근거와 구분한다.

최종 `deployment-final.json`, `main-final-loaded.json`, `voice-loaded.json`, `final-main-before.json`, `final-main-after.json` 및 첫 적용의 `deployment.json`, `predeploy-preservation.json`, `postdeploy-preservation.json` 참조. 변경 전 소스 472파일·기존 미커밋 diff·상태와 SQLite 사본을 보존했다. 커밋/푸시는 하지 않았다.

## 다음 신규 제작에서 확인할 항목

1. 최초 분량 충족 뒤 추가 외부 검색·다운로드 **0회**인지 확인한다.
2. 실제 검색어가 원본 제품 정체성을 유지하는지, 모델 검토·다운로드 실패/대체 미시도 원인을 기록한다.
3. 접수→실행→소스 확보→초안→품질 보완→최종 공유 시간을 같은 기준으로 측정한다. 병행 단계는 중복 합산하지 않는다.
4. claim 실행 시간에는 아직 내부의 요청 간격·모델 대기가 포함된다. 이번 event를 CPU 실행시간이나 모든 종류의 대기를 정밀 분해한 값으로 보고하지 않는다. 수신 상세 진단·기존 서비스 대기 기록과 함께 해석한다.
5. 동기 Playwright 호출의 실제 무진전 원인은 아직 미확정이다. 이번에는 원인 관측을 보강했으며 비동기 수신으로 전면 교체하거나 정상 대기를 짧게 끊지 않았다.

현재 완료된 상위3을 재제작하거나 하위 순위로 바꾸지 않는다. 다음 신규 선정 영상의 품질 통과와 실제 총시간이 확보되기 전에는 이번 코드만의 단축 분·비율을 확정하지 않는다.
