# 독립 편집의 스타일·전달

신규 제작과 명시된 독립 수정의 공통 후처리 경로다. 기존 제작실 실행기를 재개하지 않는다. Auto CapCut은 기존 버전 JSON·별도 프로세스로 원본 렌더를 만들며, Python 패키지를 직접 import하지 않는다.

## 현재 스타일을 계획에 적용

[대본·표지 원본](../hotpost/writing/RULES.md)의 신규 기본값을 적용할 때, 분석된 계획의 사본을 만든다. 폰트는 해당 PC의 공식 KCC간판체 파일을 명시한다. 이 명령은 다운로드나 폰트 대체를 하지 않는다.

```powershell
python -m hotpost.production_delivery style-plan --plan <분석계획.json> --font <KCC-Ganpan.ttf> --output <새계획.json>
```

이 새 계획을 독립 렌더 요청에 사용한다. 기존 계획의 자막 문구·시각·음성·소스·배치를 보존하며 표지 폰트와 표지/본문 그림자 흐림만 현재 기본값으로 지정한다. 이미 렌더된 표지의 폰트·레이아웃 검사 결과는 새 렌더가 다시 계산한다. 기존 영상 재개나 내용 수정만 요청된 경우에는 이 명령으로 스타일을 덮어쓰지 않는다.

기존 영상의 `caption-export`는 계획에 결속된 표지 경로를 재사용할 수 있다. 표지 스타일까지 바꿀 때에는 별도 `cover-preview`로 새 표지를 렌더하고 그 결과의 표지 경로·계획을 자막 수정 요청에 결속한다. 과거 `cover_path`를 새 표지로 간주하지 않는다.

## 광고와 전달 형식

독립 렌더·자막 수정·표지 미리보기의 결과는 원본 작업 파일이다. 공유할 후보는 항상 다음 공통 명령으로 새 폴더에 만든다. `--unmarked-inputs`는 입력 영상/표지가 아직 광고 후처리 전임을 실제 확인한 뒤 지정한다. 기존 전달본을 다시 입력하지 않는다.

```powershell
python -m hotpost.production_delivery finalize --raw-video <원본렌더.mp4> --raw-cover <원본표지.png> --font <한글광고표시폰트.ttf> --output <새전달폴더> --unmarked-inputs
```

본문 전체에 작은 옅은 회색 `[광고]`를 한 번 넣고, 광고가 포함된 현재 표지로 첫 프레임만 교체한다. H.264 Main@4.0/yuv420p·AAC-LC 복사·faststart·전체 디코드와 원본 대비 음성 패킷 내용/시각·영상 표시 시각을 검사한다. 기존 출력 폴더를 덮어쓰지 않으며 오류 결과는 전달 완료로 취급하지 않는다. 성공 시 `delivery-receipt.json`과 `video.mp4`, `cover.png`가 생긴다.

영수증의 `quality_complete=false`는 기술 처리 성공이 최종 QA 합격이 아니라는 뜻이다. 현재 MP4에서 광고의 가독성, 원본 자막 잔존, 표지 문구와 이미지 관계, 폰트 잘림을 직접 확인한다. 도입·사용된 각 구간·컷 경계·끝을 포함해 문제를 판단할 수 있는 위치를 확인하고 실제 시각을 기록한다. 표본 개수를 모든 영상의 합격 기준으로 고정하지 않는다. 청감과 문장별 자막 싱크는 별도 증거가 필요하다. [WORKFLOW](WORKFLOW.md)의 최종 QA 후 [저장 절차](LOCAL_VIDEO_STORAGE.md)를 따른다.
