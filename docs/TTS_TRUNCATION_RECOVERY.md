# 개인 릴스 TTS 기본·밝은 톤·문장 쉼·이상 복구

이 문서는 개인 릴스의 합성·음성 편집·검증 기준이다. 집필 원칙은 [대본 규칙](../hotpost/writing/RULES.md), 최종 영상의 완료 기준은 [WORKFLOW](WORKFLOW.md)를 따른다. 생성 설정, 원고의 대화 호흡, 편집에서 남기는 쉼을 구분한다.

## 앞으로 사용할 기본

2026-10-27 사용자 확정: “후자로 하자. 톤도 좋아졌어. 앞으로 이렇게 만들도록”. 같은 밝은 톤 원음의 비교에서 **문장 뒤 쉼을 복원한 B**를 선택했다. 이는 현재 비교 음성의 톤·쉼 선호이며 미래 모든 음성이나 새 영상의 발음·자막 싱크를 자동 승인한 것은 아니다.

- **목소리·원고:** 승인한 개인 참조, 해당 PC의 개인 엔진, Seed13·HQ를 유지한다. 선택 원고 전체를 한 번에 합성하고 실제 구간 수를 확인한다. 문장을 따로 합성해 덧붙이거나 다른 화자로 대체하지 않는다.
- **밝은 릴스 톤:** 개인 ZONOS2 Q8에는 VoiceBench 서버가 정의한 `reels_bright_v1`을 명시한다. 실제 조건은 `emotion_enabled=true`, `happy=0.35`, `emotion_strength=1`, `emotion_cfg_scale=1`, `speaking_rate_enabled=false`다. 이 값은 서버 소유 프리셋이며 클라이언트가 엔진·참조·Seed·임의 고급 수치를 덮어쓰는 계약이 아니다. 다른 PC의 엔진을 임의 교체하거나 공식 화자·일반 비교 기본값에 강제하지 않는다.
- **실제 적용:** `/v1/styles`의 버전·조건·방향자료 SHA와 요청 스냅샷·실제 worker 결과를 대조한다. 완료 응답의 `style_verified=true`와 `style_actual` 일치를 확인한다. 지원 부재, 자료 누락, 적용 불일치 때 중립 음성으로 조용히 대체하지 않는다. 스타일은 캐시 fingerprint와 영속 요청 ID에도 결속해 옛 차분한 WAV를 새 밝은 합성으로 재사용하지 않는다.
- **문장 뒤 쉼:** 새 독립 편집 기본 `sentence_preserved_v1`은 B처럼 문장 종결부의 원래 조용한 구간을 보존한다. 정책 버전은 `quiet-boundary-sentence-preserved-20261027-v1`이다. 질문·느낌표 종결도 같은 원칙이다. 문장 안의 쉼 정리는 기존 조건 안에서 유지하되 음절·약한 말끝·호흡을 보존하는지 따로 확인한다. 모든 쉼을 제거하거나 문장 끝을 수십 ms로 압축하지 않는다. 비교에 나온 특정 초 수를 모든 음성의 고정 쉼으로 복사하거나 인위적인 무음을 일괄 삽입하지 않는다.
- **원음 보존:** 원음은 변경하지 않고 편집음을 별도 파일로 만든다. 버전·원본/출력 SHA·샘플 단위 cut/keep 시간표를 남긴다. 단순히 소리가 작다는 이유로 발화가 없다고 판단하지 않는다. ASR 경계가 불확실한 구간은 문장 끝 보호를 풀 근거가 아니다. 속도·피치·음량·EQ 변경을 밝은 톤이나 말끝 복구의 대체 수단으로 쓰지 않는다.
- **경계 분류의 한계:** 현재 편집기는 ASR의 문장부호로 종결부를 분류한다. 정상 호출에서 선택 원고도 전달해 종결부 개수의 누락·불일치를 확인하고, 불확실하면 조용한 구간을 보수적으로 보존해 사유를 남긴다. 개수가 같다는 것만으로 위치·발음까지 맞는 것은 아니므로 원고·실제 말끝을 함께 검토한다. 원고 없는 호환 호출을 원고 경계 검증 완료로 보고하지 않는다.
- **기존 자료:** 과거 `tight` 명시 계획과 완료본은 보존한다. 새 기본값은 다음 정상 편집 호출에 연결하고, 기존 영상은 명시된 수정 범위에서만 새 버전으로 만든다. 비교 B를 골랐다는 기록만으로 기존 MP4·자막·최종 QA가 이미 바뀌었다고 보고하지 않는다.

거울·키티 때의 개선 기록은 주로 원고 호흡을 바꾼 결과였다. 그 원고 선호가 등록돼 있다는 것과 재사용 가능한 엔진 톤 기능이 구현됐다는 것은 별개다. 앞으로도 문서 수정, 호출 코드, 실행 중 서비스의 로드, 실제 새 음성 생성, 사용자 청감 확인을 각각 근거로 구분한다.

## 문제 발생 단계를 먼저 구분

원음 → 쉼 정리 음성 → 효과음 믹스 → 최종 MP4를 같은 파일·시간표로 대조한다.

| 관찰 | 먼저 할 대응 |
|---|---|
| 원음은 자연스럽고 편집 뒤 문장 끝이 급해짐 | 같은 원음을 유지하고 해당 쉼 처리만 비교·교정한다. TTS를 다시 뽑거나 원고부터 바꾸지 않는다. |
| 원음 자체의 톤 불만 | 실제 서버 프리셋·자료 로드·worker 적용·캐시 재사용을 확인한다. 설정 일치나 과거 원고 승인만으로 현재 톤이 같다고 주장하지 않는다. |
| 원음에서 누락·발음 이상이 사용자/실제 청취로 확인됨 | 아래 표현 교정·전체 재합성 절차를 적용한다. |
| ASR만 원고와 다름 | 확인할 후보로 기록한다. ASR 오인식과 실제 발화 결함을 구분하며 무조건 재합성하지 않는다. |
| 최종 파일에서만 문제 | 편집음·믹스·AAC의 길이·지연·파형과 재생을 확인하고 손상이 생긴 단계만 수정한다. |

비교는 같은 발화에서 한 가지 조건만 바꾼다. 밝은 톤과 쉼을 동시에 바꾸거나 동일 조건 재합성을 반복해 원인을 흐리지 않는다. 청감 비교용 페이지는 기존 방식으로 외부 접근·재생·다운로드가 검증된 Cloudflare HTTPS로 제공한다.

## 검증과 승인 범위

- ASR 일치·WAV 유효성·SHA·파형 상관·자연 종료는 각각 발화/파일/전송 검사다. 밝음·자연스러움·말끝 보존의 실제 청감 승인을 대신하지 않는다. 에이전트가 직접 듣지 못하면 그 한계를 기록한다.
- 사용자의 톤·쉼 피드백은 실제 비교한 파일과 범위에 연결한다. 선호는 다음 제작의 기준으로 사용하되 새 음성의 모든 발음이나 새 MP4의 음성·자막 싱크까지 확대하지 않는다.
- 음성이나 쉼이 바뀌면 현재 cut-map으로 자막·컷 시각을 다시 결속하고 최종 MP4를 확인한다. 이전 시간축·QA 판정을 그대로 복사하지 않는다. 삭제 구간에서 여러 원시각이 같은 출력시각으로 매핑되면 임의 역산값을 실제 ASR 시각이라고 기록하지 않는다.
- 문제는 한 단계씩 검증해 고친다. 효과 없는 동일 재요청을 반복하거나 Seed·화자 교체·검사 완화로 통과시키지 않는다.

## 원음 잘림·확인된 발음 이상의 표현 교정

2026-10-23 사용자 확정: “앞으로는 tts가 잘려오면 대본을 일부 변경해서 테스트하는걸로해.”

2026-10-26 사용자 확정: 사용자가 확인한 발음 이상에도 의미를 유지하는 최소 표현·호흡 교정 후 전체 재합성 원칙을 적용한다. ASR(음성인식) 불일치만 있는 의심과 실제 확인된 이상은 구분한다.

## 이상 판단과 수정 대상

- 사용자가 현재 음성의 특정 표현·시간을 이상하다고 확인했거나 실제 청취로 확인한 발음·발화 문제는 수정 대상으로 기록한다. 파일·버전·구간·기대 문구·실제 관찰과 확인 주체를 남기고, 사용자가 위치나 판단을 정정하면 최신 설명을 반영한다. 확인된 문제를 단순히 “나중에 확인할 항목”으로 남겨 합격본을 전달하지 않는다.
- ASR 오인식·전사 간 불일치만 있으면 의심으로 기록한다. 원음 청취 또는 별도 전사 등으로 누락·발화 여부를 확인하되, 전사 일치만으로 발음·음색·자연스러움까지 정상이라고 단정하지 않는다. 같은 계열 ASR 여러 결과를 독립 청감 평가로 표현하지 않는다. ASR 의심만으로 선택 대본을 자동 교정하거나 무조건 재합성하지 않는다.
- 직접 들을 수 없으면 그 한계를 기록하고 청감 확인을 했다고 쓰지 않는다. 사용자 청감 피드백은 실제 확인한 범위와 현재 파일에 결속한다. 재합성 후 전사가 맞아도 청감 미확인과 확정 결함 해소를 구분하며, 최종 판정은 [WORKFLOW의 QA 기준](WORKFLOW.md)을 따른다.

## 기본 대응

1. 실제 합성 입력과 생성 음성·품질 기록을 확인해 문장이나 끝부분 누락, 확인된 발음 이상을 구분한다. 전송 실패·로그인·서비스 대기를 대본 잘림으로 취급하지 않는다. 음성인식만 의심스러우면 위 판단 기준으로 먼저 확인한다.
2. 누락이나 발음 이상이 확인되면 문제 구간의 문장 표현·연결어·문장부호·호흡을 필요한 만큼만 바꾼 교정안으로 테스트한다. 제품 사실·핵심 매력·선택한 후킹 의도와 마지막 댓글 문구를 유지한다. 누락·문제 문장을 삭제하거나 내용을 축소해 검사에 맞추지 않는다. 이 단계는 기존 선택안의 표현 교정이며 신규 3안 집필·재선정으로 확대하지 않는다.
3. 같은 개인 복제 목소리·참조·엔진·Seed·품질·생성 설정을 유지하고 수정 대본 전체를 한 번에 새로 합성한다. 두 부분으로 나눠 합성하거나 끝문장만 붙이지 않는다. Seed 변경·다른 목소리 대체·EOS 강제 무시·품질 검사 완화로 해결하지 않는다.
4. 기존 대본·실패 음성·오류 기록을 보존하고 수정 대본을 새 버전으로 남긴다. 제출한 전체 원문/해시·요청 ID·실제 참조/Seed/설정·합성 구간 수와 결과를 연결한다. 실패 요청의 캐시 응답을 새 합성으로 세지 않는다.
5. 새 WAV 전체의 유효성과 전체 대본·마지막 문장의 발화를 확인한다. 원래 문제 문구와 앞뒤 연결을 새 음성의 시간축에서 다시 확인하고, 필요하면 별도 전사로 발화 여부를 재확인한다. 발화 누락 해결과 발음·음색·자연스러움에 대한 청감 평가를 구분하며, 최종 MP4에도 같은 수정 음성이 적용됐는지 확인한다.
6. 통과하면 현재 영상의 정상 경로에서 수정 대본과 그 음성을 같은 버전으로 결속하고 필요한 후속 제작을 이어간다. 이전 대본의 자막·음성 시간축·최종 QA를 새 결과에 그대로 승인하지 않는다. 유효한 기존 소스와 영향 없는 산출물은 재사용한다.

## 재작업 범위와 책임

동일 대본·동일 조건 재요청을 기본 복구 방법으로 반복하지 않는다. 별도 사용자 지시로 재현 시험이 필요하면 그 목적과 횟수를 실제 기록에 남긴다. 표현 변경에도 실패하면 실제 새 근거와 원인을 확인하며, 효과 없는 같은 변형이나 무한 재합성을 피한다. 기술적 보류가 필요해도 해결 책임과 같은 영상으로 돌아올 경로를 유지한다. 기존 사용자 중지·접근 제한·다른 영상의 중지는 자동으로 해제하지 않는다.

영상마다 별도 제작 담당 에이전트가 소스·대본·TTS·편집·현재 결과의 최종 QA와 완료 확인을 책임진다. TTS 잘림·확인된 발음 이상의 표현 교정·재합성·검증과 후속 제작도 그 담당자가 이어간다. 메인 에이전트는 후보 선정·작업 등록·조율·결과 확인을 맡으며, 담당자를 등록만 해 두고 실제 제작을 전부 대신 수행한 것을 별도 담당 제작으로 보고하지 않는다. 기존 영속 담당자가 있으면 그 담당자와 task/run을 보존하고 이중 제작을 시작하지 않는다.

VoiceBench API가 사용자가 보낸 원고를 몰래 재작성하거나 임의로 분할·Seed 변경하도록 승인한 규칙이 아니다. 문서 반영을 자동 실행기 구현·운영 적용 완료로 보고하지 않는다.

## 이번 확인 근거

귤 키링의 기존 156자 대본은 같은 개인 참조·Seed 13에서 마지막 댓글 문장 누락이 재현됐다. 중간 표현을 일부 다듬은 162자 대본은 같은 조건의 단일 구간·단일 시도로 19.33초 합성됐고, 전체 및 마지막 문장 검사를 통과했다. 이 결과는 표현 교정 후 누락 해결의 실제 사례이며 특정 단어 하나가 원인이었거나 모든 TTS 실패가 대본 수정으로 해결됨을 뜻하지 않는다.
