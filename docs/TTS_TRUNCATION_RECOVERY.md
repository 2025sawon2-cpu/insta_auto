# Google AI Studio TTS · Arlo · 쉼과 들숨 편집

## 확정 기본

2026-10-29 사용자가 Arlo의 최종 편집본을 “아주좋아”로 확인하고 이 규칙과 Google AI Studio를 최종 확정했다. 신규 음성은 기존 로그인된 Chrome 사원2 프로필의 Google AI Studio, `gemini-3.8-flash-tts`, **Arlo**를 사용한다. 사용자가 말한 ‘2’와 서비스별 프로필 선택은 [WORKFLOW의 브라우저 프로필](WORKFLOW.md#브라우저-프로필)이 원본이다. 낭독 지시는 `hotpost/ai_studio_adapter.py`의 `STYLE`이 단일 원본이다. 자연스럽고 차분한 서울말 대화체이며 과장된 광고 진행·들뜬 억양을 피한다.

- 선택 대본 201~250자 전체를 구두점·공백까지 유지해 한 번에 제출한다. 숫자 발음 변환 후 길이를 이유로 자르거나 문장별로 합성하지 않는다.
- Google 경로에는 개인 복제 참조, Seed13, 로컬 GPU 엔진, `reels_bright_v1`, HQ 판정이 없다. 이를 충족한 것으로 표시하지 않는다. `seed_supported=false`, `segment_count=1`을 기록한다.
- 기존 결과·요청·모델·완료 영상은 보존한다. 이전 provider의 진행 ID를 Google 요청으로 바꾸거나 자동 재제출하지 않는다. 현재 제작·수집·게시 중지는 그대로 유지한다.

## 생성 경로

신규 합성·중단 재개·원음 재생성·발음/잘림 교정으로 원고를 바꾸는 경우 모두 [대본 규칙](../hotpost/writing/RULES.md)을 적용한다. 교정 전후 전체 문구를 대조해 금지 표현·억지 감정 종결·의미·말투를 검토하고 수정 부분만 봤다는 이유로 나머지를 통과시키지 않는다. ‘괜히 반가워요’는 TTS 요청 준비에서도 차단한다. 발음 교정이나 전체 단일 합성이라는 이유로 대본 금지를 예외로 삼지 않는다. 음색·쉼·들숨만 바꿀 때는 선택 원고를 임의 재작성하지 않는다.

2026-11-02 정정: 에이전트가 [개발자 포럼의 개별 답변](https://discuss.ai.google.dev/t/gemini-3-1-flash-tts-preview-assisted-run-returns-http-403/183088)을 이 작업의 확정 금지 규칙처럼 적용해 Playwright 실행을 멈추고 사용자 수동 Run을 요구한 판단은 잘못됐다. 그 답변만으로 이 계정의 403 원인이나 현재 실행 금지를 확정하지 않는다. 기존 로그인된 Chrome 사원2와 아래 Playwright 경로로 직접 진행하되, 실제 접근 제한이 관측되면 원본 캡처·보고와 5분 후 제한된 재시도 규칙을 지킨다. 인증·차단 우회는 하지 않는다.

1. 기존 작업 폴더에서 `python -m hotpost.ai_studio_adapter --script <선택 원고> --output <새 원음.wav>`를 실행한다. 출력 옆 `.ai-studio/`의 `prepared.json`에 전체 원고·모델·Arlo·STYLE·요청 ID와 해시가 결속된다. 같은 경로를 재호출하면 같은 요청을 사용한다.
2. 제작 에이전트가 `cua_repl`로 기존 Chrome 사원2의 AI Studio 탭을 확보한다. **페이지 조작은 무조건 Playwright 기반 `tab.playwright`를 사용하는 `tools/ai_studio_browser.mjs` 경로로 한다.** `inspectSpeech`로 로그인·모델·목소리·지시를 확인하고, 단일 블록에 전체 원고를 넣어 `submitSpeech`를 한 번 호출한다. Playwright가 동작하지 않으면 AX 인덱스·좌표 클릭·다른 프로필/브라우저로 우회하지 말고 현재 오류를 보고한다. 전용 생성 탭임을 확인한 경우에만 `replaceExistingText:true`를 쓴다. 두 호출에 현재 작업 폴더 안의 절대 `evidenceDir`을 넘겨 오류 원본을 모은다. 생략 시 helper는 Git 제외 `data/ai-studio-errors/`에 요청별로 보관한다.
3. 제출 뒤 같은 handle로 `pollSpeech`를 바로 확인한다. 오류 관측 전에 별도 페이지 snapshot을 연속 조회하지 않는다. helper는 403·CAPTCHA 의심 등 화면의 오류·인증 의심 문구를 읽으면 **다음 브라우저 조회·클릭 전에 반드시** 현재 화면 원본 JPG를 캡처하고 당시 문구·요청·원고 SHA·관측/캡처 시각·이미지 SHA를 JSON과 함께 저장한다. `error_evidence`가 반환되거나 예외에 붙으면 에이전트는 그 파일을 실제 확인해 사용자에게 스크린샷과 저장 경로·중단 단계·확인/미확인 사항을 즉시 보고하고, 재조회·닫기·재제출은 뒤로 미룬다. 캡처 실패는 `capture_error`로 구분해 그 사실을 보고하며 이미지가 있다고 주장하지 않는다. 이미지에서 오류가 사라졌으면 당시 문구 기록과 픽셀의 증거 범위를 구분한다. 증거 보존 뒤 현재 사용 가능한 LazyCodex의 관련 스킬을 확인해 진단·정상 복구에 참고하고 실제 결과를 기록한다. 스킬이 없거나 해결 근거가 없으면 그대로 보고한다. 저장·캡처·스킬 확인은 오류 해결이나 CAPTCHA 확정·자동 해결·재제출 허가가 아니다. 생성 중 음원을 끊거나 스트리밍 조각을 완성 WAV로 저장하지 않는다. `ready`일 때 `downloadSpeech`로 해당 `.ai-studio/google-download.wav`를 저장하고 반환 `receipt`를 `.ai-studio/browser-receipt.json`에 쓴다. 다운로드는 화면 렌더 WAV를 64KB씩 읽어 전체 SHA를 대조한다. 쿠키·API 키·비공개 API에 접근하지 않는다.
   - 공개 플레이어의 전체 길이·활성 Download는 있지만 DOM audio가 짧은 placeholder로 남고 Run이 비활성인 UI에서는 같은 요청의 공개 Download를 한 번 클릭해 수신 파일을 확인할 수 있다. `registerPublicDownload`에 실제 클릭 관측 시간 범위·수신 경로·전체 SHA를 넘긴다. 현재 원고/계정/모델/Arlo/STYLE, 생성 중 Stop 없음, 활성 Download, 클릭 이후 파일 시각, 완전한 mono PCM16 24kHz WAV와 플레이어의 정확한 전체 길이가 모두 일치해야 `ready`가 된다. 이후 같은 `downloadSpeech`로 저장하며 영수증에 공개 다운로드 근거를 남긴다. 다른 요청·과거 파일·부분 음원·길이 불일치는 거절하고 자동 재제출하지 않는다. 기존 DOM WAV 경로는 그대로 유지한다.
4. 같은 Python 명령을 다시 호출해 요청/원고/화자/STYLE/음원 해시와 완전한 mono PCM16을 확인하고 원음을 저장한다. `result.json`은 음성 단계 산출물이다. `browser_pending`은 에이전트의 다음 동작이며 사용자 승인 요청이 아니다. 브라우저 도구가 없는 Python 단독 실행은 합성 완료를 가장하거나 새 브라우저 서버를 만들지 않는다.
5. 로그인·권한·할당량 오류나 제출 후 불확실 상태는 같은 탭·요청을 확인한다. 실제 종료된 무음 실패는 기록 후 `finishNoAudio`로 종료한다. **HTTP 403에 한해** 위 오류 원본 캡처·기록·사용자 보고를 마친 뒤 관측 시각부터 5분을 기다리고, 기존 사원2 탭의 로그인·모델·Arlo·전체 원고와 이전 요청의 종료 상태를 확인해 같은 영상에서 **한 번만** Playwright 경로로 새 요청을 재시도한다. 재시도 요청 ID·시각·이전 403 증거를 연결한다. 다시 403이면 새 화면도 먼저 캡처·보고하고 그 음성 단계를 보류한다. 성공 여부는 완전한 WAV와 영수증으로 판단하며 5분 경과 자체를 접근 회복 근거로 쓰지 않는다. 403 이외의 CAPTCHA·명시적 권한 차단·할당량 제한이나 종료 여부가 불명확한 요청에는 이 재시도 규칙을 적용하지 않는다. 다른 모델·목소리로 자동 대체하지 않는다.

## 확정 음원 재사용과 영상 적용

- 사용자가 특정 음원을 확정하고 영상 적용을 요청하면 그 파일을 재사용한다. 같은 목소리의 새 합성으로 대체하지 않는다. 선택 대본 전체와 기존 Google `prepared.json`·브라우저 영수증의 요청 ID, 모델·Arlo·STYLE·원음 SHA를 대조하고 기존 adapter로 같은 요청의 원음을 검증·수입한다. 재수입을 신규 합성으로 기록하지 않으며 원래 요청 ID와 영수증을 보존한다. 원고가 달라졌거나 실제 원음 결함이 확인되면 아래 복구 기준을 따른다.
- 이미 쉼·들숨 편집을 마친 확정 WAV에는 편집을 다시 적용하지 않는다. 원음과 편집음을 구분해 보존하고, 원음 SHA·sample cut/keep 맵·편집음 SHA와 PCM 일치를 확인해 현재 계획에 연결한다. 원음에 대한 실제 ASR과 종결부 검토를 재사용해 새 시각으로 변환하며, 인식 오류를 원고로 덮어 쓴 전사나 문자 수 비례 시각으로 대신하지 않는다.
- 음성 교체 시 대본·소스·표지와 자막 스타일은 요청 범위에서 보존하되 자막·장면·MP4·편집 초안은 새 음성의 시간축에 맞춘다. 기존 의미 단위도 새 표시 시각에 결속해 검토한다. 길이 조정으로 원본 사용 구간이 늘면 [편집 기준](editorial_montage_policy.md)에 따라 추가 구간과 새 컷 경계를 현재 렌더에서 확인한다. 감속·정지 화면으로 길이를 자동 충당하지 않는다.

## 최종 음성 편집 규칙

Auto CapCut의 새 독립 편집 기본은 `short_pauses_breath_v1` / `short-pauses-spectral-breath-20261029-v1`이다. 기존 `prepare_narration` 호출을 사용한다. 새 서버·대기열·별도 편집기를 만들지 않는다.

- 원음은 불변이며 별도 편집 WAV와 샘플 단위 cut/keep 맵을 만든다. 속도·피치·음량·EQ는 변경하지 않는다.
- 10ms RMS에서 -38dB 미만의 0.20초 이상 구간을 살핀다. 기존 문장 안 쉼 정리 조건을 유지하고, 문장·질문 끝의 긴 쉼도 약 0.12초를 남기는 단계로 줄인다. 이후 들숨 정리로 실제 남는 쉼은 더 짧아질 수 있다. 특정 예시의 초 수를 전체 영상 길이 목표로 강제하지 않는다.
- ASR 단어 시각과 원고를 함께 확인한다. 인식된 종결부 근처에서 다음 단어 시각이 쉼을 덮는 경우에도 실제 종결부를 보호한다. 문장부호가 없으면 역할 불확실성을 기록하고 더 긴 문장용 쉼을 적용한다. 시각을 지어내거나 인식 전사를 원고대로 바꿔 쓴 것을 실제 ASR로 보고하지 않는다.
- 기존 `audio_edit.strip_breaths`를 재사용한다. 이 녹음의 상위 95% 발화 레벨보다 20dB 낮고, 주기성 0.40 미만이며, 3.5~7.5kHz 에너지 비율 0.30 미만인 조건을 함께 본다. 내부 후보는 0.18초 이상, 발화 가장자리는 0.04초 여유와 연속 발화 프레임 조건을 사용한다. 숨과 무음을 같은 것으로 단정하지 않으며 ㅅ/ㅆ/ㅊ·짧은 폐쇄음·약한 말끝을 보호한다.
- 현재 파일에서 잔여 들숨 후보와 0.3초 이상 무음을 실제 측정한다. 후보를 모두 호흡이라고 단정하거나 검사 하나로 청감 합격을 주장하지 않는다. 확인된 긴 쉼·들숨 문제는 해당 cut-map을 수정하고 같은 입력으로 다시 확인한다.
- 출력 PCM이 keep 구간의 원음과 정확히 일치하는지, 원음 SHA·전체 프레임·대본의 시작/끝/주요 문구·마지막 CTA를 확인한다. 원본 ASR 단어를 cut-map으로 변환해 자막·장면·MP4·초안에 같은 시간축을 사용한다. 예전 자막 시각을 새 편집음에 복사하지 않는다.
- 명시된 과거 `tight`, `natural`, `compact`, `sentence_preserved_v1` 계획과 완료본은 그대로 보존한다. 신규 기본값 변경은 완료본 재검사·재렌더 지시가 아니다.

## 문제 수정과 완료

원음 → 편집음 → 믹스 → 최종 영상 순으로 손상 단계를 구분한다. 원음이 정상이고 편집 뒤 문제면 같은 원음에서 편집만 고친다. ASR 불일치만으로 발음 결함이나 누락을 확정하지 않는다. 사용자나 실제 청취로 원음의 발음/누락이 확인되면 의미를 유지하는 최소 표현·호흡 교정 후 같은 Arlo·모델·낭독 지시로 전체를 새 버전에서 한 번에 합성한다. 대본/실패 음성/요청을 보존하고 끝문장만 덧붙이거나 다른 목소리로 통과시키지 않는다.

최종 MP4의 실제 음성은 현재 편집음·믹스와 시작·중간·끝/CTA에서 대조한다. 필요하면 최종 오디오를 디코드해 파형·구간 상관과 시간 이동을 확인하며, 전달 후처리의 패킷 보존 검사는 해당 원렌더와의 동일성 근거로 사용한다. 요청 설정·파일명·스트림 시작 시각만으로 선택 음원이 적용됐다고 판단하지 않는다. 특정 실험의 상관계수나 표본 수를 모든 영상의 합격 기준으로 고정하지 않는다.

제작자는 발화·적용·쉼·자막 시각과 최종 파일을 확인한 뒤 저장·전달·완료 보고까지 진행한다. 별도 사용자 음성 승인 단계를 만들지 않는다. 직접 청취하지 못한 범위는 기록하며 ASR·파형·설정 일치를 지각적 자연스러움의 승인으로 표현하지 않는다. 실제 영상 QA는 [WORKFLOW](WORKFLOW.md), 전달은 검증된 Cloudflare HTTPS를 따른다.
