# 짧은 소스 구간 복구 구현·선반 신규 영상 독립 검토

## 검토 범위와 결론

주 담당과 별도인 에이전트가 `SOURCE_INTERVAL_IMPROVEMENT_20261017.md`, 앞선 실제 레퍼런스 5개 엄격도 감사, 새 `source_interval_recovery.py`, 연결된 `studio_sources.py`·`source_batches.py`·`shot_presentation.py` 및 관련 회귀 사례를 읽었다. 운영 코드·DB·큐·브라우저·서버를 변경하거나 새 모델 작업을 만들지 않았다. 이 문서 한 파일만 작성했다.

새 선반 `work-98ce7e341904464f` / `run-244b49520a454a18`의 실제 완성본은 정상 최종 QA를 통과했고, 독립 픽셀 표본에서도 전체 제품 전달을 무효화하는 확정 결함을 발견하지 않았다. 이것은 신규 검색·다운로드 시간 단축 실증이나 목소리 청감 승인을 뜻하지 않는다.

| 항목 | 독립 확인 |

검토 중 두 보완점을 주 담당에게 즉시 전달했고 현재 파일에서 수정을 확인했다.

1. **음성 완료 후 불필요한 후속 검토 가능성:** 최초 코드는 복구 모델 검토가 끝난 뒤에 충분 여부를 확인했다. 새 음성이 도중 완료되어 기존 분량만으로 충분해져도 다음 span의 모델 검토를 시작할 여지가 있었다. 현재 `recover()`는 제안 전과 각 span 시작에 최신 `sufficient`를 검사한다. 음성이 제안 도중 준비되는 반례 회귀도 추가된 것을 확인했다. 이미 시작한 호출을 임의 취소하는 제안은 하지 않았다.
2. **다른 파일의 유효 overview 캐시 혼입:** `_check_evidence` 자체는 영수증 내부 source·프레임 SHA를 확인하지만 현재 복구 대상과의 동일성은 확인하지 않는다. 초기 cache 읽기에는 이 외부 비교가 빠져 있어, 다른 유효 영상의 overview가 들어오면 잘못된 그림으로 제안 호출을 시작할 수 있었다. 현재 source SHA와 실제 경로 비교가 추가됐다. 후속 정식 검토의 승인 우회가 실제 발생했다고 주장하지 않으며, 모델 호출 전 잘못된 캐시를 거부하기 위한 결속 보완이다.

이 문서는 전체 회귀 실행 결과를 대신하지 않는다. 실제 실행한 검사 수·최종 운영 로딩 SHA·보존 감사는 주 담당의 완료 보고서와 배포 영수증을 따른다.

이번 새 음성246은 원음 18.7617초이며 편집 계획은 무음 정리 후 약18.0951초다. 서로 다른 길이를 혼용하지 않는다. 이 영상은 기존 승인24초가 새 음성 요구량을 충족하는 재사용 경로다. 새 검색·다운로드 없이 완성됐다는 사실을 새 구간 복구가 네트워크 수집 시간을 몇 분 절감했다는 실측으로 바꾸지 않는다.

새 복구가 실제로 시작된 것, 이후 음성 준비로 추가 작업이 필요 없어지는 경쟁 조건, 다음 호출 전 충분 판정 보완은 분리해서 보고해야 한다. 이 실제 완성본만으로 모든 실패 소스를 복구하거나 가림 면적을 항상 줄일 수 있다고 결론 내릴 수 없다.

청감 검수는 수행하지 않았다. 원작/완성본 전수 프레임 판독, 제품 재사용 권리 확정, 외부 비교 페이지 재생·다운로드 검증도 이 독립 보고서 범위 밖이다.
