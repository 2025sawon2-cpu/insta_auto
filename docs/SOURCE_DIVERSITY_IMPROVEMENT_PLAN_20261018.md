## 1. 사용자 요청과 목표

사용자는 세 완성 영상의 사용 원본이 텐트3개·가방2개·손난로1개에 그친 이유를 물었고, 원인 설명 후 개선 계획을 새 세션용 MD로 요청했다.

목표는 **적합한 동일 제품/관련 장면을 더 확보할 가치가 있는지 판단하고, 이미 확보한 적합한 원본을 편집에서 더 잘 활용하는 것**이다. 제품 매력과 자연스러운 흐름, 제작 지속성을 함께 유지한다. 원본 개수를 늘리는 것만으로 성공을 선언하지 않는다.

구현 전 현재 runtime의 v4에는 서로 다른 원본3개·5개를 강제하는 조건이 없고 이 세 작업은 소스1개+검토된 핵심 구간으로 준비될 수 있었다. 이것은 아래 새 요구의 구현 대상이며 유지할 목표가 아니다. 과거 v3/v4 run과 기존 완료본은 이력으로 보존하고 명시 신규 수집·재제작에는 새 기준을 버전으로 채택한다. 새 버전명은 구현 시 정하고 기존 v4 의미를 몰래 바꾸지 않는다.

### 최신 최소 기준의 수용 조건

1. 영상 주제·제품 근거에 맞는 **서로 다른 영어 검색어5개 이상**으로 실제 검색한다.
2. 같은 기준의 **서로 다른 중국어 검색어5개 이상**으로 실제 검색한다. 총10개 이상이며 영어10개로 중국어5개를 대신할 수 없다.
3. **관련 소스 영상 합계5개 이상**을 실제 확보하고 내용·편집 가능 여부를 검토한다. 언어별 소스5개씩을 요구하는 것은 아니다. 원문 제품과 관련된 핵심 제품 장면 및 허용된 사용/반응 맥락을 구분해 기록하며 최소1개 실제 핵심 제품 구간은 유지한다.
4. 쿼리 생성/미제출/로그인벽·CAPTCHA 미시도는 실제 검색 완료에 넣지 않는다. 서로 다른 유효 검색어의 실제 제출·일치한 결과 관측을 남기며 결과0건도 실제 검색으로 구분해 기록한다. 같은 검색어의 재시도·플랫폼 반복·공백 변경은 별도 검색어가 아니다.
5. 단순 후보 링크·무관 제품·미검토/불합격 파일·같은 부모의 잘린 파일·확인된 중복은 소스5개에 산입하지 않는다. 보관본을 소스 수에 넣으면 실제 파일/SHA·현재 관련성 검토·보관 재사용 출처를 남기고, 영어/중국어 실제 검색은 생략하지 않는다.
6. 세 조건이 충족되기 전에 분량/핵심 구간만으로 수집 완료·최소 기준 충족을 표시하지 않는다. 자원이 부족하거나 접근이 막히면 부족분과 근거를 보고하고 대기/중지하며, 자동으로1~4개를5개처럼 처리하지 않는다.
7. 최신 추가 요청에 따라 **최종 본문에도 서로 다른 원본 최소5개를 실제 사용**한다. 균등 분량은 요구하지 않는다. 장면 재사용·인접 원본 정상 속도 연장·관련 리액션은 계속 허용한다. 같은 실패 반복과 접근 제한 우회로 수량을 채우지 않는다.

사용자 편집 기준:

- 전체 제품 매력·자연스러운 흐름이 판단 단위다. 문장마다 같은 행동·감정·색상을 동시에 보여줄 필요가 없다.
- 특장점 장면 반복을 허용한다. 반복마다 새 정보·새 구도를 요구하지 않는다.
- 놀람·행복·만족 등의 관련 리액션과 사용 맥락을 넣을 수 있다.
- 짧게 잘라 둔 구간이 부족하면 실제 같은 원본의 다음 구간을 정상 속도로 더 사용한다. 감속·마지막 프레임 정지로 메우지 않는다.
- 다른 제품/부품을 해당 제품의 직접 시연으로 오인시키는 문제, 실제 반대 동작 시연과 사실 오류는 계속 검토한다.

## 5. 구현 순서와 단계별 완료 조건

### 단계1 — 수량·원본 집중도 관측과 현재 후보 재대조

먼저 기준선을 코드로 재현한다. 새 점수나 수집 동작을 넣기 전에 실제 사용 현황이 정확히 나와야 한다.

- 다운로드/보관 재사용 → 내용 검토 → 가림/세로 승인 → semantic options 포함 → 최종 선택을 단계별로 연결한다.
- 각 후보의 제외 이유를 구분한다: 무관 제품, 오인 시연, 파일 불량, 가림 미해결, 미검토, 같은 부모/중복, 의미 옵션에서 미선정, solver에서 미선정.
- 원본 식별은 기존 SHA·original_sha256·original_interval과 검증된 시간 변환을 재사용한다. 파일명/shot ID가 다르다고 새 원본으로 세지 않는다.
- 재게시 콘텐츠처럼 파일 SHA만 다른 경우, 기존 frame_hashes/시각 유사도는 별도 반복 단서로 기록한다. 근거 없이 같은 부모로 합치거나 완벽한 중복 탐지로 보고하지 않는다.
- 지표: 사용 파일 수, 확인된 부모 원본 수, 원본별 사용 초/점유율, 최대 점유율, 원본 시간 재사용량, 시각적으로 유사한 장면 반복, 적합한 미사용 대안 수.
- 표지1프레임과 본문을 구분하고 실제 출력 정수 프레임 또는 배치 구간 길이를 일관되게 집계한다.

완료 조건: 현재 세 영상의3·2·1개와 가방88.5%/손난로100%를 재현하고, 후보가 사라진 단계까지 설명하는 JSON/MD가 새 경로에 있다. 확보 파일 수와 현재 state records 수 차이도 설명한다.

### 단계2 — 확보한 후보를 더 잘 활용하는 선택기

추가 다운로드 이전에 현재 재고로 편집이 달라지는지 확인한다.

- 부모 원본별 누적 화면 시간을 solver 상태에 넣는다. 같은 부모의 shot을 바꾸어도 누적량은 유지한다.
- 부모 집중도의 점진적 비용을 추가한다. 예를 들어 `sum((parent_seconds / body_duration)^2)` 증가분을 사용하면 특정 비중을 넘자마자 실패하는 문턱 없이 편중을 줄일 수 있다. 이는 설계 후보이며 가중치는 실제 세 계획·반례로 정한다.
- 기존 replay 비용·연속 visual_cluster 비용·품질/구도/가림 비용과 역할을 구분해 이중 처벌을 피한다.
- 실제 product/direct_action 증거와 오인 방지는 유지한다. montage_support에서 관련 리액션/사용 맥락이 “제품 미노출”만으로 항상 밀리는지 확인하고 필요한 범위에서 점수를 조정한다.
- 의미상 부적합한 옵션을 새로 만들지 않는다. 적합한 후보가 많으면 최대6개 상한 전에 동일 원본의 비슷한 shot만 남지 않도록 후보 구성을 점검한다.
- 이미 frozen인 계획을 변조하지 않는다. 새 요청·새 정책 버전으로 선택하고 policy/가중치/실제 선택을 freeze·cache binding에 포함한다. 과거 계획은 유지한다.
- 비용 항목별 점수와 대안 미선정 이유를 진단에 남겨 “왜 또 같은 원본인가”를 설명할 수 있게 한다.

완료 조건: 동등하게 적합한 다른 부모가 있으면 한 부모 여러shot보다 자연스럽게 분산되는 행동 반례가 통과한다. solver 자체는 한 원본만 적합해도 정상 배치/재사용 가능하다. 이것으로 신규 수집의 소스5개 조건을 우회하지 않는다. 저품질/오인/무관 후보로 개수만 늘리는 결과는 개선으로 인정하지 않는다.

### 단계3 — 수집 종료와 예상 편집 구성 연결

수집 완료/재고 준비(`ready`)는 새 최소 기준(영어5·중국어5 실제 검색+관련 소스5개+핵심 제품 구간)을 확인한다. 원본 집중도에 따른 추가 다양성 권고는 별도 상태로 둔다. 이전 v4의 ready=true만으로 새 정책 최소치를 충족한 것으로 재사용하지 않는다.

- 최소 기준 수집과 병행하거나 준비 후 기존 분석/prepare-only 경계를 활용해 예상 선택 구성과 실제 사용 가능한 대안을 확인한다. 별도 TTS·전체 렌더를 실행하지 않는다.
- 이미 분석한 shot/동일 입력 계획은 SHA에 결속해 재사용한다. 음성 길이·검토 구간·실제 후보가 바뀐 경우에만 필요한 재평가를 한다.
- 한 원본 의존이 크면서 적합한 미사용 후보/미검토 자료 또는 제품 근거가 있는 미소비 검색 범위가 있을 때 보완 기회로 기록한다. 80%·90% 같은 비중을 쓰더라도 진단/탐색 신호이지 실패 문턱이 아니다.
- 순서는 기존 적합 대안 선택 → 이미 받은 미검토 후보 검토 → 같은 원본의 관련 인접 구간 검토 → 필요한 새 원본 검색이다. 이미 있는 자료를 보지 않고 다시 다운로드하지 않는다.
- 가능한 편집안은 유지한다. 최소 기준 충족 후 선택적인 추가 보완 기회가 없으면 원래 편집안으로 끝낸다. 최소 기준 미달이고 새 자료가 무관/중복뿐이면 부족한 수량·소진 근거를 기록하고 대기/중지한다. 기존 완성본은 보존한다.
- 새 수집 후보가 생겼다면 정상 source review/사용자 제외/가림/세로/semantic 검사를 통과한 뒤에만 새 편집 입력으로 수용한다.

완료 조건: 세 최소 조건을 각각 증거로 확인해야 수집 완료가 된다. 이미 최소 기준을 충족한 뒤에는 점유율/최종 사용 수 때문에 무조건 추가 수집하거나 제작을 막지 않는다. 최소 미달은 완료로 숨기지 않고 관련 없는 후보 추가 없이 명확히 보고한다.

### 단계4 — 근거 있는 제품 검색과 진전 기반 종료

- 보관본으로 분량이나 소스5개가 찼어도 영어5·중국어5 실제 검색을 생략하지 않는다. 현재 접근 중지이면 그 플랫폼 요청은 멈추고 다른 승인된 접근 가능 경로를 검토한다. 충족하지 못한 검색을 수행한 것으로 세거나 과거 다른run의 검색을 무조건 승계하지 않는다.
- 검색 언어별 계획/실제 제출/후보/수신/승인/최종 사용을 연결해 기록하고 다음 실험에서 비교한다. 한국어 검색 결과에 해외 영상이 나왔다는 이유로 영어·중국어 검색을 수행했다고 세지 않는다. 언어만으로 특정 플랫폼·모든 제품의 수집 효율 우위를 확정하지 않는다.
- 제품 중심 대상은 실제 원문·프레임 근거와 연결한다. 손난로를 단순 “사과”로 축약하거나 몽벨 가방을 재킷으로 넓히지 않는다.

### 단계5 — 독립 검수·동일 세 영상 비교·운영 적용

구현 요청으로 새 세션을 시작할 때 이 단계까지 완료 범위로 삼는다. 계획 파일을 읽었다는 이유만으로 현재 완료/중지 작업을 자동 재개하지 말고 그 세션의 실행 요청과 AGENTS.md를 따른다.

- 기준/선택/수집 연결의 검수 에이전트와 실제 제작의 오류·비효율 감시를 둔다. 무관 후보 증가·같은 실패 반복·정상 대기 오판을 기록한다.

- 개선본은 정상 full decode·마스크/컷 경계·표지·오디오 결속·실제 QA를 통과해야 한다. 다른 기준의 캐시나 기존 false 삭제로 통과시키지 않는다.

필수 행동 반례:

1. 같은 부모에서 잘린 여러 파일/shot을 서로 다른 원본으로 부풀리지 않는다.
2. 동등하게 적합한 다른 부모가 있으면 분산을 선호하고, 한 부모의 다른shot으로 바꿔도 누적 점유율이 유지된다.
3. solver 단독 검증에서는 적합한 원본1개뿐이어도 반복 배치가 가능하다. 신규 수집 완료는 별도로 관련 승인 소스5개를 요구하므로 단독 solver 성공을 수집 최소 충족으로 승격하지 않는다. 무관한 재킷/과일/다른 제품 직접 시연은 개수 보충용으로 넣지 않는다.
4. 관련 리액션/사용 맥락은 일반 혜택/이야기 컷에서 실제 선택될 수 있다. 주제품 구조/직접 시연 증거는 유지한다.
5. 다른 원본이어도 사실상 같은 장면이면 다양성 개선을 과장하지 않는다. 한 원본에 서로 다른 자연스러운 장면이 있으면 그 가치도 인정한다.
6. 최소 기준을 충족한 뒤 새 보완 기회가 없으면 정상 종료하고, 미달이면 부족분을 보고한다. 같은 입력·이미 실패한 물리 범위·동일 검색 후보는 반복하지 않는다.
7. 로컬 미검토 대안이 있으면 외부 다운로드보다 먼저 처리한다. 이미 받은 파일을 쓰기 전에 실제 승인·SHA를 검증한다.
8. 사용자 중지/제외·새 revision·수집 중 상태 변경과 실제 CAPTCHA/429를 덮지 않는다.
9. 이전 frozen 계획/완성본/legacy v3 정책을 읽기나 재시작만으로 변경하지 않는다. 새 점수의 cache/freeze 구분을 검증한다.
