# 현재 작업 경계와 영상 완료 계약

현재 규칙이다. 개별 작업의 ID·PID·실행 결과·임시 주소는 이 문서에 누적하지 않는다.

## 실행 경로

| 작업 | 현재 경로 | 반드시 읽을 원본 |
|---|---|---|
| 게시물 준비·계정 관리 | `hotpost.publication_server` → `post_preparation` / `accounts` | [게시물 문구](POST_COPY_RULES.md), [화면 계약](POST_PREPARATION_UI_20261022.md) |
| 대본 집필·수정 | `hotpost/writing` → 공식 Codex CLI | [대본 규칙](../hotpost/writing/RULES.md) |
| 소스 검색·검토 | 기존 로그인 Chrome, 실제 입력/결과 기록 | [수집 규칙](SOURCE_WORKFLOW.md) |
| 개인 음성 | `voicebench_adapter` → 별도 VoiceBench HTTP API | [잘림 복구](TTS_TRUNCATION_RECOVERY.md) |
| 편집 | 명시 요청된 독립 편집 경로, Auto CapCut과 버전 JSON·별도 프로세스 경계 | [전체 매력·몽타주](editorial_montage_policy.md) |
| 전달·저장 | `post_thumbnail` → `publication_export` | [저장 절차](LOCAL_VIDEO_STORAGE.md), 아래 완료 기준 |
| 휴대폰 게시 | 명시 요청된 `mobile_reels_cli` | [폰 제어](MOBILE_REELS_WIREGUARD.md) |

기존 제작실 UI·API·Studio 실행기·종속 자동 제작은 **outdated / 참고용 보존**이다. 신규 작업의 기본 실행·복구·개선 경로로 사용하지 않는다. 코드·테스트·작업 자료는 보존하며, 별도 명시 지시 없이 재사용·활성화·수정하지 않는다. `python -m hotpost serve`를 게시용 서버 대신 실행하지 않는다. 독립 게시용 서버는 `python -m hotpost.publication_server`이며 개발 검증은 임시 data·포트에서 한다. 서비스 시작 자체는 운영 재개 허가가 아니다.

`script_auto`와 로컬 Qwen 집필기는 폐기된 집필 경로다. 과거 `data/writing/legacy`는 읽기 전용 결과다. VoiceBench의 Qwen 음성 엔진과 혼동하지 않는다. 과거 특정 제품용 `tools/refine_*`, `build_*` 실험을 신규 대본 기준으로 재사용하지 않는다.

## 한 영상의 진행과 보류

신규 제작은 [게시물별 공통 상태](REFERENCE_STATUS.md)를 먼저 읽는다. 최신 원본 **게시 날짜**부터 날짜별 우선순위 순으로 미착수 후보를 확인하되, 기존 미완료 영상이 있으면 ID·단계·사유를 보여주고 사용자가 **이어 만들기 또는 새 영상 제작**을 결정할 때까지 새 작업을 시작하지 않는다. 새 영상을 명시적으로 선택하면 기존 중단 상태와 자료를 보존하고 선택 근거를 원장에 남긴 뒤 한 편만 진행한다. 중단 재개는 사용자가 지정한 고정 video_id의 원래 task/run을 확인한다. 순위 번호나 과거 요약만으로 대상을 바꾸지 않는다.

1. 새 명시 요청의 대상·범위와 현재 중지를 확인한다. 기존 task/run·영속 담당자·선택 대본·음성·소스·완료본을 보존한다. 과거 기록의 재개 명령을 현재 승인으로 사용하지 않는다.
2. 서로 다른 영상의 준비·집필·수집·음성·편집·export·최종 QA는 병행하지 않는다. 다음 후보 선정/대기열 보관만 가능하다. 현재 영상의 실제 완료 전 다음 영상의 자료를 준비하지 않는다. 단, 사용자가 현재 중단 영상의 상태를 보고 **새 영상**을 명시 선택한 경우에는 위 공통 상태 계약의 전환 기록을 남기고 한 편만 새로 진행한다.
3. 현재 영상 담당자가 끝까지 책임진다. 실패·보류·사용자 중지를 완료로 처리하거나 다음 영상으로 자동 건너뛰지 않는다. 명시 선택으로 새 영상으로 전환해도 이전 영상은 완료로 표시하지 않고 막힌 단계·증거·다음 행동·재개 조건을 보존한다.
4. 실제 진전 없는 같은 입력·수리·검색·모델 판단을 반복하지 않는다. 영속 보류를 시간 경과·프로세스 재시작으로 풀지 않는다. 정상 서비스/용량/접근 대기는 콘텐츠 실패와 구분한다. [진전 정책](quality_progress_policy.md)을 따른다.
5. 제작 중 문제는 Git 제외 로컬 기록과 [문제 기록](PRODUCTION_ISSUES.md)에 남기고 별도 수정한다. 필수 단계의 실제 실행 오류로 정상 경로도 막힌 경우만 근거·범위를 기록해 최소 수리 후 짧게 재현 확인하고 같은 단계로 돌아간다. 비치명 개선을 위해 전체 제작을 반복하지 않는다. 접근·중지·품질 기준은 수리 예외로 우회하지 않는다.

기존 자동 제작의 구현/검증 이력은 [완료 제어](PRODUCTION_COMPLETION_CONTROL_20261022.md), [신뢰성 감사](workflow_reliability_audit.md)에 있다. 이를 읽는 것만으로 실행기를 재개하지 않는다. 사진·캐러셀 자동 제작은 기본 비활성 상태이며 개별 과거 실험은 일반 재개 허가가 아니다.

## 제작 담당자와 감시 담당자

- 영상 제작을 시작·재개할 때 메인 에이전트는 현재 영상의 task/run·중지·기존 영속 담당자를 먼저 확인하고, **한 영상에 전담 제작 에이전트 한 명과 별도 감시 에이전트 한 명**을 결속해 Git 제외 로컬 인계에 신원·범위·시작 상태를 남긴다. 기존 담당자와 감시자가 있으면 이어 쓰고 이중 제작·중복 감시를 만들지 않는다. 감시자를 붙이지 못했다면 감시 중이라고 주장하거나 제작을 독자적으로 진행하지 않고 그 상태를 보고한다. 메인 에이전트는 선정·등록·조율·결과 확인을 맡는다.
- 제작 에이전트가 소스·대본·TTS·편집·현재 파일의 최종 QA와 전달까지 같은 한 편을 책임진다. 감시 에이전트는 같은 task/run에 붙어 **읽기 전용**으로 실제 단계 진전, 무진전 반복, 검색어의 원작·제품·장면 근거와 언어·플랫폼 적합성, 생성/선정/실제 제출의 구분, 후보 발견/다운로드/채택/사용의 구분, 소스·음성·편집·QA의 중지 및 품질 규칙 준수를 관찰한다. 이상 징후는 근거와 함께 제작 담당자와 메인 에이전트에 제때 알린다. 감시자는 검색 제출·다운로드·미디어 승인·대본 변경·렌더·DB 상태 변경·코드 수리를 대신하지 않는다.
- **현재 영상이 실제 최종 QA와 완료 조건을 충족한 뒤**, 감시 에이전트는 그 영상의 Git 제외 작업 폴더에 감시 결과를 Markdown으로 저장한다. task/run, 관찰 시각, 단계별 실제 진전, 검색어와 소스의 이상 여부, 각 문제의 파일·URL·시간 구간·로그 등 재확인 가능한 근거, 미확인 사항을 구분해 적는다. 완료 전에 막혔다면 보류 근거를 임시 기록으로 남기되 완료 후 감시 보고서라고 부르지 않는다.
- 메인 에이전트는 완료 후 감시 Markdown의 **문제 주장마다** 현재 원본·로그·실제 파일·프레임 및 필요한 짧은 재현으로 사실 여부를 독립 확인한다. `확인됨 / 반증됨 / 근거 부족`과 판단 근거를 기록하고, 감시자의 추측을 확정 결함으로 승격하지 않는다. 확인된 문제만 [문제 기록](PRODUCTION_ISSUES.md)에 연결해 별도 수정·짧은 검증을 수행한다. 비치명 개선 때문에 완성 영상을 통째로 반복 제작하지 않는다. 필수 단계가 실제 오류로 막힌 경우에만 위 최소 수리 원칙에 따라 같은 단계로 돌아가며, 제작자와 감시자가 동시에 수리하지 않는다.

## 콘텐츠·서비스 경계

- 대본은 `writing/RULES.md`가 단일 원본이다. 세 안, 첫 문장의 미해결 의문, 도입 감탄사·금지 질문형, 짧은 '나도' 종결과 사용자 선택안을 보존한다. 선택 원고를 원본 전사로 대체하지 않는다.
- 실제 음성 전사 `speech`, 프레임 OCR `screen_text`, 본문·추론을 구분한다. 미확인 기능·건강 효능·가격·사용 경험을 사실로 만들지 않는다.
- 음성은 승인한 개인 참조·엔진·Seed·품질·실제 생성 파라미터를 고정하고 쇼츠 전체 원고를 한 번에 합성한다. 잘림은 별도 절차로 표현을 교정하며 분할·끝문장 덧붙이기·Seed 변경으로 해결하지 않는다. 긴 원고의 VoiceBench 일반 기능과 쇼츠 계약을 구분한다.
- VoiceBench 패키지 직접 import·클라이언트 엔진/참조/Seed 덮어쓰기는 금지한다. 수동 공식 목소리는 `/v1/voices`가 공개한 `voice_id`만 사용하고 빈 ID는 해당 PC의 개인 기본값을 유지한다.
- Auto CapCut은 별도 프로세스·버전 JSON 경계를 유지한다. 패키지 직접 import·가상환경 통합을 하지 않는다.
- 계정 목록의 원본은 `influencer_list.txt`이며 `AccountRegistry`로 DB와 동기화한다. DB만 수정하지 않는다. 계정 삭제는 과거 게시물 삭제가 아니다.
- 댓글·DM·파트너스·리틀리·실제 게시를 초안 저장의 부수 동작으로 실행하지 않는다. 상품 확인/게시 계정 역할과 기존 1회 시도·실패 이력은 보존한다. 필요할 때 [수익화 계약](MONETIZATION_PLAN_20261015.md)을 읽는다.

## 실제 완료·전달

- 전체 제품 매력과 자연스러운 흐름으로 검토한다. 문장별 정확한 동시 시연을 강제하지 않되 다른 제품·반대 동작을 직접 시연으로 오인시키지 않는다. 정상 속도 연장·관련 컷 연결·검토된 반복은 가능하며 감속/끝 프레임 정지로 자동 충당하지 않는다.
- 썸네일은 실제 사용 구간의 프레임, 얼굴 없음(반사·사진 포함), 얼굴 블러 대체 금지다. 제품 크롭은 원본 SHA·시각·좌표·새 이미지 SHA를 결속하고 새 픽셀/마스크를 재검토한다. 기존 본문 승인을 표지 승인으로 재사용하지 않는다.
- 최종 영상 전체와 첫 표지에 작은 옅은 회색 `[광고]`를 우상단 여백 안에 읽히도록 유지한다. 원작 워터마크로 제거하거나 음성에 넣지 않는다.
- 전달본은 MP4 H.264 Main@4.0 / 8bit yuv420p / AAC-LC / faststart가 기본이다. 무손실 `-qp 0` master를 전달하지 않는다. 실제 프로파일·레벨·픽셀 형식·전체 디코드·다운로드 파일을 검증한다.
- QA는 현재 대본·음성·plan·최종 파일 SHA와 결속한다. 설정 일치는 청감 승인이나 실폰 재생 확인이 아니다. 코드 구현·격리 검증·프로세스 로드·실제 영상 완료를 구분한다.
- 영상 완료·썸네일 변경 완료 뒤 해당 PC의 `local/VIDEO_STORAGE.md`, `local/video-storage.json`과 공통 저장 절차를 읽고 현재 영상/실제 표지를 복사·해시 검증한다. 설정 없는 PC의 경로를 추측하지 않는다.
- 결과·미리보기·비교·다운로드는 실제 외부 접근을 검증한 **Cloudflare HTTPS**로 전달한다. 영상 Range·다운로드 헤더·SHA를 확인하고 비교는 원본 왼쪽/완성본 오른쪽이다. localhost를 전달 링크로 대신하지 않는다. 임시 터널 의존·실패·미검증은 정확히 보고한다. 공개는 요청된 미디어·읽기 전용 페이지로 제한하며 제작 API·인증정보·폰 화면을 노출하지 않는다.
