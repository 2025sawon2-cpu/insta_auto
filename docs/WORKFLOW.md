# 현재 작업 경계와 영상 완료 계약

현재 규칙이다. 개별 작업의 ID·PID·실행 결과·임시 주소는 이 문서에 누적하지 않는다.

## 실행 경로

| 작업 | 현재 경로 | 반드시 읽을 원본 |
|---|---|---|
| 게시물 준비·계정 관리 | `hotpost.publication_server` → `post_preparation` / `accounts` | [게시물 문구](POST_COPY_RULES.md), [화면 계약](POST_PREPARATION_UI_20261022.md) |
| 대본 집필·수정 | `hotpost/writing` → 공식 Codex CLI | [대본 규칙](../hotpost/writing/RULES.md) |
| 소스 검색·검토 | 기존 로그인 Chrome, 실제 입력/결과 기록 | [수집 규칙](SOURCE_WORKFLOW.md) |
| 개인 음성 | `voicebench_adapter` → 별도 VoiceBench HTTP API | [잘림·발음 이상 복구](TTS_TRUNCATION_RECOVERY.md) |
| 편집 | 명시 요청된 독립 편집 경로, Auto CapCut과 버전 JSON·별도 프로세스 경계 | [전체 매력·몽타주](editorial_montage_policy.md) |
| 전달·저장 | 독립 제작은 `production_delivery`, 기존 썸네일 반영은 `post_thumbnail` → `publication_export` | [독립 전달](PRODUCTION_DELIVERY.md), [저장 절차](LOCAL_VIDEO_STORAGE.md), 아래 완료 기준 |
| 휴대폰 게시 | 명시 요청된 `mobile_reels_cli` | [폰 제어](MOBILE_REELS_WIREGUARD.md) |

기존 제작실 UI·API·Studio 실행기·종속 자동 제작은 **outdated / 참고용 보존**이다. 신규 작업의 기본 실행·복구·개선 경로로 사용하지 않는다. 코드·테스트·작업 자료는 보존하며, 별도 명시 지시 없이 재사용·활성화·수정하지 않는다. `python -m hotpost serve`를 게시용 서버 대신 실행하지 않는다. 독립 게시용 서버는 `python -m hotpost.publication_server`이며 개발 검증은 임시 data·포트에서 한다. 서비스 시작 자체는 운영 재개 허가가 아니다.

`script_auto`와 로컬 Qwen 집필기는 폐기된 집필 경로다. 과거 `data/writing/legacy`는 읽기 전용 결과다. VoiceBench의 Qwen 음성 엔진과 혼동하지 않는다. 과거 특정 제품용 `tools/refine_*`, `build_*` 실험을 신규 대본 기준으로 재사용하지 않는다.

## 한 영상의 진행과 보류

신규 제작은 [게시물별 공통 상태](REFERENCE_STATUS.md)와 [오전 7시 선정](DAILY_RANKING.md)을 먼저 읽는다. 최근 **72시간** 게시물의 현재 조회수/팔로워 수가 기준을 통과한 전체 순위에서 미착수 후보를 확인한다. 완성된 영상은 성과 순위에 남기되 제작 대상에서만 건너뛴다. 기존 미완료 영상이 있으면 ID·단계·사유를 보여주고 사용자가 **이어 만들기 또는 새 영상 제작**을 결정할 때까지 새 작업을 시작하지 않는다. 새 영상을 명시적으로 선택하면 기존 중단 상태와 자료를 보존하고 선택 근거를 원장에 남긴 뒤 한 편만 진행한다. 중단 재개는 사용자가 지정한 고정 video_id의 원래 task/run을 확인한다. 순위 번호나 과거 요약만으로 대상을 바꾸지 않는다.

1. 새 명시 요청의 대상·범위와 현재 중지를 확인한다. 기존 task/run·영속 담당자·선택 대본·음성·소스·완료본을 보존한다. 과거 기록의 재개 명령을 현재 승인으로 사용하지 않는다.
2. 서로 다른 영상의 준비·집필·수집·음성·편집·export·최종 QA는 병행하지 않는다. 다음 후보 선정/대기열 보관만 가능하다. 현재 영상의 실제 완료 전 다음 영상의 자료를 준비하지 않는다. 단, 사용자가 현재 중단 영상의 상태를 보고 **새 영상**을 명시 선택한 경우에는 위 공통 상태 계약의 전환 기록을 남기고 한 편만 새로 진행한다.
3. 현재 영상 담당자가 끝까지 책임진다. 실패·보류·사용자 중지를 완료로 처리하거나 다음 영상으로 자동 건너뛰지 않는다. 명시 선택으로 새 영상으로 전환해도 이전 영상은 완료로 표시하지 않고 막힌 단계·증거·다음 행동·재개 조건을 보존한다.
4. 실제 진전 없는 같은 입력·수리·검색·모델 판단을 반복하지 않는다. 영속 보류를 시간 경과·프로세스 재시작으로 풀지 않는다. 정상 서비스/용량/접근 대기는 콘텐츠 실패와 구분한다. [진전 정책](quality_progress_policy.md)을 따른다.
5. 제작 중 문제는 Git 제외 로컬 기록과 [문제 기록](PRODUCTION_ISSUES.md)에 남기고 별도 수정한다. 필수 단계의 실제 실행 오류로 정상 경로도 막힌 경우만 근거·범위를 기록해 최소 수리 후 짧게 재현 확인하고 같은 단계로 돌아간다. 비치명 개선을 위해 전체 제작을 반복하지 않는다. 접근·중지·품질 기준은 수리 예외로 우회하지 않는다.

기존 자동 제작의 구현/검증 이력은 [완료 제어](PRODUCTION_COMPLETION_CONTROL_20261022.md), [신뢰성 감사](workflow_reliability_audit.md)에 있다. 이를 읽는 것만으로 실행기를 재개하지 않는다. 사진·캐러셀 자동 제작은 기본 비활성 상태이며 개별 과거 실험은 일반 재개 허가가 아니다.

## 제작 담당자와 감시 담당자

- 영상 제작을 시작·재개할 때 메인 에이전트는 현재 영상의 task/run·중지·기존 영속 담당자를 먼저 확인하고, **한 영상에 전담 제작 에이전트 한 명과 별도 감시 에이전트 한 명**을 결속해 Git 제외 로컬 인계에 신원·범위·시작 상태를 남긴다. 기존 담당자와 감시자가 있으면 이어 쓰고 이중 제작·중복 감시를 만들지 않는다. 감시자를 붙이지 못했다면 감시 중이라고 주장하거나 제작을 독자적으로 진행하지 않고 그 상태를 보고한다. 메인 에이전트는 선정·등록·조율·결과 확인을 맡는다.
- 제작 에이전트는 소스·대본·TTS·편집·현재 파일의 최종 QA와 전달을 책임진다. 감시 에이전트는 같은 task/run을 **읽기 전용**으로 관찰한다: 단계 진전·무진전, 검색어의 원작/제품/장면 근거와 언어/플랫폼 적합성, 생성/선정/실제 제출, 후보 발견/다운로드/채택/사용, 소스·음성·편집·QA의 중지/품질 규칙. 검색 중 Chrome 탭 목록과 기록을 대조해 검색어·후보별 탭 및 완료된 다운로드 탭의 누적을 확인한다. 누적 시 사용자·현재 검토 탭과 구분해 불필요한 탭 ID·근거를 제작자와 메인에게 즉시 알려 정리를 요청한다. 다른 이상도 근거와 함께 알린다. 감시자는 탭 조작·검색 제출·다운로드·미디어 승인·대본 변경·렌더·DB 상태 변경·코드 수리를 하지 않는다.
- **현재 영상이 실제 최종 QA와 완료 조건을 충족한 뒤**, 감시 에이전트는 그 영상의 Git 제외 작업 폴더에 감시 결과를 Markdown으로 저장한다. task/run, 관찰 시각, 단계별 실제 진전, 검색어와 소스의 이상 여부, 각 문제의 파일·URL·시간 구간·로그 등 재확인 가능한 근거, 미확인 사항을 구분해 적는다. 완료 전에 막혔다면 보류 근거를 임시 기록으로 남기되 완료 후 감시 보고서라고 부르지 않는다.
- 메인 에이전트는 완료 후 감시 Markdown의 **문제 주장마다** 현재 원본·로그·실제 파일·프레임 및 필요한 짧은 재현으로 사실 여부를 독립 확인한다. `확인됨 / 반증됨 / 근거 부족`과 판단 근거를 기록하고, 감시자의 추측을 확정 결함으로 승격하지 않는다. 확인된 문제만 [문제 기록](PRODUCTION_ISSUES.md)에 연결해 별도 수정·짧은 검증을 수행한다. 비치명 개선 때문에 완성 영상을 통째로 반복 제작하지 않는다. 필수 단계가 실제 오류로 막힌 경우에만 위 최소 수리 원칙에 따라 같은 단계로 돌아가며, 제작자와 감시자가 동시에 수리하지 않는다.

## 제작자의 완료 전 최종 QA

이 절은 제작자의 최종 검토 기준이다. 위에 정한 **완료 후 감시 Markdown과 메인의 주장별 독립 검증을 앞당기거나 대체하지 않는다.** 이 문서를 읽거나 검사하는 일은 중지된 제작의 재개 승인이 아니다.

- 제작 에이전트가 최종 후보 MP4와 실제 적용 썸네일을 직접 확인한다. 같은 task/run의 Git 제외 작업 폴더에 대본·음성·편집 계획·최종 MP4·썸네일의 버전과 파일 식별값, 확인 시각, 아래 항목별 `충족 / 수정 필요 / 확인 불가` 판정과 실제 문장·시간 구간·프레임 근거를 남긴다. `규칙 읽음` 표시나 이전 후보 QA를 현재 파일의 합격 근거로 재사용하지 않는다. SHA는 검토한 파일과 저장·공유한 파일의 동일성 확인용이며 내용 품질의 증거가 아니다.
- **대본:** 신규 집필이면 [집필 규칙](../hotpost/writing/RULES.md)의 세 안과 선택 근거를 대조한다. 기존 선택안을 부분 수정했다면 원래 선택과 수정 전후를 확인하며 세 안을 새로 만들지 않는다. 첫 문장을 그대로 인용해 어떤 구체적 의문이 생기는지, 다음 장면을 보고 싶은 이유가 무엇인지, 이미 답을 다 말했는지 판단한다. 공통 다섯 단계의 역할을 실제 문구에 연결하되 문장 통합을 허용하고, 상황 반복·억지 문제·기능 나열·형식적인 공감과 세 안의 실질적 중복을 확인한다. 본문이 의문을 동작·단서·결과로 풀어 제품의 실제 매력에 연결되는지, 댓글 요청을 지워도 제품을 찾아보고 싶은 이유가 남는지 확인한다. 소스 수나 확보 장면에 맞춰 약한 대본을 채택하지 않는다. 사실·복사·말투·금지 표현도 확인하되 형식 항목만 맞아 내용 결함을 덮지 않는다. 내용 평가는 중간 사용자 승인 절차가 아니며 사용자 판단은 최종 영상에서 한다.
- **화면:** [소스 규칙](SOURCE_WORKFLOW.md)의 실제 사용 원본 수와 [편집 기준](editorial_montage_policy.md)의 핵심 장면 역할·전체 흐름을 별도로 확인한다. 같은 편집 기준의 본문 화면 채우기·움직임 검수를 적용해 9:16 파일 안의 실제 여백, 각 컷의 시작·중간·끝과 움직임·컷 경계에서 제품·손동작 잘림 및 원작 자막 잔여를 확인한다. 변화·결과가 소구점이면 필요한 처리 과정과 보이는 변화가 전달되는지 최종 MP4 시각과 원본 구간으로 기록한다. 다른 제품의 결과를 소개 제품의 단일 효과로 오인시키지 않는다. 사용 구간의 원본 대본 자막과 워터마크가 남지 않았는지 확인하며 제품 라벨·부수 문자·`[광고]`를 일괄 제거하지 않는다.
- **음성·자막:** 선택 대본과 실제 음성의 시작·끝 및 주요 문구를 듣고, [편집 연결 기준](editing_adapter.md)의 음성 단어 시각에 따른 자막이 최종 MP4의 여러 시점과 컷 경계에서 같은 순서·내용으로 보이는지 확인한다. 오디오·비디오 스트림이 동시에 시작한다는 사실만으로 문장별 싱크를 합격시키지 않는다. 승인한 음성 설정의 일치와 실제 청감도 구분한다. 사용자가 확인한 발음 이상은 수정 대상으로 기록하고 [음성 복구 기준](TTS_TRUNCATION_RECOVERY.md)에 따라 교정·재합성한 뒤 원래 문제 문구와 앞뒤 연결을 다시 확인한다. ASR만 의심하는 경우와 확정 결함을 구분하며 전사 일치로 청감까지 승인하지 않는다.
- **표지·전달:** [썸네일 기준](../hotpost/writing/RULES.md)과 실제 적용 이미지·영상 첫 프레임을 대조해 문장 끝 마침표, 얼굴, `[광고]`를 확인한다. 이미지의 대표성과 문구의 후킹을 각각 평가하고, 함께 봤을 때 생기는 기대를 영상이 충족하는지 본다. 문구를 이미지 설명이나 대본 첫 문장에 맞추도록 강제하지 않으며 표지 한 장에 문구의 결과가 보이지 않는다는 이유만으로 감점하지 않는다. 기술 형식과 저장 검사는 아래 완료 기준과 [저장 절차](LOCAL_VIDEO_STORAGE.md)를 따르되 기술 검사 통과로 내용 검토를 대체하지 않는다. 설정 일치는 청감 승인이나 실폰 재생 확인이 아니며, 코드 구현·격리 검증·프로세스 로드·실제 영상 완료를 구분한다.

`수정 필요`나 `확인 불가`가 남은 현재 파일은 완료 조건을 충족했다고 기록하지 않는다. 제작자는 확인된 부분을 수정하고 영향받은 항목과 새 파일을 다시 QA한다. 무진전 반복과 불필요한 전체 재제작은 위 보류·최소 수리 원칙을 따른다. 후속 감시·검증에서 필수 완료 항목의 결함이 확인되면 그 파일을 품질 합격본으로 계속 보고하지 않고 [공통 상태](REFERENCE_STATUS.md)의 완료 근거를 정정한다. 기존 파일·이력은 보존하며 허용된 같은 영상의 수정본을 해당 항목부터 다시 QA한다. 이전 파일의 통과 근거를 새 파일에 그대로 적용하지 않는다.

### 현재 파일에 결속한 제작자 QA 기록

사용자 반응은 바로 앞의 대상·맥락·명시한 확인 범위에만 적용한다. 대본 확인이나 단순 진행 동의인 “좋아”를 영상 재생·청감·문장별 싱크 확인으로 넓히지 않는다. 음성을 실제 들을 수 없으면 `확인 불가`를 유지한다. 사용자 검토를 근거로 쓸 때에는 해당 evidence에 `method=human_user_review`, `user_quote`(실제 발언), `review_context`(제시한 대상과 질문), `reviewed_checks`(확인된 항목), `video_sha256`을 남긴다. 코드가 범위·현재 파일 결속을 검사하더라도 발언 의미를 대신 판단하지 않는다.

판정 기준은 위 Markdown 규칙이다. 제작 에이전트는 실제 파일을 보고 판단한 뒤, 같은 Git 제외 task/run 폴더에 UTF-8 JSON 기록을 남긴다. 신규 완료 전환에는 `schema_version=2`, `video_id`(shortcode), `task_id`, `run_id`, `edit_id`, `producer`, 시간대가 있는 ISO `reviewed_at`이 필요하다. `artifacts`의 `script`·`voice`·`plan`에는 각각 현재 선택본의 `id`, 실제 파일의 절대 `path`와 SHA-256을, `video`·`cover`에는 각각 현재 최종 파일의 절대 `path`와 실제 SHA-256을 기록한다. `dependencies.sources`에는 실제 사용 원본 파일 전체를, `dependencies.rules`에는 적용한 지침 원본을 각각 비어 있지 않은 `{path, sha256}` 배열로 연결한다. 코드는 연결된 입력 파일·규칙의 실제 바이트가 검토 당시와 같은지 확인하며, 자료 선택의 타당성·내용 품질은 제작자가 원본과 대조한다. 이 목록이 모든 사용 원본과 필요한 규칙을 포함했는지도 제작자가 확인한다.

내용 검토 **전에** `python -m hotpost.final_qa inputs --script <선택 대본 파일> --voice <음성 파일> --plan <계획 JSON> --source <사용 원본 파일> --rule <규칙 원본>`으로 입력 경로와 해시를 읽기 전용 JSON으로 얻을 수 있다. `--source`·`--rule`은 필요한 파일마다 반복한다. 출력의 입력 정보를 같은 QA 기록에 연결하고 원래 선택본의 ID를 추가한 뒤 실제 검토와 판정을 기록한다. 명령은 QA 기록을 쓰거나 `충족` 판정을 생성하지 않는다. 변경 뒤 해시만 다시 채워 이전 판정을 유지하지 않고 영향받는 내용과 연결을 재검토한다.

기존 `schema_version=1` 기록과 완료본은 기존 계약으로 읽고 `input_binding=legacy_metadata_only`로 범위를 구분한다. 원본·과거 판정을 자동 변경하거나 새 입력 검증을 소급해 주장하지 않는다. 새 `mark ... --state completed`에는 v2가 필요하다. v2 입력이 삭제·변경됐으면 현재 원장 완료 확인과 저장도 실패하며 자동 재제작하지 않는다. v1의 기존 영상·표지 해시 검사와 미확인 항목 거부는 유지한다.

`checks`에는 `script`, `visual`, `audio_captions`, `cover_delivery` 네 항목을 모두 둔다. 각 항목은 `status`를 `충족 / 수정 필요 / 확인 불가` 중 하나로 기록하고, `evidence` 배열에 실제 관찰의 `asset`·`location`(문장·시간 구간·프레임 등)·`observation`을 남긴다. 대본 항목은 `script`, 화면·음성/자막 항목은 `video`, 표지·전달 항목은 `cover`에 대한 근거를 각각 포함한다. 예: `"visual": {"status": "충족", "evidence": [{"asset": "video", "location": "00:03.2–00:05.1", "observation": "처리 과정 뒤 양말의 변화가 보임"}]}`. 빈 근거나 `수정 필요`·`확인 불가`가 있으면 완료로 표시하지 않는다.

`hotpost.final_qa.validate`는 기록의 형식·task/run·제작자 결속과 현재 영상·표지의 파일 존재/해시를 검사하고, v2의 대본·음성·계획·연결한 소스·규칙도 실제 파일과 대조한다. 검증 도중 파일이나 QA 기록이 바뀌면 거절한다. 관찰 내용의 진실성·후킹·청감·마스킹 품질을 자동 보증하지 않는다. `reference_registry mark ... --state completed`와 `publication_export save ... --qa-record <이 JSON>`은 같은 검사를 거친다. 썸네일 반영 작업의 `completed`는 기술 작업의 종료이며 영상 품질 완료가 아니다. 반영 후 영상/표지 바이트가 달라졌다면 그 파일을 새로 검토해 QA 기록을 갱신한다. 과거 제작실 DB의 완료 이력은 읽기용으로 보존하고 새 QA 합격으로 소급 해석하지 않는다.

## 콘텐츠·서비스 경계

- 대본은 `writing/RULES.md`가 단일 원본이다. 세 안, 첫 문장의 미해결 의문, 도입 감탄사·금지 질문형, 짧은 '나도' 종결과 사용자 선택안을 보존한다. 선택 원고를 원본 전사로 대체하지 않는다.
- 실제 음성 전사 `speech`, 프레임 OCR `screen_text`, 본문·추론을 구분한다. 미확인 기능·건강 효능·가격·사용 경험을 사실로 만들지 않는다.
- 음성은 승인한 개인 참조·엔진·Seed·품질·실제 생성 파라미터를 고정하고 쇼츠 전체 원고를 한 번에 합성한다. 잘림·확인된 발음 이상은 [별도 절차](TTS_TRUNCATION_RECOVERY.md)로 표현을 교정하며 분할·끝문장 덧붙이기·Seed 변경으로 해결하지 않는다. 긴 원고의 VoiceBench 일반 기능과 쇼츠 계약을 구분한다.
- VoiceBench 패키지 직접 import·클라이언트 엔진/참조/Seed 덮어쓰기는 금지한다. 수동 공식 목소리는 `/v1/voices`가 공개한 `voice_id`만 사용하고 빈 ID는 해당 PC의 개인 기본값을 유지한다.
- Auto CapCut은 별도 프로세스·버전 JSON 경계를 유지한다. 패키지 직접 import·가상환경 통합을 하지 않는다.
- 계정 목록의 원본은 `influencer_list.txt`이며 `AccountRegistry`로 DB와 동기화한다. DB만 수정하지 않는다. 계정 삭제는 과거 게시물 삭제가 아니다.
- 댓글·DM·파트너스·리틀리·실제 게시를 초안 저장의 부수 동작으로 실행하지 않는다. 상품 확인/게시 계정 역할과 기존 1회 시도·실패 이력은 보존한다. 필요할 때 [수익화 계약](MONETIZATION_PLAN_20261015.md)을 읽는다.

## 실제 완료·전달

- 전체 제품 매력과 자연스러운 흐름으로 검토한다. 문장별 정확한 동시 시연을 강제하지 않되 다른 제품·반대 동작을 직접 시연으로 오인시키지 않는다. 정상 속도 연장·관련 컷 연결·검토된 반복은 가능하며 감속/끝 프레임 정지로 자동 충당하지 않는다.
- 썸네일은 실제 사용 구간의 프레임, 얼굴 없음(반사·사진 포함), 얼굴 블러 대체 금지다. 제품 크롭은 원본 SHA·시각·좌표·새 이미지 SHA를 결속하고 새 픽셀/마스크를 재검토한다. 기존 본문 승인을 표지 승인으로 재사용하지 않는다.
- 최종 영상 전체와 첫 표지에 작은 옅은 회색 `[광고]`를 우상단 여백 안에 읽히도록 유지한다. 원작 워터마크로 제거하거나 음성에 넣지 않는다.
- 전달본은 MP4 H.264 Main@4.0 / 8bit yuv420p / AAC-LC / faststart가 기본이다. 무손실 `-qp 0` master를 전달하지 않는다. 실제 프로파일·레벨·픽셀 형식·전체 디코드·다운로드 파일을 검증한다.
- QA는 현재 대본·음성·plan·최종 파일 SHA에 결속한다. 위의 완료 전 검토를 수행하되 SHA·설정 일치만으로 품질·청감을 승인하지 않는다.
- 영상 완료·썸네일 변경 완료 뒤 해당 PC의 `local/VIDEO_STORAGE.md`, `local/video-storage.json`과 공통 저장 절차를 읽고 현재 영상/실제 표지를 복사·해시 검증한다. 설정 없는 PC의 경로를 추측하지 않는다.
- 사용자가 링크를 요청하면 메인페이지·원본 게시물·결과물·미리보기·비교·다운로드 등 대상에 관계없이 실제 외부 접근을 확인한 **Cloudflare HTTPS 링크만** 전달한다. localhost·내부 주소나 원본 사이트의 직접 링크로 대신하지 않는다. 적절한 주소가 없으면 허용된 읽기 전용 범위에서 준비·검증하고, 만들 수 없거나 검증에 실패하면 링크를 제공하지 말고 이유를 정확히 알린다. 영상은 Range·다운로드 헤더·SHA와 필요한 재생을 확인하고 비교는 원본 왼쪽/완성본 오른쪽이다. 임시 터널 의존을 명시한다. 공개는 요청된 미디어·읽기 전용 페이지로 제한하며 제작 API·인증정보·폰 화면을 노출하지 않는다.
