# 현재 파일 최종 QA

이 문서는 [현재 작업 경계](WORKFLOW.md)의 제작자 완료 전 최종 검토 기준이다. 신규·재개 제작의 역할과 완료 후 감시 보고서·메인의 독립 검증 시점은 WORKFLOW를 따른다. 이 문서를 읽거나 검사하는 일은 중지된 제작의 재개 승인이 아니다.

## 제작자 검토 기록

- 제작 에이전트가 최종 후보 MP4와 실제 적용 썸네일을 직접 확인한다. 같은 task/run의 Git 제외 작업 폴더에 대본·음성·편집 계획·최종 MP4·썸네일의 버전과 파일 식별값, 확인 시각, 아래 항목별 `충족 / 수정 필요 / 확인 불가` 판정과 실제 문장·시간 구간·프레임 근거를 남긴다. `규칙 읽음` 표시나 이전 후보 QA를 현재 파일의 합격 근거로 재사용하지 않는다. SHA는 검토한 파일과 저장·공유한 파일의 동일성 확인용이며 내용 품질의 증거가 아니다.
- **대본:** 신규 집필이면 [집필 규칙](../hotpost/writing/RULES.md)의 세 안과 선택 근거를 대조한다. 기존 선택안을 부분 수정했다면 원래 선택과 수정 전후를 확인하며 세 안을 새로 만들지 않는다. 첫 문장을 그대로 인용해 어떤 구체적 의문이 생기는지, 다음 장면을 보고 싶은 이유가 무엇인지, 이미 답을 다 말했는지 판단한다. 본문이 의문을 동작·단서·결과로 풀어 제품의 실제 매력에 연결되는지, 댓글 요청을 지워도 제품을 찾아보고 싶은 이유가 남는지 확인한다. 소스 수나 확보 장면에 맞춰 약한 대본을 채택하지 않는다. 사실·복사·말투·금지 표현도 확인하되 형식 항목만 맞아 내용 결함을 덮지 않는다. 내용 평가는 중간 사용자 승인 절차가 아니며 사용자 판단은 최종 영상에서 한다.
- **화면:** [소스 규칙](SOURCE_WORKFLOW.md)의 실제 사용 원본 수와 [편집 기준](editorial_montage_policy.md)의 핵심 장면 역할·전체 흐름을 별도로 확인한다. 변화·결과가 소구점이면 필요한 처리 과정과 보이는 변화가 전달되는지 최종 MP4 시각과 원본 구간으로 기록한다. 다른 제품의 결과를 소개 제품의 단일 효과로 오인시키지 않는다. 사용 구간의 원본 대본 자막과 워터마크가 남지 않았는지 확인하며 제품 라벨·부수 문자·`[광고]`를 일괄 제거하지 않는다.
- **음성·자막:** 선택 대본과 실제 음성의 시작·끝 및 주요 문구를 듣고, [편집 연결 기준](editing_adapter.md)의 음성 단어 시각에 따른 자막이 최종 MP4의 여러 시점과 컷 경계에서 같은 순서·내용으로 보이는지 확인한다. 오디오·비디오 스트림이 동시에 시작한다는 사실만으로 문장별 싱크를 합격시키지 않는다. 승인한 음성 설정의 일치와 실제 청감도 구분한다.
- **표지·전달:** [썸네일 기준](../hotpost/writing/RULES.md)과 실제 적용 이미지·영상 첫 프레임을 대조해 문장 끝 마침표, 얼굴, 제품·문구 관계, `[광고]`를 확인한다. 기술 형식과 저장 검사는 WORKFLOW와 [저장 절차](LOCAL_VIDEO_STORAGE.md)를 따르되 기술 검사 통과로 내용 검토를 대체하지 않는다. 설정 일치는 청감 승인이나 실폰 재생 확인이 아니며, 코드 구현·격리 검증·프로세스 로드·실제 영상 완료를 구분한다.

`수정 필요`나 `확인 불가`가 남은 현재 파일은 완료 조건을 충족했다고 기록하지 않는다. 제작자는 확인된 부분을 수정하고 영향받은 항목과 새 파일을 다시 QA한다. 무진전 반복과 불필요한 전체 재제작은 WORKFLOW의 보류·최소 수리 원칙을 따른다. 이 기록은 제작자의 책임이며 **완료 후 감시 Markdown과 메인의 주장별 독립 검증을 앞당기거나 대체하지 않는다.** 후속 감시·검증에서 필수 완료 항목의 결함이 확인되면 그 파일을 품질 합격본으로 계속 보고하지 않고 [공통 상태](REFERENCE_STATUS.md)의 완료 근거를 정정한다. 기존 파일·이력은 보존하며 허용된 같은 영상의 수정본을 해당 항목부터 다시 QA한다. 이전 파일의 통과 근거를 새 파일에 그대로 적용하지 않는다.
