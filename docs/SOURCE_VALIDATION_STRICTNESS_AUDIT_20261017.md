# 소스 검증 엄격도: 실제 레퍼런스5개 비교

사용자 요청: 직전 영상의 남은 문제를 검증한 뒤 실제 레퍼런스5개와 현재 소스 검증 로직을 비교해 과도하게 엄격한지 확인한다. 기존 제작 상태·실패·원본·완성본과 운영 코드는 유지한 채 별도 audit 경로에서 검사한다. 제작 재실행이나 SNS 게시가 아니다.

**결론: 기능·화질·제품 매력 기준 전반이 과도하다는 증거는 없었다. 반면4초 단위 가림 검토가 유용한 짧은 구간까지 함께 제외하는 보수성은 실제 반례로 확인했다. 우선 개선할 것은 시간 구간 분할·가림 제안·거절 원인 분류다.** 원작의 자연스러운 상반신/생활 보조 컷을 무조건 탈락시키는 새 기준은 추가하지 않는다.

## 선정·방법

선정 결과를 새 모델 검사 전에 고정했다. 오늘 상위3인 스웻팬츠·틈새 선반·후드 집업과 바로 앞 제작의 지퍼 수선·토트백을 택했다. 착장 중심, 설치·생활 사용, 기계적 시연을 포함하며 검사 결과를 보고 교체하지 않았다. 과거10개 보정용 표본과 별도의 최근5개다.

- 원본5개 전체 구간에서 실제 native PTS 약0.5초 간격으로 **195프레임**을 저장하고 원본·프레임·화면 묶음 SHA를 결속했다. 모델에 실제 이미지를 전달했으며 원문은 ASR/OCR 오류 가능성을 유지했다.
- 현재 `source_functional.review_function`에 원본 자체를 후보로 넣는 정상 입력 대조 검사5회. 파일명이나 인기만으로 통과를 가정하지 않았다. 같은 영상의 양성 대조이므로 이것만으로 임의의 다른 후보에 대한 오탈락률을 추정하지 않는다.
- 현재 `source_presentation.review_presentation`으로 실제1080×1920 중앙 크롭3표본씩을 검사했다. 실제 비디오 스트림 끝을 사용했다.
- 별도 전체 제품 매력 검사5회는 기존 통과/실패 결과를 주지 않고 전체 시간표본과 `PRODUCT_APPEAL_INSTRUCTION`으로 판단했다. 문장별 사건 재현과 제품 지원 장면을 구분했다.
- 기존 저장 소스35개는 현재 `editing_ready`와 실제 파일 SHA, 기능/세로/가림 영수증을 대조했다. 저장된 완료 판단을 수정하지 않았다.
- 원본5개에 현재 가림 검토 경로도 별도로 적용한다. 원작 자막·워터마크를 갖춘 자연스러운 레퍼런스의 매력과, 우리 신규 영상에 재사용할 수 있는 승인 구간은 서로 다른 항목이다.
- 현재 관련 계약 회귀 **84개 통과**,4.28초. 별도 가림·마스크 계약35개도 통과,5.06초. `contracts.xml`, `mask-contracts.xml` 보관. 운영 정책을 낮춰 통과시킨 검사가 아니다.

근거 경로: `data/source-strictness-audit-20261017/`. 반복 가능한 도구 `tools/audit_source_strictness_20261017.py`. 운영 소스8모듈 SHA와 전체55task raw state SHA를 동결했다.

## 가림 구간 처리의 보수성

현재 최초 검토는 앞/중간/뒤 각4초다. 위 다섯 원본에서 합집합은 모두12초,전체 비디오 길이의 **46.8~87.6%**다. 나머지는 ‘품질 탈락’이 아니라 **아직 검토하지 않은 구간**이다. 새 다운로드 전에 같은 파일의 유용한 미검토 구간을 좁혀 검토할 여지가 있다. 반대로 보지 않은 나머지를 자동 승인하면 안 된다. `window-budget.json`.

`propose_masks`는 한 구간의 각 표본에서 찾은 서로 다른 위치를 모두 그4초 전체에 적용한다. 이동·변경되는 자막은 서로 다른 가림이 동시에 누적되어 필요 이상의 화면을 가릴 수 있다. 앞서 확인한 다중 가림의 실제 코드상 원인 중 하나다. 제안 좌표가 큰 오류 자체까지 이 구조 하나로 설명할 수는 없다.

개선 방향은 **불필요한 추가 수집 전에 유망한 짧은 구간을 시간별로 나누고, 각 구간의 실제 픽셀과 마스크를 다시 독립 검토하는 것**이다. 제품과 문자가 함께 가려진 채로 통과시키거나 기존 승인 영수증의 시간만 수동으로 줄여 쓰는 방식은 아니다.

## 보수적인 구간 손실을 확인한 추가 반례
