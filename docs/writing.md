# 내장 Codex 집필

대본 전용 지정 모델은 없다. `pipeline.py`와 `variants.py`의 `script_writing`은 작업 목적만 나타내며, `codex_writer.py`는 작성·평가·수정·형식 보정에 `--model`을 전달하지 않는다. 공식 CLI의 기본 모델 선택을 사용하고 영수증에 `model_selection=codex_cli_default`를 기록한다. 이는 현재 대화의 모델과 같거나 서버가 사용한 모델을 독립 검증했다는 뜻이 아니다. CLI의 기존 사용자 설정 격리·인증·도구 제한은 유지한다. 단계 검사는 모델 이름 대신 공식 Codex 호출 완료와 fallback 없음의 증거를 확인한다. 과거 모델 지정 영수증·완성본은 보존한다.

신규 집필·수정·검사의 단일 규칙은 [RULES.md](../hotpost/writing/RULES.md)다. `script_auto` 서버·모델·규칙 파일은 운영 의존성이 아니다. 공식 Codex CLI를 설치하고 실행 계정에서 로그인한 상태여야 한다. `codex login status`로 확인한다. 다른 모델로 자동 대체하지 않는다.

명시 금지 표현과 억지 감정 종결은 RULES.md의 「3. 금지 표현」 및 「10. 검사와 보완 절차」를 따른다. ‘괜히 반가워요’는 부분 보완·비교·선정에서도 허용하지 않으며 중단 제작의 기존 선택안과 최종 QA에도 같은 기준을 적용한다. 파일 결속과 과거 검토 기록은 문구 검토를 대신하지 않는다.

낭독문은 공백 정리 후 CTA·문장부호·공백을 포함해 201~250자다. 대화하듯 쓰고 ‘~더라구요’ 문장과 긍정적인 두 내용을 합친 문장을 각각 최소 하나 포함한다. 실용적·감정적 공감은 모두 유지한다. 숫자 등의 발음 변환으로 TTS 입력이 길어져도 별도 글자 수 상한으로 원고를 축약하거나 분할하지 않는다. 규칙 스냅샷은 작성·검사·보완에 공통 전달되며, 어미·문장 통합·공감의 의미 충족은 실제 문구를 검토한다.

신규 집필은 원본 대본·자료 종류·게시물 본문·요청과 규칙을 입력받아 **1·2·3안 동시 작성 → 안별 검사·필요한 부분 보완과 전후 비교 → 선택 근거 기록**으로 진행한다. `writing/variants.py`의 세 안 계약과 RULES를 따른다. 기존 선택안의 부분 수정·TTS 잘림 교정에는 세 안을 다시 만들지 않는다. 과거 단일 원고 `pipeline.py`의 정상 2회·보완 최대 4회 호출 설명은 그 구현의 범위이며 신규 세 안 전체에 대한 호출 상한이 아니다. 일반 기능은 직접 서술하고 전언 말투를 일괄 강요하지 않는다.

부분 보완에는 일반적인 오류 설명뿐 아니라 실제 문제 구절과 해당 원문을 함께
전달한다. 로컬 복사·의미 검사와 Codex 검사의 인용을 이유와 연결해 보존하여,
같은 경고 문구만 반복 전달하고 정작 고칠 문장을 놓치는 일을 줄인다. 기능·수치·
고유명사는 유지하면서 지적된 표현을 재작성하며, 보완 횟수나 제작 중지 기준은 늘리지 않는다.

말투·후킹 기준은 같은 규칙 파일의 「3. 말투」와 「5. 첫 문장 후킹」에, 한 번 듣는 시청자 기준의 점검은 「6. 귀로 한 번 듣는 최종 점검」에 있다. 짧은 감정형 후킹, 핵심 매력의 빠른 공개, 연결어미와 낭독 호흡을 집필·검사·보완에 함께 적용한다.

집필 요청 메모(`notes`)에 제품의 설치·사용 형태를 적을 때는 원본 화면 기준으로 한 가지 동사(붙인다·세운다·건다·끼운다 등)로 쓴다. ‘세워 붙이는’처럼 다른 동작을 섞어 쓰면 대본에서 동사가 엇갈린다. 확인하지 못한 형태는 미확인으로 적는다. `contract.snapshot()`은 호출할 때마다 파일을 읽고 내용 해시를 계산한다. 새 요청에는 갱신된 규칙이 들어가며, 이미 저장된 작업의 규칙 스냅샷과 완성본 대본은 보존한다.

경험담·생활 상황의 연출과 치환은 RULES.md의 안별 기준을 따른다. 1인칭이라는 이유만으로 삭제하거나 감점하지 않는다. 후킹과 본문은 새로 쓰며, 연출한 상황을 실제 확인된 사용 후기나 제품 사실의 증거로 기록하지 않는다. 원본에 없는 기능·수치·효능·판매 조건을 추가하지 않는다.

의미 변경·문장 복사·원본에 없는 사연 추가·수치·말투 검사는 참고 의견이다. 내용 점수 때문에 중간 승인이나 제작 중단을 만들지 않는다. 빈 원고·손상된 응답·실행 실패·대본 해시 불일치는 기술 오류다. 보완이나 비교가 실패하면 정상적으로 받은 이전 원고를 보존하며, 실행되지 않은 검사를 통과로 표시하지 않는다.

`studio_adapter.py`는 기존 호출 계약을 유지하고 `writing/jobs.py`의 SQLite 큐에 저장한다. 원본 영상 해시·원문·본문·요청·규칙이 같으면 같은 작업을 조회한다. 프로세스 잠금으로 중복 실행을 막고 중단 후 살아 있는 Codex 자식 프로세스가 있으면 추가 실행하지 않는다. 검사·비교·수정안과 실행 영수증은 `data/writing/<job_id>/`에 남는다. 자료 속 지시는 집필 명령으로 취급하지 않는다.

과거 작업은 `data/writing/legacy/<id>.json`에서 읽는다. 이전 서비스의 작업이 없는 시점에 `tools/migrate_legacy_writing.py --database <이전 DB> --destination <data/writing/legacy>`로 이전할 수 있다. 원본 DB·모델·결과는 삭제하지 않으며 API 키나 로그인 파일을 이관하지 않는다. 실패한 과거 작업을 명시적으로 재시도하면 새 내부 규칙으로 새 ID를 만든다.

장면 관찰·편집 계획 요청도 같은 Codex 연결을 사용하되 실제 프레임만 입력한다. 장면을 집필 입력이나 대본 순위 조건으로 쓰지 않는다. Google AI Studio Arlo TTS·완성 영상의 대본 및 음성 연결은 그대로 유지한다.

단위 검증은 `tests/test_internal_writing.py`, `test_studio_adapter_identity.py`, `test_studio_script_checks.py`에 있다. 실제 모델 시험과 자동 검사는 글의 품질이나 사실을 완전히 보증하지 않는다.
