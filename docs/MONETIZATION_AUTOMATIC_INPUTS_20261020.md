# 후속 작업 입력 자동화 — 2026-10-20

> 후속 사용자 변경: 원작 댓글 키워드 추출을 제거하고 댓글을 ‘나도’로 고정했다.
> 아래 원작 키워드 부분은 당시 구현 기록이며 최신 동작과 실제 한 건 확인 결과는
> `FIXED_COMMENT_VERIFICATION_20261020.md`를 따른다.

사용자 요청에 따라 `monetization.html`의 작업 ID·원작 댓글 키워드·작업별 계정
입력칸을 제거했다. 완성 영상 목록에서 제목을 선택하면 작업 ID와 원작 댓글 조건이
자동 연결된다. 우리 인스타 계정은 위쪽 공통 설정에 한 번 저장해 재접속과 이후
수동/자동 후속 작업에서 함께 사용한다. 자동 진행 체크는 선택 사항으로 유지한다.

## 데이터와 실행

- `monetization_inputs.py`: 제작 DB에서 최근 완료 영상 50개의 요약만 읽는다.
  제작실의 `?task=` 링크는 해당 영상을 선택하고, 일반 진입은 저장 계정의 앞선
  예약/진행 작업을 우선한다. 그 외에는 최신 완료 영상을 선택한다. 목록 밖의 명시
  작업은 한 건만 추가 조회한다. 존재하지 않는 명시 작업을 다른 영상으로 대체하지 않는다.
- 원작 `posts.caption`에서 해당 shortcode의 댓글 키워드를 읽는다. 승인된 우리
  대본의 ‘나도’ CTA를 원작 키워드로 사용하지 않는다. 모호한 복수 키워드·원작
  부재·조건 미확인은 화면에 사유를 표시하고 새 상품 확인을 시작하지 않는다.
- 원작이 명시적으로 ‘아무 댓글이나 남겨주세요’라고 안내한 경우에는 `all`로
  구분하고 허용된 요청 문구 ‘나도’를 사용한다. 이는 추출된 원작 키워드라고
  표시하지 않는다. 실제 브라우저의 전송 전 검사도 같은 조건을 확인한다.
- `run_saved`는 저장 계정과 현재 선택 영상의 원작을 서버에서 다시 읽는다.
  브라우저는 `/run`에 빈 JSON 객체만 보내며 계정·키워드를 수동 전달하지 않는다.
  상품 확인이 이미 끝난 작업은 원작 키워드 재입력을 요구하거나 재댓글하지 않는다.
- 페이지 조회·목록 새로고침·계정 저장만으로 외부 작업을 시작하지 않는다.
  계정은 기존 SQLite `configuration/automation` 설정을 사용하며, 자동 진행 여부를
  임의로 켜거나 기존 작업의 게시 계정을 변경하지 않는다.

추가 읽기 API는 `GET /api/monetization/inputs?task=…`다. 기존 실행 API의 `run`과
`product`는 서버가 입력을 결정한다. 기존 계정/레퍼런스별 시도 제한·예약 슬롯·
결과 불명확 시 재전송 금지·검수 파일 결속은 유지한다.

## 검증과 운영

관련 테스트 **106개 통과**. 저장 후 재접속의 계정 재사용, 빈 입력으로 실행,
원작 키워드와 우리 CTA 구분, 모든 댓글 조건, 불분명한 조건의 전송 차단,
완료 영상 자동 선택·명시 링크·계정 예약 우선·조회 상한과 브라우저 UI를 검증했다.
기존 수익화·완료 인계·게시·브라우저 대상 선택 회귀도 포함한다.

후속 전용 3235 서버에 적용했고 실제 리스너 PID **33532**에서 관련 모듈 10개의
로드 SHA를 확인했다. 실제 페이지의 JavaScript 오류는 0개이며 수동 작업 ID/
키워드/작업별 계정 입력은 0개, 공통 계정 입력은 1개다. 현재 완료 영상 25개를
읽고 그중 14개에서 키워드 또는 명시적인 모든 댓글 조건을 확인했다.

수익화 DB 전후 행과 SHA가 동일하고 `quick_check=ok`다. 메인 제작 서버·완료
영상·예약·사용자의 크롬을 재시작하거나 재개하지 않았다. 외부 댓글·DM·게시·
리틀리 생성 추가는 0건이다. 현재 실제 계정 값은 아직 저장되지 않았다.
