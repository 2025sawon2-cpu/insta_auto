## 이전 음성 기준과 현재 음성의 실제 차이

예전 감사 도구에는 거울 영상 VoiceBench **168번**이 비교 기준으로 남아 있다. 최초 분석에서는 승인 영상 식별을 미확정으로 두었으나, 이후 사용자가 **“승인영상은 거울영상이 맞다”**고 확인했다. 이제168번을 승인 기준으로 사용하며 당시 원음 SHA와 정확한 대본을 `data/approved-mirror-tone-20261016/approved-baseline.json`에 결속했다. 새 기본 음성이나 임의 감정 프리셋을 적용한 것은 아니다.

VoiceBench DB를 읽기전용으로 조회해 168·230(손난로)·231(패딩)의 실제 run을 비교했다. 세 요청 모두 ZONOS2 Q8의 같은 모델 revision·개인 참조 SHA·HQ·실제 선택 Seed13·T0.9/P0.95/minP0.05·단일 합성 정책이 일치했다. QA fallback이나 다른 화자로 바뀐 증거는 없다. Hotpost 저장 속도도 두 현재 영상 모두1이다.

| 기존 원음 | 길이 | 초당 한글 음절 | 낮은 에너지 구간 비율 |
|---|---:|---:|---:|
| 거울168 |20.364초|6.68|9.4%|
| 손난로230 |19.249초|6.86|7.7%|
| 패딩231 |17.788초|6.41|12.7%|

이는 원음의 상대 에너지 기준(95백분위 RMS보다35dB 낮은10ms 구간)과 문자 수를 이용한 측정이다. 단어 정렬된 말속도·사람의 청감 평가·감정 판정이 아니다. 손난로가 단순히 느려졌다는 설명은 이 수치로 지지되지 않는다. 손난로의 자기상관 추정 피치 상위 범위는 기준보다 좁았지만 음절 구성·추정 오차를 포함하므로 자연스러움의 점수로 사용하지 않는다.

확인한 구조적 이유:

1. Seed는 같은 입력의 난수 조건이다. 서로 다른 대본에서 동일 억양·감정·속도를 지정하는 값이 아니다.
2. 현 `zonos2_worker.generation_request`는 실제로 `emotion_enabled=False`, `speaking_rate_enabled=False`를 전송한다. 개인 참조는 ECAPA 화자 임베딩으로 들어가며, 승인 영상의 발화 리듬을 새 대본에 옮기는 운율 지침은 전달하지 않는다.
3. 대본의 문장 길이·쉼표·연결어·서술 종결이 달라졌다. 현재 패딩의 ‘집게 되네요 / 돌아서겠어요’나 손난로의 연속 상황 해설은 같은 샘플링 값에서도 다른 낭독 리듬을 유도할 수 있다. 이는 입력 구조에 대한 해석이며 청감 원인 하나로 확정하지 않는다.
4. 현 QA는 누락·반복·발음·파일 유효성을 검사하며 승인 톤과의 청감 일치를 검사하지 않는다. 설정 일치만으로 톤 일치를 선언한 기존 접근은 충분하지 않았다.

최초 분석 단계에서는 같은 대본·같은 값으로 무작정 재합성하지 않고 원인 분석까지 수행했다(TTS0회). 이후 사용자의 승인 영상 확인에 따라 별도 폴더에서 실제 음성 재제작을 진행한다. 거울의 제품 사실·독특한 문장을 옮기지 않고, 직접 말을 건네고 기능·실용적인 이득을 이어 설명하는 호흡을 원고에 적용한다. 각 제품3안과 선택 이유를 보존하고 전체 대본을 같은 개인 참조·시드·엔진으로 합성한다. `RULES.md`에도 대화 톤·과한 상황 해설과 예고 종결 축소를 반영했다. 실제 재제작 결과와 청감 승인 여부는 후속 영수증으로 구분한다.

## 거울 기준 확인 후 실제 재합성

이후 사용자 확정: **“아 앞으로도 그럼 그런느낌의 원고로 가자”**. 키티235 수정본의 상황 해설 축소·구체적인 제품 매력의 빠른 제시·동작과 쓰임을 이어 말하는 대화 호흡을 신규 원고의 기본으로 반영했다. 공통 집필 계약은 v8로 구분하며, 기존3안 규칙과 제품별 독립 설계는 유지한다. 원고 스타일 선호와 모든 음성의 청감 승인을 구분한다.

사용자가 거울 영상을 승인 기준으로 확정한 뒤, 각 제품의 말투3안·선택 이유와 실제 새 음성을 별도 `data/approved-mirror-tone-20261016/`에 만들었다. 기존 작업의 선택 대본·음성·영상은 교체하지 않았다.

| 새 요청 | 대상·버전 | 원음 길이 | 실제 생성 검사 |
|---|---|---:|---|
|235|손난로 대화 톤 수정|19.249초|전체1회·선택 Seed13·QA 통과·fallback 없음|

각 실제 run의 엔진 전체 설정·모델 revision·개인 참조 SHA·synthesis 정책이 승인168번과 일치한다. 원 대본의 제품 사실을 유지하면서 원고의 호흡을 수정했다. 음량·피치 이동·속도 보정·문장별 합성 덧붙이기는 하지 않았다. 따라서 이것은 TTS 파라미터를 바꿔 승인 운율을 강제 복제한 기능이 아니다.

첫 패딩 수정의 추정 피치 중앙값113Hz가 승인 원음132Hz보다 낮고 범위도 좁아, 같은 입력을 재추첨하지 않고 도입을 시청자 직접 질문으로 바꾸고 장점 재요약을 덜어 새 비교안을 만들었다. 두 번째는 중앙값129Hz로 가까워졌지만, 음절 구성·휴지 비율도 달라 청감 일치를 입증하지 않는다. 손난로 새 원음의 중앙값136Hz/상위 범위193Hz도 승인132Hz/200Hz에 가까우나, 원음의 음절/초는 승인보다 낮다. 수치가 가깝다는 이유로 톤 개선·속도 개선·사용자 승인을 선언하지 않았다. 완성 영상의 후처리 음성과 혼동하지 않도록 새 파일은 원음으로 제공한다.

확인 자료:

- `approved-baseline.json`: 사용자 확인과 거울168 원음 SHA.
- `scripts.json`: 두 제품의3안 및 원래 대본. `Dec8wlLhu9N-v2/method.json`: 추가 비교의 가설·변경 내용.
- 각 폴더 `submission.json`, `voice.json`, `narration.wav`: 실제 요청ID·대본 SHA·결과 SHA.
- `verification.json`: 첫 두 음성 검사. `verification-final.json`: 추가 비교까지 실제 run 설정·전체 WAV 디코드·QA·기존 원음 해시 보존 검사.
- `preservation.json`: 기존 손난로·패딩 원본 완성본·패딩 개선본 MP4 SHA 불변.
- 관련 회귀85개 통과(`regression.xml`). 신규 음성의 청감 승인은 아직 없으며 실제 승인 기준과 비교해 들을 수 있게 제공한다.

실행 중 첫 API 요청은 고유 생성 키가100자 제한을 넘어 HTTP400으로 거부됐고, 같은 대본의 접수 기록0건을 확인했다. 새 짧은 키로 수정한 뒤 정상 접수했다. 이 과정에서 HTTP 거절을 연결 불가로 잘못 표시하는 기존 adapter 오류도 수정했다. 이제 잘못된 키는 외부 요청 전에 검증하고, HTTP 거절은 응답 코드와 함께 구분한다. 실제 요청을 재등록하는 재시도 루프를 추가하지 않았다.
