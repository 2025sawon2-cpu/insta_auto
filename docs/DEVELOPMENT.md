# 개발과 지침 유지보수

## 코드 확인

- 요청한 결과와 완료 조건 안에서 작업한다. 실제 오류·필수 입력 부족·선택적 개선을 구분하고, 입력 부족이나 예상되는 미래 요구를 새 기능 개발로 자동 확대하지 않는다.
- 안내 보완 → 기존 기능 재사용 → 작은 수정 순으로 먼저 해결한다. 새 도구·설정·상태 체계는 명시적 요구나 실제 막힘 때문에 필요한 경우에만 추가하고, 필요한 검증과 완료 조건을 충족하면 멈춘다. 이 원칙을 위한 별도 체크리스트·보고서·승인 단계는 만들지 않는다.
- Python 설정은 `hotpost/config.py`의 Settings와 config.json/HOTPOST_* 우선순위를 확인한다. PC별 설정을 다른 PC에 덮어쓰지 않는다.
- `web/data.js`는 `hotpost/report.py`의 생성물이다. 데이터 계약 변경은 생성 코드와 화면을 함께 검토한다.
- API 변경은 해당 HTTP handler와 web 요청·표시·다운로드를 함께 확인한다. 게시용 서버가 제작실/큐/수집 실행기를 import하지 않는 회귀를 유지한다.
- Python은 지원 최소 3.10과 실제 환경을 고려한다. worktree에 venv가 없으면 원래 clone의 Python을 사용하되 cwd/PYTHONPATH는 수정 중인 worktree로 둔다. 운영 data/config를 테스트 fixture로 사용하지 않는다.
- 관련 검사: `python -m pytest -q tests/<관련 파일>`, JS는 `node --test tests/<관련 파일>.test.cjs`와 `node --check <변경 파일>`. 정적 확인은 `git diff --check`.
- 격리 테스트·소형 합성 fixture를 사용한다. 실제 외부 검색·모델·GPU·전체 영상 재제작을 일반 회귀 검사에 끼워 넣지 않는다.
- 입력 스냅샷·상태 잠금·짧은 재개 요약은 ABBYS 2026-10-24 배포본의 설계를 참고해 기존 Python 모듈에 구현했다. 외부 런타임·전역 훅 의존성은 없다. 입력 변경·저장 중 변경·오래된 쓰기·프로세스 충돌과 강제 종료를 작은 파일 fixture로 검사한다. 기계적 결속 검사는 실제 품질 판정이나 에이전트의 네이티브 실행 확인을 대신하지 않는다.

## 지침 구조

항상 읽는 AGENTS는 작업 진입점으로 두고, 현재 작업 경계는 WORKFLOW, 세부 규칙은 작업별 단일 원본으로 관리한다. 개별 영상 진행·일시적 PID/주소/완료 건수는 로컬 인계에 적는다. 날짜를 붙여 같은 규칙을 반복 추가하지 말고 현재 규칙을 직접 수정한다.

`python tools/check_guidance.py`는 현재 지침 파일의 존재·필수 원본·상대 링크·폐기된 지시의 재유입을 검사한다. CI도 같은 검사를 수행한다. 이 검사는 에이전트가 실제로 문서를 읽었는지나 의미를 완전히 보존했는지 증명하지 않으므로 변경 diff와 관련 계약 테스트를 함께 본다.

현재 Markdown 지침에는 바이트 상한을 두지 않는다. 필요한 규칙은 담당 원본에 온전히 유지하며, `docs/guidance.json`의 문서 목록은 크기 제한이 아닌 파일 존재와 상대 링크 검사 대상으로 사용한다.

새 숫자 제한·필수 절차를 추가할 때는 근거와 적용 범위를 담당 원본에 적는다. 사용자 명시 요구, 실제 API/코덱/모델 계약, 재현한 실패와 보호 목적을 구분한다. 구현에 숫자가 있다는 사실만으로 제품 품질의 근거가 되지는 않는다. 실험 기본값·특정 영상의 예외·일회성 회귀 표본 수를 모든 신규 영상의 합격 조건으로 승격하지 않는다. 권장값은 권장값으로 표시하고, 제한이 필요한 실제 입력·단계에만 적용한다.

날짜별 보고서와 보존된 제작실 설명은 당시 상태·구현 근거다. 현행 지침과 충돌하면 현행 담당 원본을 따르고 충돌을 기록한다. 과거 기록을 삭제하거나 과거 완료본의 합격을 현재 계약으로 소급하지 않는다. 문서 정정과 실행 코드 변경·현재 프로세스 적용·실제 영상 검증을 각각 보고한다.

재개 메모는 `local/SESSION.md`에 목적, 브랜치/기준 커밋, 읽은 원본 경로/SHA, 변경·검증, 다음 단계, 보류 사유, 내용 소실 동의 범위를 적는다. `local/`은 Git 제외이며 비밀값은 넣지 않는다. worktree의 로컬 인계가 없으면 원래 clone의 인계를 확인한다.

정리 전 AGENTS 원문은 `git show e470bd1:AGENTS.md`로 조회한다. 과거 지시·영상 ID·운영 관측은 이력으로 보존하며 현재 읽기 목록에서 제외했다. 현행 규칙의 이동 위치는 [정리 보고서](GUIDANCE_AUDIT_20261024.md)에 기록한다.

기존 제작실·사진 제작·수동 제품 실험은 저장된 작업 및 테스트가 참조하므로 미사용이라는 추측만으로 삭제하지 않는다. 삭제 후보는 진입점/호출자/저장된 계약/회귀 확인을 먼저 기록한다. 현재 개발은 독립 게시용 경로와 공통 계약에서 시작한다.
