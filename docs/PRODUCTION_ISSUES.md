- 저장된 실제 오류에 결속한 격리 검증에는 **실패 → 원인에 맞는 수정/입력 변화 → 짧은 재현 확인 → 정상 명시 재개 → 같은 작업의 후속 단계 수용 → 현재 최종 산출물/QA에 대한 완료 전환**을 포함한다. 내부 상태 전환·입력 결속 경계는 실제 함수를 연결하고, 외부 송신을 대체한 시험은 실제 새 영상 제작 성공과 구분한다.
- 재시작 후 같은 진행 위치 복원, 기존 산출물 재사용, 변경 영향에 따른 무효화, 중복 claim/외부 실행 방지, 오래된 QA/다른 run 결과의 완료 수용 거절, 사용자 중지·접근 보호 유지를 짧은 관련 검증에 포함한다.
- 향후 실제 제작이 별도로 허용되면 현재 영상의 중단 단계부터 최종 파일 생성과 현재 plan/export에 결속한 최종 QA까지 확인한다. 최종 완료 여부·소요 시간·같은 실패 반복·불필요한 재작업/모델 호출을 함께 기록한다. 해결 불가 시 원인·필요 조치·재개 조건을 남기되 보류를 완성으로 보고하지 않는다.

### 6. 첫 영상의 실제 차단 원인부터 최소 범위로 수정

1. 향후 실행 허용 시 현재 중지/입력/산출물과 첫 영상의 실제 차단 원인을 먼저 확인한다. Chrome 실제 backend·보존 프로필·로그인·접근 상태가 필수인 단계라면 그 준비를 선행하고 과거 Ego 오류를 현재 원인으로 가정하지 않는다.
2. 해당 차단의 필수 수정과 영상 전체 순차 제어·동일 실패 반복 차단·보류 후 해결/재개 연결을 우선 구현·짧게 검증한다. 부분 구현을 이유로 보호 없는 자동 제작을 먼저 시작하지 않는다.
3. 허용된 현재 영상의 해당 단계부터 제작을 이어 최종 QA까지 확인한다. 진행 중 문제/검색어는 기록하며 비치명 개선은 이후 별도 단계로 보낸다.
4. 기존 감사의 전달·상태·검색/장면 연결 결함은 현재 영상의 실제 차단과 관련된 것을 먼저 처리하고 나머지는 후순위로 둔다. 전체 감사 개선과 모든 과거 오류 수정을 첫 영상 제작의 선행조건으로 만들지 않는다. 미확정 정책은 결정 전까지 기존 기준을 유지한다.

현재 상태는 **여섯 보완점의 계획 반영 완료**다. 실행기 구현·격리 검증·운영 적용/로드·실제 영상 완성 검증은 모두 미실행이다.

## 2026-10-21 사용자 지정 작업 방식

### 한 영상을 최종 완료한 뒤 다음 영상 시작

사용자는 영상 동시 제작을 중단하고 한 영상을 최종영상까지 완결한 다음 다음 영상을 제작하도록 지정했다. 준비·대본·소스 검색/수집·음성·편집·최종 export·QA를 포함해 서로 다른 영상의 제작 단계를 겹치지 않는다. 다음 영상의 대본/수집만 미리 하는 것도 동시 제작에 포함된다. 후보 선정과 순서 있는 대기열 보관은 가능하지만 제작 시작과 구분한다.

다음 영상의 시작 조건은 현재 영상의 실제 최종 파일 생성과 현재 export/plan에 결속한 최종 QA 완료 확인이다. 대본/음성/초안 생성, 단일 job 종료, owner의 완료 주장만으로 전환하지 않는다. 영상별 기존 영속 담당자는 보존하며 현재 영상 담당자만 제작을 진행한다. 기록만을 위한 별도 감시 에이전트를 추가하지 않는다.

현재 영상이 실패/보류/접근 제한/사용자 중지이면 미완료다. 자동으로 다음 영상을 시작하지 않고 원인과 현재 상태를 기록 후 보류한다. 이를 이유로 끝없이 재시도하거나 모델 관측을 반복하지 않는다. 건너뛰기나 순서 변경에는 별도 사용자 지시가 필요하다. 따라서 이 규칙은 동시 실행 경합을 줄이지만 앞 영상의 장애가 뒷 영상을 막을 수 있다는 한계가 있다.

영상 제작 시도가 끝난 뒤 비치명 문제를 별도 수정하고 해당 오류만 짧게 재현 확인한다. 비용이 큰 전체 제작 회귀 시험은 다음 영상에서 한다. 현재 영상의 완성을 막는 오류는 짧은 확인 후 막힌 단계부터 이어 제작하고 현재 최종 파일의 QA까지 확인한다. 다음 영상이 별도 수정 경로를 거치지 않으면 그 회귀 검증은 미실행으로 남긴다. 치명적 실행 오류의 최소 수리 예외는 아래 기준을 유지한다.

실행기에는 선정/대기와 제작 입장을 분리하고, 자동 선정·명시 시작/재개·에이전트 후속 실행·worker claim에 같은 현재 영상 제어를 적용해야 한다. 상위 후보 수를1로 바꾸거나 각 worker lane만1개로 제한하는 것으로는 전체 영상의 순차 제작을 보장할 수 없다. 기존 사용자 중지와 자료를 보존하며 순차 규칙에 맞춰 전환해야 한다. 현재는 문서 반영 상태이며 실제 실행기 구현/로드·현재 작업 재개·다른 작업 강제 종료는 수행하지 않았다.

### 제작 중 치명적 실행 오류의 제한된 수리 예외

사용자가 확인한 취지는 ‘정말 제작이 불가능할 정도의 치명적인 문제만 제작 중 수정하고 나머지는 나중에 수정’이다. 필수 제작 단계가 실제 실행 오류로 막히고 기존 정상 경로로도 진행할 수 없는 경우에만 적용한다. 예를 들어 필수 렌더러의 재현 가능한 충돌이나 필수 파일 생성 코드의 오류가 이에 해당할 수 있다. 단순 지연·개선 여지·최적화·우회 가능한 비치명 오류를 치명적으로 승격하지 않는다.

오류 근거, 진행 불가 판단, 최소 수정 범위와 결과를 기록한다. 해당 오류의 짧은 재현 확인 후 원래 막힌 단계부터 이어갈 수 있으나 전체 제작을 처음부터 반복하는 시험으로 확대하지 않는다. 해결되지 않으면 해당 시도를 보류하고 별도 수정 목록으로 넘긴다. 같은 문제를 계속 진단·수리·재시도하는 루프로 돌아가지 않는다. 구체적인 시간·횟수 제한값은 아직 정하지 않았다.

로그인/CAPTCHA/429/403, 사용자 중지, 소스 부족이나 품질 미달은 이 코드 수리 예외로 우회하거나 기준을 낮출 사유가 아니다. 기존 오늘3 수집 중지는 유지한다. 이 예외는 아래 일반적인 제작/수리 분리 규칙에 우선하지만 실행기에 이미 구현·로드됐다는 뜻은 아니다.

### 일반적인 제작/수리 분리

제작과 코드 수리를 분리한다. 제작 중 발견한 문제는 여기에 근거와 함께 기록하고, 감시 에이전트를 붙여 동시에 코드를 수정·시험·배포하며 같은 영상을 계속 재시도하지 않는다. 제작을 시도한 다음 이 MD를 읽어 별도 수정 단계에서 처리한다. 사용자 추가 승인에 따라 수정 직후 해당 오류의 짧은 재현 확인은 수행하고, 비용이 큰 전체 제작 회귀 시험은 다음 영상 제작 시 수행한다. 현재 영상의 완성을 막는 오류는 상단 보완 계획에 따라 해당 단계부터 이어 최종 QA까지 확인한다. 기존 ‘문제를 만나면 제작과 동시에 수리하고 끝까지 재시도’ 지시보다 이번 지시가 우선한다.

짧은 재현 확인은 기록된 오류 조건과 수정 효과를 확인하는 범위로 한정한다. 확인한 조건·수정 버전·결과를 남기며 전체 검색·다운로드·TTS·렌더를 다시 수행하는 제작 시험으로 확대하지 않는다. 짧은 확인 통과와 실제 전체 제작 검증 통과를 구분한다. 이 승인으로 오늘3 수집을 재개하지 않는다.

이 문서는 작업 방식과 문제 기록이다. 실행기에 기록 전용 모드, 자동 종료 기준, 후속 검증 결속이 이미 구현·로드됐다는 뜻이 아니다. 현재는 최종 전체 사용자 중지를 유지하며, 앞선 다른 작업 유지/자연 유휴 지시는 과거 이력이다. 이번 문서 변경으로 제작 재개·접근 제한 우회·품질 기준 완화를 승인하지 않는다.

## 평가 및 구현 전 정할 사항 — 권고, 아직 사용자 확정 아님

이 절의 미확정 사항과 별개로, 아래 ‘무진전 복구 종료 수정 계획’의 보류 유지·재호출 방지·검증 기준은 사용자 요청으로 수정 계획에 반영했다. 구체적인 단계별 시간/횟수 값은 여전히 미확정이다.

- 제작 시도 종료는 완성뿐 아니라 진행을 막는 문제를 기록하고 보류하는 경우도 포함해야 한다. ‘영상 완성 후에만 수리’라고 하면 완성을 막는 오류에서 순환 대기가 생긴다.
- 무진전 대기와 동일 원인 재시도에는 종료 기준이 필요하다. 단계별 실제 파일/작업 진전과 정상 서비스 대기를 구분하며, 제한값은 아직 정하지 않았다. 기록 모드만 추가해도 기존 대기 루프가 자동으로 해결되는 것은 아니다.
- 수정 직후 짧은 오류 재현 확인과 다음 영상의 전체 제작 시험 분리는 사용자 승인으로 위 확정 규칙에 반영했다. 광범위한 추가 테스트까지 승인된 것으로 확대하지 않는다.
- 다음 영상이 수정한 경로를 실제로 지나지 않으면 검증은 미실행이다. 오류가 없었다는 이유만으로 해결됨으로 닫지 않는다. 수정 코드 버전·재현 조건·검증 결과를 연결한다.
- 최종 영상 품질 검토와 로그인/CAPTCHA/403/429 중지는 코드 수리 시험과 별개로 유지한다.

## 무진전 복구 종료 수정 계획 및 통과 기준

### 바꿀 대상

P-005의 기존 보호 장치는 중복 조회·동일 변경을 거절하지만 이후 recovering/next_at으로 에이전트를 다시 판단시킨다. 새 반복 제한을 덧붙이거나 진단 제한을 없애는 대신, 실제 진전 없이 막힌 제작 시도를 기록 후 영속 보류하는 상태 전환과 재진입 제어를 구현한다. 한 편씩 제작하는 제어와 별개로 필요한 변경이다.

### 보류 및 재개 동작

1. 작업/run/job, 사용자 명령 세대, 관련 실제 코드/입력 지문, 마지막 실제 진전, 원 오류·거절·중단 근거를 묶어 기록한다. 로그 시각·heartbeat·조회 메모·판단 호출 자체를 새 제작 진전으로 세지 않는다.
2. 무진전 보류를 재실행 가능한 recovering 및 next_at 재예약과 구분해 영속 저장한다. 실제 사용자 중지와 정상 서비스 대기·유효한 작업 진전도 별도로 유지한다. 모든 오류를 무조건 즉시 보류하는 일반 오류 처리로 확대하지 않는다.
3. 같은 조건의 보류 작업에 manager tick, 시간이 지남, 기존 blocked_observation 복구, 프로세스 시작/동기화가 다시 모델 판단·수집 claim을 허용하지 않도록 연결 경계를 확인한다. 보류 중 자동 원job 재시도를 남겨 모델 호출만 줄인 것으로 완료 처리하지 않는다.
4. 보류 해제는 별도 명시 재개 조치로 처리하고 현재 입력·수정 근거를 다시 확인한다. 담당자는 상단 보완 계획에 따라 해결 조치·검증·재개 연결을 책임지고 보류를 방치하지 않는다. 상태 이름 변경·원래 로그 시각 갱신만으로 자동 해제하지 않는다. 사용자 중지나 로그인/CAPTCHA/429/403·소스/품질 보호는 이 재개 경로로 우회하지 않는다. 자료·기존 owner·실패 이력은 보존한다.
5. 보류된 영상을 최종 완료로 세거나 다음 영상을 자동 시작하지 않는다. 수정 후 짧은 오류 재현 확인과 실제 제작 성공은 별도로 기록한다.

### 짧은 재현 확인의 필수 통과 기준

- 수정 전에는 저장된 실제 오류 조건에 결속한 격리 재현에서 ‘조회/수정 거절 → recovering → 다음 판단 예약’이 발생함을 확인한다.
