# 현재 소스 검색·검토 규칙

검색은 명시 승인된 현재 작업에만 실행한다. 과거 진행 이력은 재개 허가가 아니다.

## 브라우저와 접근

- Chrome의 현재 로그인된 동일 프로필·창·세션을 사용한다. 그 창에 새 탭 추가는 가능하며 target/window·플랫폼·검색어·시각을 기록한다. 별도 프로필·새 창·계정·Ego로 대체하거나 사용자 창을 종료/재시작하지 않는다. 다운로더도 같은 세션을 사용하며 쿠키 파일 존재만으로 로그인을 추정하지 않는다.
- TikTok·YouTube·Douyin 탭을 다운로드 사이트로 이동시켜 재사용하지 않는다. 같은 플랫폼 탭 **안에서는** 검색어를 바꾸고 영상을 열어 검토한 뒤 뒤로가기로 검색 결과에 돌아와도 된다. 검색어·후보마다 새 탭을 만들거나 모든 검색 결과·검토 완료 원문 탭을 보존할 필요는 없다. 플랫폼별 작업 탭과 사용자가 직접 연 탭, 현재 검토에 필요한 원문은 유지하고 불필요한 중복 탭은 정리한다. 다운로드 사이트는 같은 로그인 Chrome 창의 **별도 새 탭**에서 열고 수신을 확인한 뒤 그 다운로드 탭은 닫아도 된다. 탭을 정리해도 실제 검색·후보 URL·구간·판정 기록은 보존한다.
- 현재 CAPTCHA·로그인·403·429·DRM을 우회하지 않는다. 과거 CAPTCHA 기록은 현재 화면을 다시 관찰하고 근거를 보존해 판단한다. 캡처/판정 실패는 미확인이며 CAPTCHA 확정으로 기록하지 않는다. 실제 인증창 의심은 [이미지 검토 계약](CAPTCHA_SCREENSHOT_REVIEW_20261019.md)을 따른다. 인증 자동 해결·시간 경과만으로 차단 해제는 금지다.
- TikTok 검색/상세 열기는 합산 최소 30초 직렬 간격, 기타 플랫폼 검색 시작은 기본 10초, 명시 외부 요청/다운로드/재시도는 `request_pacing.py`의 1~3초를 적용한다. 계정 간 4~9초·Retry-After·오류 휴식은 보존한다. 로컬 DB/파일/서비스 상태 조회에는 불필요한 대기를 넣지 않는다.
- Douyin도 기존 로그인 Chrome에서 근거 있는 중국어 검색을 사용한다. TikTok MP4 수신 실패 시 승인된 `tikvideo.app/ko`, Bilibili는 `snapany.com/ko/bilibili`의 보이는 UI 경로가 가능하다. 이는 접근 차단 우회나 앱·확장 설치·숨은 API 승인이 아니다.
- Bilibili는 표시된 검색 카드 링크만 후보로 센다. 검색 제한 안내는 `query_restricted`이며 CAPTCHA/플랫폼 전체 차단과 구분한다.

## 검색어와 근거

- 단일 기록 원본은 [SOURCE_SEARCH_LOG.md](SOURCE_SEARCH_LOG.md)다. 생성·선정·실제 제출, 발견·다운로드·채택·최종 사용을 각각 구분한다. 원문·언어·플랫폼·목적·제출 시각·결과/중단 사유·증거를 task/run에 결속한다. 재시도는 별도 시도이며 고유 검색어 수를 늘리지 않는다.
- 원작 본문·실제 음성·화면 글자·프레임으로 제품/용도/상황 검색 가설을 만든다. DM·정확 SKU 완전성을 탐색의 필수 입력으로 강제하지 않는다.
- **검색 전에 화면 목표를 적는다.** 원작에서 실제 보이는 대상·재료의 형태·사용 동작·상태 변화와 선택 대본이 주장하는 내용을 분리하고, 필요한 컷을 `도입 상황 / 핵심 사용 동작 / 결과 / 보조 맥락`처럼 영상별로 정한다. 각 컷에 원작 근거, 검색할 장면, 최종 편집 역할, 확인되지 않은 점을 남긴다. 원작의 모든 부수 장면을 대본의 핵심으로 승격하지 않는다.
- **제품·정체성과 화면·동작, 두 경로를 모두 실제 검색한다.** 제품 경로는 원작에서 확인한 브랜드·모델이 있으면 그 이름과 제품 종류를 찾는다. 이름이 불명확하면 확인된 제품 종류를 찾고, 원작에 연결된 상품명이 있으면 각 상품을 `미확인 후보`로 따로 검색한다. 연결 상품 검색을 생략하거나 그중 하나를 원작 제품으로 확정하지 않는다. 화면 경로는 사용 전 상태·제품/도구의 형태·핵심 사용 동작·사용 후 상태처럼 서로 다른 실제 장면을 찾는다. 어느 한 경로의 후보가 부족해도 다른 경로의 실제 검색을 생략하지 않는다.
- 두 경로에 서로 다른 검색어를 선정·제출하고 실제 결과를 각각 기록한다. 한 검색어를 두 경로의 실적으로 중복 계산하지 않는다. 접근 제한 등으로 제출하지 못한 경로는 완료로 표시하지 않는다. 기존 영어 5개·중국어 5개의 전체 최소 실적은 그대로 유지하고, 경로별 임의의 새 숫자 기준은 만들지 않는다. 제품 경로에서 찾은 후보도 실제 장면이 맞는지 확인하며, 화면 경로에서 찾은 후보도 확인된 제품 종류·형태·기능과 맞아야 핵심으로 센다.
- 주요 대상+한 관점의 자연스러운 현지어 표현, 보통 1~4단어·최대 10공백단어다. 모든 부가 특징을 검색어마다 강제하지 않는다. 초과분을 임의 절단하지 말고 다시 선정한다. 동의어·어순·공백만 바꿔 개수를 채우지 않는다.
- `subject_identity_supported`와 실제 주장한 정체성의 literal/visual provenance는 유지한다. `core_identity_complete`, `known_subject_identity_complete`는 진단이며 false만으로 근거 있는 주제 탐색을 차단하지 않는다. OCR 불일치는 유효한 원본 프레임·실제 관찰·독립 검토에 결속한 시각 근거로 명시하고 원문을 고치지 않는다.
- 모델/OpenCLIP 추론·검색 가설·후보 제목을 확정 제품 사실이나 미디어 승인으로 승격하지 않는다. 실제 영상에서 제품·동작·관련성을 검토한다. 브랜드가 같다는 이유만으로 같은 제품으로 세지 않는다.

## 확보·편집 가능 판정

- 신규 기본은 정책 v6다. 실제 영어 5개+중국어 5개의 서로 다른 근거 있는 검색, 관련 원본 합계 최소 5개 및 본문 실제 원본 최소 5개, 핵심 제품 서로 다른 원본 5개 확보/활용 우선이다. 파생 파일·같은 부모·표지 전용 사용·미검토 파일은 중복 산입하지 않는다. [v6 원본](CORE_PRODUCT_PRIORITY_IMPLEMENTATION_20261019.md)을 읽는다.
- **후보는 영상 전체 제목이 아닌 실제 사용 가능한 시간 구간으로 판정한다.** 같은 원본 안에서 핵심 동작과 결과가 이어지는 영상은 먼저 검토하되 모든 원본에 완전한 전 과정을 요구하지 않는다. 구간별로 핵심 시연·관련 장면·맥락·제외를 구분하고, 실제 재료/제형·동작·대본 주장과의 일치 및 부모 원본을 확인한다. 비슷한 제목·썸네일·검색어는 판정 근거가 아니다.
- 결과나 전후 효과를 보여줄 때는 같은 대상의 변화인지, 중간에 다른 처리나 조작이 있었는지 검토한다. 서로 다른 원본의 전후를 하나의 효과처럼 연결하거나, 다른 제품·제형·반대 동작의 결과를 현재 제품의 효과처럼 제시하지 않는다. 모순되는 장면이 들어 있는 영상도 독립된 사용 전 상태 등 무해한 구간은 별도 검토할 수 있지만, 그 구간을 핵심 효과 증거로 세지 않는다. 문장마다 정확히 같은 동작을 맞출 필요는 없으며 완성본의 전체 의미와 흐름을 함께 본다.
- 첫 검색 묶음에서 핵심으로 쓸 구간이 없으면 실제 결과와 제외 사유를 보고 화면 목표·검색 관점을 수정한다. 이전 검색과 후보를 보존하고 생성·제출·다운로드·채택 수를 새 계획의 실적으로 합치지 않는다. 유효한 새 관점 없이 브랜드명·동의어만 바꿔 같은 실패를 반복하지 않는다.
- v6의 독립 검토 핵심 탐색과 접근 가능한 미사용 범위를 소진한 부족 근거가 있어야 보조 전환한다. CAPTCHA·서비스 대기·미검토 수신은 부족 증명이 아니다. 승인된 자연어 주제 탐색과 보조 검색을 구분하며 보조 검색을 핵심 실적으로 세지 않는다.
- 현재 영상에 대한 명시 예외는 범위·근거와 함께 그 run에만 적용한다. 과거 세 소스 예외를 일반 최소치로 만들지 않는다. 저장된 v1~v5 run은 당시 계약으로 보존하며 읽기·재시작만으로 이전하지 않는다. 오래된 v3의 음성 길이 1.25배/핵심4초나 v4의 단일 소스 준비 규칙을 신규 v6 기준 대신 적용하지 않는다.
- 360×640 미만·종횡비2 초과는 경고/검토 우선순위다. 점수만으로 탈락시키지 않는다. 실제 1080×1920 크롭의 화질·동작 보존·마스크·승인 구간을 확인한 분량만 편집 가능량으로 센다.
- 원본·사용자 촬영 자료·이력은 보존한다. 다운로드 성공은 재사용 허가가 아니며 출처·권리 상태를 남긴다. 기준 Instagram 릴스는 분석용이며 소스 ZIP에 넣지 않는다.

품질·진전·완료는 [WORKFLOW.md](WORKFLOW.md)를 함께 따른다. 옛 정책과 영수증은 역사이며 새 실행 명령이 아니다.
