# 모바일 업로드 간단한 시작 안내

스킬명을 몰라도 이 저장소를 연 Codex에 평소 말로 요청하면 된다.

- 처음 연결: **“기존 설정부터 확인하고 인스타 업로드 초기 연결만 해줘.”**
- 게시 전 준비: **“이 영상 업로드 준비해줘. 아직 게시하지 마.”**
- 실제 업로드: **“이 영상 리틀리부터 업로드랑 고정댓글까지 진행해줘.”**

## 기존 설정부터 확인

에이전트가 저장된 계정·스토어·등록 폰·현재 완성 영상과 초안부터 확인한다. 이미 있는 설정과 프로젝트를 재사용하며, 새 등록이나 반복 입력을 기본 절차로 만들지 않는다.

기존 Chrome의 탭에 실제 접근한 뒤 Instagram(상품 확인용), 리틀리 DM 자동화(게시용 Instagram 연결), 쿠팡 인플루언서 ‘내 스토어’를 확인한다. 빠진 서비스만 열어 로그인해 달라고 요청한다. 폰의 Instagram·Edits 게시 계정도 확인하며, 사용자에게는 직접 로그인·2단계 인증·폰에서만 가능한 잠금 해제/연결 승인만 요청한다. 비밀번호나 인증 코드는 채팅으로 받지 않는다.

폰 연결은 [휴대폰 연결 가이드](PHONE_SETUP.md)를 따른다. 새 Wi-Fi에서는 기존 VPN IP·페어링을 유지하고 현재 연결 포트부터 확인한다. 준비된 영상이 없으면 그 사실을 알리며 영상 제작이나 PC 간 이전을 자동 시작하지 않는다. 초기 연결만 요청했다면 게시하지 않는다.

## 핵심 흐름

**기존 설정·작업 확인 → 상품/우리 원링크 검증 → 리틀리 저장 확인 → Edits 음악 선택·70% → Instagram 게시 → 본인 댓글 작성·길게 눌러 고정 → 실제 게시물과 리틀리 연결 확인**

같은 자동화·초안·댓글이 있으면 재사용한다. 공유는 한 번만 실행하며 결과가 불명확하면 재공유하지 않고 실제 게시물부터 확인한다. 댓글 고정은 목록을 다시 열어 핀 표시까지 확인한다. 실제 이용자 댓글→DM 전달 여부는 업로드·고정댓글 완료와 구분한다.

세부 실행과 재개는 [모바일 업로드 워크플로우](MOBILE_REELS_WIREGUARD.md)가 원본이다.

## 설치가 없을 때만

기존 Python 환경과 도구가 없을 때 에이전트가 `requirements-publication.txt`로 업로드에 필요한 의존성을 준비하고 FFmpeg·FFprobe 실행을 확인한다. 완성본 업로드 때문에 음성 모델·GPU·편집기를 설치하지 않는다. 스킬이 없으면 저장소의 `skills/hotpost-mobile-upload`를 현재 호스트의 스킬 경로에 설치한다. Chrome 제어 연결이나 VPN이 없다면 그 누락만 먼저 해결하고 연결 성공을 확인한다. 매 업로드마다 재설치·VPN 서버 구축을 수행하지 않는다.
