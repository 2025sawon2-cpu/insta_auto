- 상태: **시스템 점검·설계 계획. 구현·운영 적용·새 영상 완성 보고가 아니다.**
- 목적: 원작의 중심 대상과 구매 매력을 먼저 찾고, 부족한 장면만 유사 소스로 보완하는 원칙을 전 과정에서 일관되게 적용한다.

## 0. 새 세션 시작 지침 — ‘최신 MD 파일 읽고 수행해’의 실행 범위

사용자가 새 세션에서 **‘최신 MD 파일 읽고 수행해’**라고 요청하면, 이 문서를 현재 이어받기 기준으로 읽고 아래 작업을 진행한다. 작업 폴더는 `C:/Codex/인스타자동화/insta_auto`다. 새 세션 하나에서 통합 수행하며, 사용자에게 세 세션을 열거나 세 개의 지시문을 다시 전달하도록 요구하지 않는다.

1. `AGENTS.md`, `docs/CODE_MAP.md`, 본 문서 전체와 9절의 기존 source/editorial/global 감사 자료를 먼저 읽는다. 과거 제작 인계 문서의 ‘실패 영상 이어 만들기’보다 현재의 **시스템 검수 단계**를 우선한다. 수정 시각만 최신인 다른 MD를 임의로 현재 작업 지시로 선택하지 않는다.
2. 기존 조사 결과를 재사용하고, 아직 확인하지 못한 경계·충돌·누락을 실제 코드·프롬프트·설정·기존 테스트와 대조한다. 이미 확인한 조사를 처음부터 반복하거나 계획을 요약하는 것만으로 끝내지 않는다.
3. 원작 중심 대상부터 찾고 부족한 장면만 유사 영상으로 보완한다는 원칙으로, **초기 소재 분석 → 레퍼런스 분석·다운로드 → 소스 탐색·채택 → 대본 → 편집 → 최종 QA → 썸네일 이미지·문구** 전 과정을 연결해 검수한다. 별도 `auto_capcut` 소비 경계도 해당 저장소 지침을 읽고 확인한다.
4. 확인된 충돌과 추정 위험을 구분하고, 조건마다 **근거 코드 위치·영향·유지/변경 범위·최소 수정안·수정 순서·검증 방법**을 하나의 통합 결과로 정리한다. 새 게이트·점수·예외를 덧붙이기보다 중복·과조건을 줄인다. 2.3절의 기존 명시 수량과 표지 범위 규칙을 임의로 폐기하지 않는다.
5. 8절에 따라 향수·불꽃에서 무엇을 고정하고 어떤 실제 결과로 효과를 판단할지 구체화한다. 저장 자료 기반 검증, 향후 실제 수집, 실제 완성 영상 비교를 구분한다. 실행하지 않은 시험·영상 비교를 성공한 것으로 쓰지 않는다.
6. 검수 결과와 남은 정책 결정, 최소 수정 순서, 다음에 할 작업을 본 문서 말미에 날짜가 있는 ‘통합 검수 결과·다음 작업’ 절로 기록한다. 기존 근거·실패·검토 이력은 보존하며, 검수가 끝나면 완료 범위와 남은 사항을 간결히 보고한다.

**이번에 수행할 일은 검수와 통합 수정안 정리까지다.** 프로그램 코드·운영 설정·DB를 적용/변경하거나 실제 검색·다운로드·TTS·렌더·제작 재개를 실행하지 않는다. 이 문서를 읽으라는 명령을 뒤 단계 구현·운영 반영의 자동 승인으로 해석하지 않는다. 작업 트리의 기존 변경과 중간 자료를 보존한다.

상단 운영 조치와 기존 감사 영수증은 작성 당시의 관측이다. 현재 상태가 필요하면 읽기 전용으로 확인하고 과거 상태를 현재로 단정하지 않는다. 삭제한 사용자 대상 자동화 메시지·heartbeat를 다시 만들지 않는다. 이후 사용자가 작업 범위를 새로 지시하면 그 지시와 실제 진행 상태를 이 절에 갱신한다.

**이어받기 진행 상태 — 2026-10-21:** 0절의 정적 통합 검수와 수정안 정리를 수행했다. 결과·기존 감사의 정정·검증 설계·남은 결정은 **10절**에 있다. 다음 세션은 기존 세 감사 자료를 처음부터 다시 조사하지 말고 10절부터 읽는다. 프로그램 구현·격리 회귀·운영 반영·제작 재개는 수행하지 않았으며, 이 상태 기록이 그 작업의 승인을 뜻하지 않는다.

## 1. 이번에 확정한 방향

### 1.1 영상의 목표

단순한 제품 사양 리뷰를 만드는 것이 아니라, **원작의 중심 대상과 핵심 매력이 사람에게 왜 좋고 즐거운지 후킹하여 제품에 관심을 갖게 하는 영상**을 만든다. 제품의 특징과 사용 모습, 사용자의 경험·반응을 함께 활용한다.

‘제품은 중요하지 않으니 아무 관련 장면을 모은다’로 해석하지 않는다. ‘특정 제품을 정확히 보여주는 컷만 모두 모아야 한다’로도 해석하지 않는다.

### 1.2 검색·선택의 우선순위

1. 원작에서 특정 가능한 중심 인물·제품·사용 상황과 핵심 매력을 직접 보여주는 장면을 우선 찾는다.
2. 같은 인물·제품의 다른 실제 사용·선호 발언·즐기는 모습을 찾는다.
3. 실제로 검토한 소스에서 필요한 장면이 부족하면, **부족한 그 장면**을 최대한 유사한 대상·사용 방식·효과·경험으로 보완한다.
4. 일반적인 반응·생활·파티 분위기는 해당 대목을 지원하는 보조 장면으로 쓴다.

이 순서는 우선순위다. 모든 장면에 똑같은 인물·모델·색·형태를 강제하는 일괄 탈락 조건이 아니다. 반대로 수량이 많거나 다운로드가 쉬운 범용 장면이 중심 대상 장면을 먼저 밀어내게 하지 않는다.

### 1.3 완화해도 유지하는 구분

- **중심 대상:** 누구·무엇을 우선 소개하는가.
- **핵심 매력:** 시청자가 왜 이것을 원하게 되는가.
- **구체적 주장:** 특정 인물의 추천, 특정 제품의 기능·성능·안전성처럼 대상과의 연결 근거가 필요한 말.
- **장면의 쓰임:** 직접 시연인지, 사용·즐김인지, 분위기·반응을 지원하는지.

유사 제품은 관련 경험과 분위기를 보완할 수 있다. 그 영상으로 원래 제품의 미확인 성능이나 특정인의 실제 추천을 입증하지 않는다. 같은 제품 영상도 보여주지 않은 기능까지 입증하지 않는다.

## 2. 검수 방식: 규칙을 더 쌓지 않고 연결을 정리한다

### 2.1 조건마다 한 번만 결정할 것

각 조건을 다음 네 가지 중 하나로 정리한다.

| 구분 | 사용 방식 | 예시 |
|---|---|---|
| 필수 유지 | 실제 오류·오해·파일 불일치를 막는 범위에 적용 | 실제 파일 존재·재생, 승인 구간 일치, 잘못된 인물 추천 연결 방지 |
| 우선순위 | 좋은 후보를 먼저 찾고 고르는 기준 | 중심 인물·제품, 원작의 핵심 사용, 같은 대상의 즐기는 모습 |
| 해당 주장에만 적용 | 그 주장을 실제로 하는 대목만 검증 | 버튼 조작의 직접 시연, 특정 제품의 안전성·성능 |
| 진단·권장 | 정보를 남기되 단독으로 제작을 차단하지 않음 | 모델명 미확인, 제품 정보 완전성, 보유 원본 수의 선호 목표 |

같은 조건이 검색에서는 권장인데 최종 검수에서는 필수로 되살아나는지 확인한다. 해상도·유사도·키워드 점수·장면 길이도 문서에 적힌 성격과 실제 분기 처리가 같은지 확인한다.

### 2.2 추적할 연결

**조건을 만드는 곳 → 저장·전달하는 곳 → 후보를 거르는 곳 → 완료를 결정하는 곳 → 실패 복구에서 다시 사용하는 곳**을 한 줄로 추적한다. 프롬프트 한 곳의 수정만으로 개선 완료라고 하지 않는다.

기존 기획·레퍼런스·대본·소스 검토 자료를 재사용한다. 기획 요약에 중심 대상, 핵심 매력, 구체적 주장, 필요한 장면을 유지하는 최소 보완을 우선한다. 새 분류기·점수 체계·단계별 승인 에이전트를 추가하는 것을 기본 해법으로 삼지 않는다.

### 2.3 기존 명시 수량의 처리

| 기존 조건 | 이번 계획의 처리 |
|---|---|
| 언어 무관 검색어 최대 10공백단어 | 유지. 짧고 자연스러운 표현을 우선하며 10단어를 채우지 않는다. |
| 원작 대상·제품을 먼저 찾기 | 유지·강화. 검색과 편집 선택 모두에서 우선한다. |
| 동일 제품 핵심 원본 5개 목표·core≥1·탐색 소진 조건 | 현재도 5개 미만을 허용하는 전역 fallback은 있다. 다만 이를 장면별 부족 보완에도 묶는 범위가 최신 원칙과 충돌한다. 같은 대상 우선 목표는 유지하면서 전환 조건을 정렬하고, core0의 일괄 전환 금지도 함께 재검토한다. |
| 영어5·중국어5 실제 검색 | 과거 사용자 명시 기준이다. **이번 문서만으로 폐기하지 않는다.** 완료 차단 조건을 탐색 지표로 바꿀지는 정책 결정 항목으로 분리한다. 결정 전후의 집계·완료 처리를 명시해야 한다. |
| 관련 원본 최소5 확보·본문에도 실제5개 사용 | 과거 사용자 명시 기준이므로 유지 대상으로 둔다. 같은 제품5개와 혼동하지 않는다. 개수 때문에 무관한 컷을 넣지 않는다. |
| 같은 원본 재사용·정상 속도 연장 | 유지. 실제 검토한 구간 안에서 자연스러운 흐름을 평가한다. |

숫자를 줄여 통과시키거나 과거 검색·승인을 지워 새 기준을 만족시킨 것으로 만들지 않는다. 옛 영어 검색이 실제 존재하지만 새 자연어 의도 집계에는 포함되지 않는 경우, **역사적 실제 실행과 새 기준 충족을 따로 표시**한다.

## 4. 8개 단계별 검수 조건

### 4.1 영상 소스 분석 — 제작 소재·게시물의 초기 분석

여기서 ‘영상 소스 분석’은 검색 후 후보 검토와 구분하여, 제작 소재로 들어온 게시물·원문·메타데이터의 초기 분석을 뜻한다.

- 입력: 원작 URL, 게시물 본문, 알려진 인물·제품 단서, 실제 게시 유형.
- 확인: 제목·짧은 작업명·배경 로고를 중심 대상으로 단정하지 않는가. 검색 가설과 확인된 사실을 따로 유지하는가.
- 우선순위: ‘연예인 향수’에서 한소희가 특정되면 한소희의 향수 사용·취향 발언부터 찾도록 전달되는가.
- 충돌 검수: 광고 본문의 제품 사양을 전부 필수 조건으로 만들거나 DM 상품명이 나올 때까지 초기 탐색을 막지 않는가.
- 통과 사례: 인물은 확인되고 향수 모델은 불명이어도, 그 인물의 향수 관련 영상을 우선 탐색할 기획이 만들어진다.
- 유지: 현재 비활성인 사진·캐러셀 제작을 자동 재활성화하지 않는다. 수집·분석 대상과 제작 허용 대상을 구별한다.

### 4.2 레퍼런스 영상 분석 및 다운로드

- 입력: 실제 원작 미디어와 본문. 음성, 화면 글자, 이미지 관찰을 구분한다.
- 확인: 실제 재생·디코드되는 원작인지, 주제·중심 대상·핵심 매력·사용자 경험을 전체 맥락으로 분석하는지.
- 전사 확보만으로 전체 분석을 완료 처리하지 않는다. 긴 음성·배경 가사·무음·화면 문구만 있는 입력에서 실제 주제 분석이 어디까지 이뤄지는지 확인한다.
- 충돌 검수: 이미지에 특정 병이 없다는 이유로 향수 취향이라는 주제까지 미확인으로 만들지 않는가. OCR 오탈자와 실제 픽셀 읽기를 구별하는가.
- 주장 범위: ‘안 뜨거워 위험하지 않다’ 같은 원작 표현을 원작의 주장으로 기록하고 확인된 제품 사실과 혼동하지 않는다. 검증되지 않은 절대 표현만 다루며 일반 기능·매력까지 일괄 보류하지 않는다.
- 표지 관찰: 원작의 영상 첫 프레임·도입 문구와 실제 피드 썸네일을 혼동하지 않는다.
- 통과 사례: 원작의 매력과 인물·제품 우선순위를 보존하면서, 확인하지 못한 SKU·온도·안전성은 사실로 추가하지 않는다.
- 유지: 부분 다운로드를 완성 파일로 수용하지 않음, 원본 SHA·출처·재생 검사, 실제 접근 중지 준수.

### 4.3 소스 영상 분석 — 검색·수집·후보 채택

- 같은 인물·제품·원작 핵심 사용/경험을 먼저 실제로 찾았는지 확인한다. 쉬운 범용 소스가 많다는 이유로 이 순서를 건너뛰지 않는다.
- 검색어는 주요 대상+관점 하나의 자연어로 만든다. 인물·브랜드·제품·용도·경험 등 서로 다른 접근을 쓰되 모든 특징을 한 검색어에 강제하지 않는다.
- ‘후기·사용법·review’ 같은 자연스러운 관점어가 옛 공급자 문법 규칙 때문에 삭제되거나 승인과 실제 전송 사이에서 달라지지 않는지 확인한다. 화면 근거로 승인한 검색 가설을 텍스트에 없다는 이유만으로 재차단하지 않는다.
- 채택은 실제 장면과 쓰임으로 판단한다. 제품 일치 여부, 직접 시연 가능 범위, 경험·분위기 기여를 한 불리언으로 뭉치지 않는다.
- 부족 판단은 ‘필요한 장면/분량이 없음’이다. 접근 차단·모델 대기·미검토 수신을 대상 소진의 증거로 쓰지 않는다. 모든 플랫폼·모든 특징 변형을 소진해야만 유사 장면으로 넘어가는 일괄 조건도 두지 않는다.
- 유사 장면을 쓰면 어떤 부족을 메우는지 짧게 기록한다. 특정인의 추천·특정 제품 성능을 대신 입증하는 사용은 하지 않는다.
- 수집 종료·다음 단계 전환에서 제품 수·검색 수·원본 수의 정책을 섞지 않는지 확인한다. 기존 명시 수량의 변경은 2.3절 결정 항목과 일치해야 한다.
- 통과 사례: 불꽃 분사기 정확한 사용 장면을 우선 보존하고, 함께 즐기는 모습만 부족하면 유사 분사기의 축하 장면을 보완한다. 프린터는 주제와 무관하므로 제외한다.
- 유지: 생성 검색어와 실제 제출 분리, 실제 미디어 검토, 중복 부모 원본 구분, 현재 접근·pacing·중지, 출처·권리 상태 기록.

### 4.4 대본 제작

- 원작의 중심 대상·핵심 매력·구매 동기를 유지한다. 단순 설명 목록으로 만들지 않고 사용 가치와 경험을 후킹에 연결한다.
- 기존 3안·심리 메커니즘 재설계·구어체·CTA ‘나도’·승인 음성 연결을 유지한다. 소스 개수 때문에 대본 평가 순위를 바꾸거나 중심 대상을 범용 주제로 자동 희석하지 않는다.
- 인물·상황을 창작하는 규칙과 실제 특정 연예인의 발언·추천을 바꾸는 행위를 구별한다. 특정 인물에 귀속한 사실은 다른 사람의 사실로 치환하지 않는다.
- 촬영 연출 제안과 원작 사실을 구별한다. ‘손잡이를 가까이 담기’, ‘꽃다발 다음 컷’ 같은 제안이 모든 후보의 필수 조건으로 내려가지 않게 한다.
- 제품의 모든 성분·구조·형태를 설명해야 한다는 검사와, 모든 문장을 실제 컷으로 재연해야 한다는 검사를 두지 않는다.
- 통과 사례: 향수 취향·사용·즐김의 매력을 유지한 3안을 작성한다. 확인하지 못한 향수병을 ‘한소희가 쓴 바로 그 제품’이라고 추가하지 않는다.
- 출력 정합성: 선택 대본의 실제 내용·버전과 편집에서 요구하는 구체적 주장이 일치해야 한다. 대본을 바꾸면 음성·자막·계획의 필요한 부분만 정상 갱신한다.

### 4.5 편집

- 전체 순서에서 원작 대상과 핵심 매력이 읽히는지, 같은 대상의 좋은 장면을 실제 우선했는지 확인한다.
- 부족한 대목에 유사 장면을 넣을 수 있다. 매 컷 제품 노출·매 문장 동시 일치·반복마다 새 정보·같은 색/모델의 즉시 일치를 강제하지 않는다.
- 직접 시연으로 제시한 장면만 해당 동작·연결 부위·시작/끝 상태를 확인한다. 반응·즐김 장면에 제품 작동의 증명을 요구하지 않는다.
- 다른 제품의 장면을 붙인 결과가 특정 제품의 성능·추천을 거짓으로 연결하는지는 실제 전후 컷·음성을 함께 검토한다.
- 기존 정상 속도 연장·반복·몽타주 허용을 유지한다. 감속·정지 프레임으로 기계적으로 채우거나 미검토 구간까지 승인한 것으로 쓰지 않는다.
- 장면 순위의 정체성 전역 제외와 필수 프레임 보정의 시간 겹침 금지를 직접 대조한다. 모델 프롬프트가 허용해도 실제 선택·보정 함수가 다시 막으면 정렬 대상이다.
- 통과 사례: 휴대형 스파크 사용→유사 분사기와 함께 촬영하는 사람들→원래 제품의 효과 장면이 자연스럽게 연결된다. 바닥형을 보여주며 ‘이 손잡이 버튼을 누르면’이라는 직접 시연으로 제시하는 것은 수정한다.
- 확인 경계: insta_auto의 계획·수량 검사뿐 아니라 별도 auto_capcut 실행기의 선택·배치·검증에도 같은 정책이 전달되는가.
- 핵심 원본 수를 최대화하는 정렬이 필요한 경험 장면의 의미·리듬보다 항상 먼저 적용되는지 대조한다. 기존 전체영상 매력 검토는 이미 몽타주·유사 제품·반응을 허용하므로 그 규칙을 재작성하기보다 실제 차단·정렬 경계를 수정한다.

### 4.6 최종 완성

- 최종 조건은 실제 결과물의 주제·매력·의미·기술 품질이다. 수집 목표 달성, 코드 시험 통과, 검토용 MP4 생성을 최종 완성과 혼동하지 않는다.
- 전체 본문과 실제 오디오·자막·첫 프레임 표지를 함께 검토한다. 텍스트상 ‘지원 장면’이라는 표시가 있어도 실제 편집이 거짓 시연을 만들면 통과시키지 않는다.
- 이미 허용한 관련 리액션·반복·정상 속도 연장을 QA가 단독 결함으로 되살리지 않는지 확인한다.
- 실패를 지적할 때 실제 잘못된 구간·내용·다음 수정 범위를 남긴다. 하나의 문제를 모든 소스 재수집·전체 재작성으로 확대하지 않는다.
- 같은 수집 job 성공 후 남은 실패 포인터, 늦게 도착한 옛 결과, 현재 입력과 다른 승인 캐시를 정상 수용/복구 경로에서 구별한다.
- 통과 사례: 다른 향수나 유사 분사기 컷이 있다는 이유만으로 탈락하지 않고, 전체가 중심 대상의 매력을 전달하면서 구체적 주장을 오인시키지 않으면 내용 검토를 통과한다.
- 완료에 묶을 것: 현재 선택 대본·음성·편집·썸네일·최종 파일과 실제 QA. 과거 완료본/실패 이력은 보존한다.

### 4.7 썸네일 제작

- 실제 본문에 사용하는 승인 영상 프레임을 먼저 찾고, 중심 대상·핵심 매력이 보이는 이미지를 우선한다. 다른 제품 이미지가 원래 제품의 실물로 오인되지 않는지 문구와 함께 판단한다.
- 기존 표지 얼굴 금지(반사·사진 포함)는 유지한다. **본문의 인물 장면까지 금지하지 않는다.** 얼굴 블러로 대체하지 않고 실제 프레임의 손·제품·사용 장면 또는 허용된 크롭을 검토한다.
- 중심 인물 주제여도 얼굴을 못 쓰면 표지의 관련 사물·행동과 근거 있는 문구로 표현한다. 불가능한 경우를 제품 구조 미확인과 혼동하지 않는다.
- 과거 실험용 생성형 이미지/고정 템플릿 경로가 실제 자동 제작에 도달하는지 확인한다. 이름만 비슷한 미사용 코드도 조사하되 미사용이라는 근거 없이 삭제 대상으로 단정하지 않는다.
- 통과 사례: 한소희의 얼굴을 본문에서 쓸 수 있으면서, 표지는 얼굴 없는 실제 향수 사용 컷으로 만들 수 있다. 이것을 상충으로 취급하지 않는다.
- 유지: 최종 크롭·가림·글자·실제 이미지 검토, 표지 프레임의 원본/시간/파일 일치, 본문 승인으로 표지 자동 승인하지 않음.

### 4.8 썸네일 문구 제작

- 이미지·문구·본문이 같은 중심 대상·핵심 매력·약속을 공유하는지 함께 본다.
- 특정 인물의 실제 선호·추천과 일반적인 인기 표현을 구별한다. ‘연예인 향수’라는 검색 가설을 ‘모든 연예인이 추천’이라는 확정 문구로 승격하지 않는다.
- ‘안 뜨겁다’, ‘무조건 안전’, 수치·성분·가격·인기를 근거 없이 새로 만들지 않는다. 과도한 확정 표현을 고칠 때 제품의 유효한 매력까지 지우지 않는다.
- 두 줄은 기존 디자인 형식이다. 제품명+‘왜?’·비밀·질문형을 모든 소재에 강제하거나, 기능이 보인다는 이유만으로 탈락시키지 않는다.
- 문구 보완 때문에 대본·음성·본문을 불필요하게 전부 다시 만드는지 확인한다. 변경 범위와 기존 승인 재사용 범위를 분리한다.
- 표지 전용 변경에서 본문5 검사가 실행되는 현재 경로를 확인한다. 본문이 그대로임을 확인할 수 있으면 그 검증을 재사용할 범위와 최종 파일에서 다시 확인할 범위를 구별한다.
- 통과 사례: 파티 불꽃의 분위기·사진 매력을 약속하고 본문이 실제로 전달한다. 표지 문구만 안전성 제품 리뷰를 약속하는 식의 모순은 없다.

## 5. 실제 실행 순서에서의 충돌도 검수한다

위 8개 항목은 **검수 범주**이며 그대로 직렬 실행해야 한다는 뜻이 아니다.

원작 확보·분석 → 기획 요약 → 대본/우선 소스 탐색 → 필요한 장면 보완 → 선택 대본·음성·편집 계획 → **사용 프레임을 기준으로 썸네일 이미지와 문구를 함께 확정** → 최종 합성·출력 → 실제 전체 QA → 완료.

- 대본과 소스 확보 사이의 순환 의존을 막는다. 소스 확보 전 대본을 못 쓰고 대본 없이는 필요한 소스를 못 찾는 구조가 되지 않아야 한다.
- 썸네일은 현재 첫 프레임에 포함되므로, 표지 전 본문 준비/검토 완료와 표지 포함 최종 완료를 나눠 표시한다.
- 표지만 바꾸면 필요한 표지 합성·최종 파일 검수로 제한한다. 대본·음성 수정은 실제 변경이 있을 때만 한다.

## 7. 점검·개선의 순서와 종료 조건

1. **정책 대조:** 최신 사용자 원칙과 과거 AGENTS·대본 규칙·기술 문서의 충돌을 표시한다. 오래된 문서를 지우기보다 적용 범위·우선순위를 명시한다.
2. **정적 경로 감사:** 8단계별 생산/전달/판정/완료/복구 지점을 연결한다. 쓰이지 않는 경로와 실제 운영 진입점을 구분한다.
3. **정책 결정 정리:** 중심 대상 우선·장면별 대체는 확정 원칙으로 삼고, 기존 EN/ZH 최소 횟수처럼 명시적으로 폐기되지 않은 수량은 변경 결정 항목으로 남긴다. 이 문서만으로 임의 변경하지 않는다.
4. **수정 설계:** 중복·과조건 삭제와 기존 필드/모듈 재사용을 먼저 검토한다. 새 예외 플래그·fallback 단계·분류기를 덧붙여 복잡도를 늘리는 설계는 이유를 설명해야 한다.

## 8. 실제 영상 제작이 좋아졌는지 비교하는 계획

### 8.1 무엇을 입증할 것인가

조건 충돌 해소와 영상 개선은 별도 결과다. **중심 대상과 구매 매력을 유지하면서 장면이 자연스러워지고, 불필요한 작업을 줄여 완성으로 이어지는가**를 확인한다. 후보·다운로드·통과 수가 늘어도 그 자체를 품질 개선으로 세지 않는다. 점수를 합산하는 새 품질 게이트나 새 상시 감시 루틴은 만들지 않는다.

비교 사례는 기존 향수와 불꽃이다. 향수는 특정 인물의 향수 취향·사용을 먼저 찾는지, 불꽃은 실제 분사기의 효과·사용을 먼저 찾고 부족한 즐김 장면을 보완하는지 본다. 두 사례는 개선 가능성을 확인할 첫 사례이며 전체 주제에 대한 통계적 증명이 아니다.

### 8.2 공정하게 비교할 입력과 범위

| 비교 | 고정할 것 | 바꿀 것 / 알 수 있는 범위 |
|---|---|---|
| 저장 자료로 정책·선택 비교 | 같은 원작·본문·대본·음성·검토된 소스와 승인 구간·편집 형식. 코드/정책 버전·파일 SHA와 시작 재고 기록 | 기존/개선 규칙만 변경. 거절·우선순위·편집 선택의 차이를 확인하며 신규 검색 성과를 입증하지 않음 |
| 향후 실제 수집 비교 | 같은 원작·선택 대본·시작 재고·허용 플랫폼·언어 기준·사용 가능한 탐색 범위와 자원 한도 | 승인한 실제 쿼리→제출→새 URL→수신→검토→최종 사용을 추적. 날짜·검색 결과·접근 상태·캐시 차이는 함께 기록하여 로직 효과와 구분 |
| 향후 전체 제작 비교 | 같은 원작과 핵심 제작 의도·음성/디자인 조건 | 대본 개선까지 포함하면 그 변경을 명시. 같은 대본 비교와 별도 결과로 보고하여 효과를 섞지 않음 |

현재는 비교 계획만 작성한다. 저장 자료 시험도 이번에 실행한 것으로 보고하지 않는다. 나중에 비교할 때 과거 실패 코드를 운영에 다시 올리거나 기존 작업을 덮어쓰지 않고 격리된 사본·입력으로 확인한다. 탐색 범위와 자원 한도는 비교 전에 같은 기준으로 정하고, 결과가 나쁠 때 한쪽만 늘리지 않는다. 진행 중인 전송을 경과 시간만으로 끊지 않으며 접근 중지는 그대로 보존한다.

기존 완성본이 있으면 해당 파일과 검수 기록을 기준으로 삼는다. 기존 결과가 수집 실패·미완성이면 그 정지 지점까지 비교한다. **없는 기존 완성본의 품질을 추정해 개선판이 더 좋다고 결론내리지 않는다.** 개선판만 완성된 경우 완성 가능성 개선과 그 영상 자체의 품질 검수 결과까지만 보고한다.

시간은 작업 시작부터 종료/중단까지의 실제 경과 시간과 단계별 사건을 남긴다. 설명할 때 시스템 처리·큐/외부 서비스 대기·접근 차단·사용자 중지·분류 불가 시간을 구분하고, 원인이 확인되지 않으면 추정 배분하지 않는다. 동시에 실행된 에이전트·작업 시간은 겹친 구간을 중복 합산하지 않는다. 별도로 기록하는 누적 호출 비용·사람 개입 시간도 벽시계 경과 시간에 더하지 않는다.

초기 비교에서 임의의 ‘30% 단축’·합산 점수·새 원본 수 목표를 성공선으로 만들지 않는다. 어떤 불필요한 작업이 사라졌고 품질에 어떤 차이가 생겼는지 실제 사건과 장면으로 설명한다. 비교 중 발견한 새 결함은 같은 사례의 수정 전후를 보존하고, 잘 나온 시도만 골라 전체 성공으로 보고하지 않는다.

### 8.4 블라인드 영상 비교

최종 결과물이 둘 다 있을 때 제작 담당과 분리된 검토자에게 개선 전후 이름을 숨기고 A/B로 제공한다. 향수·불꽃의 제시 순서를 번갈아 두고, 원작/제작 의도를 먼저 동일하게 보여준 뒤 표지와 문구를 포함한 전체 영상을 비교한다. 초기 판단 전에 core 수·통과 상태·제작 시간·만든 쪽의 설명을 보여주지 않는다.

검토자는 ‘중심 대상·매력’, ‘자연스러움’, ‘사용하고 싶은 이유’ 각각에 **A 우세/B 우세/차이 없음/판단 불가**와 짧은 이유를 남긴다. 실제 잘못된 추천·성능 연결이나 주제 손실은 해당 시간대/표지 문구를 지적한다. 선호를 남긴 다음에 원본·주장 근거와 제작 비용을 대조한다. 단순 취향과 사실 오류를 구분하며, 의견이 갈리면 그 이유를 남기고 합산 점수로 덮지 않는다.

이 비교는 개선 효과 평가이며 기존 필수 QA를 대신하지 않는다. 주장하지 않은 기능을 새로 입증하라고 요구하거나 표지 전용 조건을 본문 전체에 적용하지 않는다. 실제 시청·구매 전환은 게시 실험을 하지 않았으므로 판단하지 않는다. 게시나 외부 메시지 전송을 이 계획에 포함하지 않는다.

### 8.5 결론과 종료 기준

| 결론 | 판단 방식 |
|---|---|
| 개선 확인 | 주제·사실 관계와 기본 품질을 유지하고, 품질 또는 완성 가능성·효율 중 개선이 있으며 다른 축에 뚜렷한 악화가 없음. 어떤 축이 좋아졌는지 명시 |

| 악화 | 중심 대상·구매 매력 손실, 허위 추천/시연, 또는 비교 가능한 조건에서 품질·완성·비용이 악화. 속도나 후보 수로 상쇄하지 않음 |

향수·불꽃 각각 **기준 입력/버전 → 변경한 조건 → 실제 사용 장면 → 품질 선호와 이유 → 시간·대기·비용 → 결론/남은 한계**를 한 비교 보고서에 남긴다. 공통 결론이 같지 않으면 사례별로 보고한다. 한정한 결함을 고친 뒤 관련 검증만 다시 수행하며, 결과가 마음에 들 때까지 무제한 수집·렌더를 반복하지 않는다.

평가를 끝낼 때 ‘정적 충돌 정리’, ‘격리 회귀 통과’, ‘실제 수집 효과’, ‘실제 영상 품질/완성 개선’을 별도 상태로 보고한다. 앞 단계의 통과가 뒤 단계의 성공을 자동 의미하지 않는다.

### 10.5 하나의 최소 수정안과 순서

**1차: 이미 확인된 전달·상태 결함부터 수정한다.** C10의 같은 job 성공 수용을 현재 claim/run/input/epoch 확인과 같은 저장 경계에서 멱등 처리하고, C06은 역사 실적과 현재 계약 충족을 구분해 표시한다. 이 두 수정은 EN/ZH 최소치나 core 수량을 변경할 필요가 없다. 일반 refresh도 `source_goal.ready`와 회차 종료를 구분해 보여야 한다. `lifecycle:365`의 “추가 수집 완료”는 회차 표현으로 한정한다.

**2차: 검색 계약을 일치시킨다.** C14의 공통 자연어 문법과 공급자 입력 제약을 분리하고 C15의 텍스트/픽셀 근거 소비를 정렬한다. C16은 `reference_scenes`, `scene_ids`, `scene_ids_supported`, `scene_links`를 재사용한다. 새 장면 분류기나 승인 에이전트를 추가하지 않는다. 새 승인 검색어가 provider 전송 직전에 다시 절단되지 않는지 `tiktok_product_queries/platform_queries/plan_queries/round_queries`를 함께 검증한다. 의미 변경 영수증은 새 revision으로 분리하고, 기존 r1~r4는 당시 의미로 읽는다.

**3차: 기획 의도를 기존 입력에 연결한다.** `primary_subject`, 실제 원작 관찰, `reference_scene_intents`, `viewpoint`, `context_usage_limits`, 선택 대본의 주장 정보를 사용해 중심 대상·매력·치환 불가 사실·부족 장면을 전달한다. 후보의 `featured_product_identity=false`를 고쳐 쓰지 않는다. C17은 기존 집필용 실제 프레임을 활용해 참고문구 선택의 주제 관련성을 확인하는 범위부터 설계한다. 제품명 하나를 모든 단계의 사실 판정으로 사용하는 부분만 좁힌다.

**4차: 수집·편집·최종 QA의 정책 의미를 동시에 바꾼다.** 아래 D1을 확정한 뒤 `source_policy`→`source_coverage/source_core_priority`→`studio_sources`→host 계획→외부 `studio_visual_cuts/studio_story_selection/studio_core_priority`→최종 `require_usage`를 같은 revision으로 변경한다. 목표5는 유지하고 장면별 보완을 전역 탐색 소진에 묶는 조건을 줄인다. C20은 existing relation/visual_requirement와 실제 주장 범위를 활용하고 C21은 추가 겹침만을 이유로 한 차단을 제거할 범위를 정한다. 사용 이유·장면 근거가 필요하면 기존 option reason/장면 근거에 남기고 별도 전역 점수 체계를 만들지 않는다.

**5차: 표지와 완료 경계를 정리한다.** 기존 `verify_manual_thumbnail`, `render_if_cover_only`, `verified_quality_export`를 재사용한다. 불변 본문은 원래 승인 정책·plan·render·오디오에 결속하고, 새 표지 이미지·문구·최종 출력은 새 QA에 결속한다. 사전 2줄 문구 생성과 표지 얼굴 금지를 유지한다. 원작의 인물/제품/주장 관계가 대본→표지 검토까지 필요할 때 기존 근거를 함께 전달한다.

각 차수와 함께 `AGENTS.md`, `docs/CODE_MAP.md`, `docs/source_video_pipeline.md`, `writing/RULES.md`, 외부 `AGENTS.md`의 현행/역사 범위를 정렬한다. 특히 ‘모든 검색어 정체성 고정’과 ‘부족 전역 소진’의 과거 문구를 현 자연어 규칙보다 우선 적용하지 않는다. **이번 문서 단계에서는 실행 프롬프트인 RULES나 운영 지침을 수정하지 않았다.**

### 10.7 격리 검증 설계 — 이번에는 미실행

현재 테스트 중 `test_source_topic_queries`, `test_source_query_identity`, `test_query_ten_word_limit`, `test_spoken_reference_visual`, `test_reference_scene_roles`, `test_core_product_priority`, `test_editorial_semantics_20261018`, `test_source_diversity_completion_recovery`, `test_studio_thumbnail`, `test_prepared_cover_only_admission`과 외부 core/story/diversity 시험을 관련 기반으로 삼는다. 구형 계약 기대값은 보존하고 새 정책 기대값을 분리한다. 함수 이름이나 테스트 파일 존재만으로 통과를 보고하지 않는다.

실제 저장 입력의 원본·대본·음성·소스 검토·실패 상태를 격리 사본으로 읽고 외부 검색/모델/TTS/렌더 송신만 대체한다. 내부 승인 행 생성·plan 전달·수용·목표·선택·최종검사는 실제 함수를 연결한다. 유효한 자료를 임의로 core로 라벨링한 fixture만으로 효과를 증명하지 않는다. 다음 15개는 6절 사례의 검증 경계다.
