# 제품 매력 중심 기준 정렬 및 오전 상위3 재제작

상태: 세 동일 작업의 실제 MP4 제작·최종 QA·공개 비교 페이지 검증 완료(2026-10-18). 2026-10-18 사용자 목표는 ① 기준을 먼저 바꾸고 독립 검수 ② 실제 레퍼런스로 기준 재평가 ③ 멈춘 동일 상위3을 끝까지 제작하며 실제 오류와 반복을 감시하는 것이다. 이전 진단과 수정 경과를 보존하고, 최종 증거는 아래 6~8절에 정리했다.

## 1. 기준과 구현

최종 공유 기준은 `product-appeal-first-20261018-v3`, 신규 편집 정책은 `normal-speed-editorial-v1`이다. [정책 문서](editorial_montage_policy.md)와 AGENTS.md에 사용자 피드백을 기록했다.

- 전체 영상이 제품의 특징과 매력을 자연스럽게 전달하는지 판단한다. 대사 조각별로 같은 제품·동작·감정을 동시에 보여야 하는 조건을 제거했다.
- 실제 관찰된 리액션과 관련 맥락 컷을 허용한다. 제품을 언급한다는 이유로 모든 컷의 제품 노출을 요구하지 않는다.
- 같은 특장점 장면을 반복할 수 있다. 원본 시간 중복은 다양성 선호 점수이며 필수 금지가 아니다. 반복마다 새 정보가 있어야 한다는 문구도 제거했다.
- 특정 기능의 차이를 모든 제품 설명·혜택·마무리에 대한 전역 제외로 전파하지 않는다. 실제 다른 제품의 직접 시연 오인·반대 동작의 직접 시연은 검토한다.
- 잘라 둔 장면이 짧으면 같은 원본의 실제 인접 구간을 정상 속도로 더 사용한다. 새 구간은 실제 화면·가림·기능·세로 검토를 통과해야 한다. 감속이나 마지막 화면 복제로 길이를 메우지 않는다.
- 새 배치 실패는 부족한 beat/후보/필요 프레임을 가진 구조화된 구간 확장 요청으로 전달한다. 정상 검토 후 같은 job으로 돌아오며 기존 요청·결과·의미 분석은 별도 이력에 보존한다.
- 명시 신규 제작·재제작의 수집 v4는 1.25배 분량·핵심4초를 권장량으로 표시한다. 재고 준비와 최종 품질 승인을 구분하고, 보완에 신규 원본2개·3개를 필수로 요구하지 않는다. 저장된 과거 run은 읽기·재시작·일반 진행만으로 변경하지 않는다.

[의미 정책 구현](MORNING_EDITORIAL_SEMANTIC_IMPLEMENTATION_20261018.md), [렌더러 구현](MORNING_EDITORIAL_RENDERER_IMPLEMENTATION_20261018.md), [독립 기준 검수](MORNING_EDITORIAL_POLICY_REVIEW_20261018.md)에 각각의 근거가 있다.

## 2. 실제 레퍼런스 검증

기존 원작 6개와 사전 분리한 4개를 새 출력 경로에서 동결한 동일 기준으로 재평가했다. 원본 영상·전사·실제 프레임·시트 SHA를 확인했고 모델이나 음성 설정을 바꾸지 않았다.

이전 v2 전체 표본 평가는10개 모두 통과였지만 독립 검수자가 공기청정기 영상의 다른 기기 연결을 발견했다. 해당 구간에 원본 native17프레임을 추가한 별도 실제 재평가를 수행했다. 최종 결과는 **차단 결함 미관찰9개, 실제 제품 연결 결함1개**다. 원래10개 응답은 변경하지 않았다. 최종 v3에서는 공기청정기의 native17장을 처음부터 포함해 10건 모두 새로 평가했고, 9개 통과·같은 실제 결함1개를 확인했다. 최종10건에는 이전 판정을 입력하지 않았다.

공기청정기의 사각 기기 앞문과 다른 원통형 필터를 한 제품의 연속 시연처럼 연결하는 부분은 오인 문제로 확인했다. 같은 평가에서 쉬는 반려동물 컷은 일반 혜택의 자연스러운 맥락으로 허용했다. 따라서 단순 비동시 설명·반복·리액션을 막는 기준과 실제 제품 시연 오인을 구분한 반례가 있다.

[실제 검증 보고서](EDITORIAL_REFERENCE_VALIDATION_20261018.md). 정지 표본 검토이므로 모든 연속 동작·음성 청취·모든 컷 경계를 전수 확인했다는 뜻은 아니다. 새 완성본의 출력 경계·가림·최종 QA는 별도로 수행한다.

## 3. 구현 중 발견하여 고친 연결 오류

1. 준비 요구가 비어 있는데 `coverage_current=True`만 보고 추가 검토를 건너뛰어, 실제 deferred 소스가 있어도 새 편집 방법을 만들지 못하는 기존 경계가 있었다. 실제 요구가 있을 때만 해당 우회 경로를 사용하도록 수정했다.
2. 구간 검토 중 원본이 바뀌면 승인 결과를 수용할 수 있는 경쟁 경계를 발견했다. 검토 후와 상태 반영 직전 실제 SHA를 재확인한다. 수동 제외·withdrawal·사용자 중지의 변경도 덮지 않는다.
3. 검토가 끝난 뒤 상태 반영 전에 사용자가 중지하면, 검토 완료 표시 때문에 정상 재개를 차단하던 오류를 재현했다. 검토 완료와 상태 적용을 구분하여 동일 승인 결과를 재사용하고 새 모델 호출을 피한다.
4. 새 정책 도입만으로 과거 run을 바꾸지 않도록 `adopt_policy`와 명시 새 run 수용을 분리했다. 신규 task 자체도 v4를 받도록 생성 진입점을 정렬했다.
5. 본문 렌더의 기존 `tpad` 정지 화면 보충을 새 정책에서는 사용하지 않는다. 실제30fps 출력 프레임 수를 선택 전에 계산하고 실제 clip 프레임 수도 확인한다.
6. 오래된 검토 캐시 테스트가 정책·출력 경계 근거가 달라도 과거 판정을 무조건 재사용하도록 요구했다. 실제 계약이 같은 경우에만 재사용하고, 정책 변경/근거 누락 시 실제 재검토 경로로 가는 검사로 정정했다. 운영 검수 조건을 약화하지 않았다.

관련 main 회귀343개 통과 결과와 명령은 `data/editorial-montage-20261018/validation/`에 보존했다. 이후 보완 수집의 같은 원본 추가 구간만으로 진행하는 v4/legacy 반례4개를 포함한 검사17개도 통과했다. 겹치는 검사를 합산하여 별도 총수로 주장하지 않는다. renderer 계약70개 및 실제 저장 입력 회귀4개, main 연결 경계12개 결과는 각 구현 보고서에 있다.

## 6. 최종 QA에서 추가로 발견하고 해결한 문제

### 큰 경계 프레임 시트의 전송 제한

텐트 첫 QA job `job-3670ecae905e4be8`는 모델 판정 전에 실패했다. 1440×2010 경계 시트 두 장이 각각1,244,452/1,096,485바이트여서 집필 worker의1MiB 전송 제한을 넘었다. 해상도나 제품 내용 불합격이 아니다. `daily_quality.py`와 `daily_quality_scope.py`의 모든 실제 프레임 전송을 기존 `visual_media.review_frame_data`로 통일했다. 원본 파일·SHA·픽셀 크기는 보존하고 전송용 JPEG 품질만 조정해467,624/475,488바이트로 보냈다. 실제 시트/모든 QA 그룹을 사용한 전송 테스트3개가 통과했다.

### 동일 제품의 색상 전환을 순간 대사 불일치로 거절

가방 첫 QA는 남색→주황색 전환에 “이 주황색에 눈이 가요” 자막이 걸친다는 이유로 scene_gap을 냈다. 독립 검수자도 처음에는 결함으로 보았지만 전체 영상의 같은 Montbell 가방 여러 색상과 해당 beat 안의 주황색 전환을 확인한 뒤 철회했다. 전체 매력/흐름 기준에 맞춰 RANK와 공유 기준을 v3로 명확히 했다. 같은 제품 색상 전환은 선호 일치 문제이며, 실제 없는 색상·독점 사양을 사실로 단정하거나 다른 구조의 제품을 직접 시연으로 제시하는 문제와 구분한다. 기존 false 응답과 이력은 보존했다.

첫 false 직후 자동 추가 수집이 시작돼 TikTok 파일4개를 실제 수신했다. 중지 전에 발생한 비용이며 '추가 수집0'으로 보고하지 않는다. 수신4개는 미검토 자료로 보존됐고 새 소스 정식 편입과 최종 영상 사용은0이다. 정상 pause-auto로 해당 수집job을 중지한 뒤 새 QA에서는 수집을 재개하지 않았다. 새 대본·TTS·재렌더도 없었다.

### 안전한 새 실제 QA 요청

정상 `recheck-quality` 명령을 추가했다. 현재 edit·render/plan SHA·기준 SHA·revision·작업 큐·중지 토큰을 확인하고 새 QA job만 만든다. 과거 실패 job과 paused 수집job을 되살리지 않는다. 같은 영상·기준의 동일 요청은 차단한다. 큐 수용 이후 실제 영상/계획/기준이 바뀌면 worker가 디코드·모델 호출 전에 거절한다. 명시 재검토에서는 과거 판정/그룹 캐시를 재사용하지 않는다. 같은 edit의 같은 false 결과가 다시 나오면 pending만 남는 오류도 재현해 정상 중단 상태로 마무리하도록 고쳤다. 독립 행동 반례24개가 통과했다.

새 텐트 QA `job-fdebcc884aa84bcd`와 새 가방 QA `job-96d66a9a26db4790`는 모두 실제 재평가 passed/issues=[]다. 가방은 과거 false와의 상충을 정상 밀집 프레임 확인1회로 해결했으며 evidence_recheck=true 영수증이 있다. 손난로 `job-26633bf96fee4e4a`의 기존 v2 통과는 유지했다. 세 영상 모두 v3 모델 호출을 다시 했다고 주장하지 않는다.

## 7. 실제 시간과 보존 감사

시간은 DB job 및 claim event 기준이다. 재제작 접수는12:52:21~22 KST, 세 작업 최종 통과는13:18:09 KST다. **동일3개를 다시 제작한 전체 경과는25분47초**이며 기존 소스·승인 음성을 재사용하고 이번 오류 수정 대기까지 포함한다. 최초 수집부터 시작한 새 영상 전체 제작시간이나 향후 보장 시간으로 해석하면 안 된다.
