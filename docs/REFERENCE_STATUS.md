# 터진 게시물의 공통 상태

이 문서는 신규 제작·중단 제작 재개·레퍼런스 현황이 함께 읽는 상태 계약이다. 실제 값은 각 PC의 Git 제외 `data/reference-status.json`에 둔다. 다른 PC의 로컬 상태가 자동 동기화된다고 가정하지 않는다. 수집 리포트, 기존 작업 기록, 완료 파일을 확인하지 않은 게시물을 `미제작`으로 단정하지 않는다.

세 스킬의 공유 원본은 저장소 `skills/hotpost-*/SKILL.md`이며, 각 PC의 Codex 스킬 폴더에 설치해 사용한다. 설치본이 바뀌어도 이 문서와 실제 원장의 상태가 우선한다.

## 식별·정렬

- `video_id`는 Instagram 원본 게시물의 **shortcode**로 고정한다. 매일 순위는 바뀔 수 있으므로 제작·재개 입력 ID가 아니다.
- `python -m hotpost.reference_registry sync --report data/report.json --run-id <수집 run>`은 최신 비샘플 리포트의 핫 릴스를 원장에 합친다. 현재 [72시간 선정](DAILY_RANKING.md) 리포트는 **전체 기간의 현재 조회수/팔로워 점수** 내림차순이며, 완성 영상도 같은 순위에 남긴다. 동점은 조회수·게시 시각 내림차순, shortcode 순이다. 원장의 `reference.rank`가 전체 순위다. 과거 리포트의 날짜별 정렬과 `rank_in_published_date`는 당시 이력 조회용으로 보존한다. 축약 수치는 원문을 표시하고 근삿값으로 계산하며, 실제 누락값은 미확인으로 남긴다.
- sync는 원본·점수·판정만 갱신하고 제작 상태와 과거 항목을 보존한다. 최신 리포트에 없는 항목은 `in_latest_report=false`로 남긴다. `list`는 최신 후보, `list --all`은 보존 항목까지, `show <video_id>`는 한 게시물의 근거를 보여준다.

## 제작 상태

| 상태 | 의미 |
|---|---|
| `unknown` | 기존 작업·완료본 확인 전. 신규 제작 가능 판정이 아니다. |
| `not_started` | DB/작업 폴더/완료본 중복 검사를 근거로 미착수 확인. |
| `in_progress` | 한 편의 task/run과 서로 다른 제작자·읽기 전용 감시자 결속 후 진행. |
| `paused` | 사용자 중지 또는 명시적 일시 중단. 자동 해제 금지. |
| `blocked` | 실제 필수 단계 또는 품질/접근 보류. 진전 근거 없는 재호출 금지. |
| `completed` | 현재 최종 파일의 QA 근거와 SHA-256으로 완료 확인. 게시 완료를 뜻하지 않는다. |

상태 변경은 `python -m hotpost.reference_registry mark <video_id> --expected-state <현재값> --state <새값> --evidence <근거>`로 한다. 변경 전 `show`와 실제 작업 자료를 다시 확인한다. `in_progress`에는 task/run·서로 다른 제작자/감시자가 필요하고 다른 영상이 진행 중이면 거부한다. 다른 `paused/blocked` 영상이 있으면, 사용자가 현황을 보고 **기존 영상 재개 또는 새 영상**을 선택한 기록·이유와 `--new-over-paused <ID>`를 함께 남겨야 새 영상으로 전환할 수 있다. 기존 중단 상태·자료는 유지하고 병행 제작하지 않는다. `completed`는 현재 `in_progress` 영상에서만 허용하며 `--qa-evidence <제작자 QA JSON>`과 `--final-sha256 <실제 MP4 SHA>`가 필수다. JSON은 [현재 파일 QA 기록](WORKFLOW.md#현재-파일에-결속한-제작자-qa-기록)의 task/run·제작자·항목별 근거를 담고 실제 영상·표지 파일의 해시와 일치해야 한다. 원장은 QA 기록과 영상·표지 해시를 함께 보존한다. 임의의 합격 문구·과거 후보 기록·상태값이나 SHA만으로 실제 QA를 대신하지 않는다. 기존 완료 이력은 보존하며 새 전환부터 검사한다.

## 스킬이 읽는 순서

1. 현황 스킬은 `list --report <리포트>` 또는 `show <ID> --report <리포트>`로 최신 수집 결과를 메모리에만 합쳐 전체 우선순위와 제작 상태·근거를 **읽기 전용으로** 보여준다. 파일을 쓰는 `sync`는 현황 조회에 실행하지 않는다. 상태가 `unknown`이면 기존 작업/완료본 감사가 필요하다고 표시한다.
2. 신규 제작 스킬은 전체 순위 위에서부터 현재 완료 근거가 있는 영상만 건너뛰어 첫 미착수 후보를 확인한다. `next --report <리포트>`는 상태/현재 QA·파일을 검사해 `start / audit_history / audit_completion / review_existing / no_candidate`를 읽기 전용으로 반환한다. `in_progress/paused/blocked` 영상이 있으면 ID·단계·사유를 제시하고 사용자가 재개할지 새 영상을 택할지 결정할 때까지 새 제작을 시작하지 않는다. 중단 영상을 선택하면 재개 스킬 경로로 간다. 새 영상 선택은 명시적인 한 편 원칙의 예외로 기록한다.
3. 재개 스킬은 사용자가 입력한 고정 `video_id`로 원장과 원래 task/run·인계·파일을 **실행 직전 다시** 확인한다. 완료 또는 미착수 영상을 재개로 처리하지 않는다.

원장은 인덱스이자 결정 기록이며 원본 영상·검색 로그·QA·DB를 대체하지 않는다. 기록이 서로 모순되면 제작을 시작하지 않고 원본 근거로 정정한다. 스킬 설치나 원장 sync는 현재 중지의 해제·수집·제작 실행이 아니다.
