## 요약

- 순서: **영상 제작 완료 → 레퍼런스에 댓글 → 자동 DM 수신·필요시 팔로우 확인 → 상품 확인 → 본인 쿠팡파트너스 API 링크 발급·검증 → 대본 기반 본문 → 리틀리 자동 DM 설정**.
- 인스타 댓글·DM은 기존 로그인된 수집 Chrome에 Playwright로 연결한다. 상품 확인 전체 시도는 같은 계정·레퍼런스당1회만이며, 실패하면 오류로 종료하고 자동 재요청하지 않는다.
- 쿠팡 링크 발급은 API 방식만 우선 구현한다. 계정의 API 이용 자격·인증키 연결과 실제 발급/연결 상품 검증이 필요하다.
- 리틀리는 사용자가 지정한13단계로 **다음에 올릴 게시물 / 모든 댓글** 자동화를 만든다. 고정 메시지의 제품명을 치환하고, 버튼 특징은18자 이내, URL은 검증된 우리 제휴 링크, 답글 추가는 정확히2회다.
- 영상 완료 상태와 수익화 상태는 분리한다. 수익화 오류 때문에 영상·대본·개인 음성을 다시 만들지 않는다.

## 구현 순서와 첫 완료 기준

1. 기존 계정 연결 화면에 쿠팡파트너스 API 연결·발급·검증을 추가한다. 인증키는 로컬 비밀정보로 관리하고 Git/로그/화면 응답에 노출하지 않는다.
2. 게시물별 수익화 상태와1회 시도 기록을 내구 저장한다. 댓글 제출 전에 시도 기록을 저장하지 못하면 댓글을 보내지 않는다.
3. Playwright의 레퍼런스 댓글·직접 링크형/팔로우 확인형 DM 흐름을 구현한다. 실패·불명확·중단은 오류이며 같은 레퍼런스를 자동 재시도하지 않는다.
4. 확인된 상품·발급 링크·선택 대본을 연결해 게시글 본문을 준비한다. 리틀리 DM은 아래 고정 템플릿을 사용한다.
5. 아래13단계의 리틀리 생성과 저장 내용 확인을 구현한다. 실제 UI locator·기본 답글·완료 표시·다음 게시물 연결 동작은 구현 시 확인한다.
6. 첫 실제 영상/레퍼런스/상품 하나로 종단 검증한다. 설정 생성과 실제 댓글→DM 전달을 구분하고 각각 결과를 기록한다. 이후에 여러 상품으로 확장한다.

재시도 제한은 인스타 상품 확인 전체 시도에 적용한다. 리틀리의13단계와 지정된 답글 추가2회는 정상 동작이다. 다만 리틀리 등록 결과가 불명확할 때 새 자동화를 중복 생성하지 않는다.

## 확정 요구와 실행 계획 — 사용자 최신 지시 반영

이 절은 영상 제작 이후의 신규 기능 기획이다. 실제 댓글·팔로우·DM 버튼·쿠팡 링크 발급·리틀리 등록을 실행한 기록이 아니다. 기존 영상 제작이나 다른 세션의 구조 개선 작업을 재개·변경하는 지시로 해석하지 않는다. 아래 사용자 확정 요구가 앞선 대화의 제안보다 우선한다.

### 11.1 확정 순서와 연결 방식

**영상 제작·검수 완료 → 레퍼런스 릴스에 안내된 키워드로 댓글 → 원작성자의 자동 DM 수신·제품 확인 → 쿠팡파트너스 API로 우리 링크 발급·검증 → 선택 대본 기반 본문 준비 → 리틀리에 다음 게시물 자동 DM 설정.**

- 상품 확인을 영상 제작 앞으로 옮기지 않는다. 기존 완성 영상·대본·음성은 보존한다.
- 2단계는 원작성자에게 직접 DM을 보내는 것이 아니다. 레퍼런스 게시물에 댓글을 달아 자동 DM을 받는다.
- 인스타 댓글/DM/팔로우 확인 버튼은 기존 로그인 수집 Chrome에 Playwright로 연결하는 방향이다. 창/프로필/계정을 임의 교체하지 않는다.
- 쿠팡파트너스는 API 방식만 우선 구현한다. 설정에서 API 이용 자격과 본인 계정의 키를 연결하고 실제 발급을 확인한다. API가 준비되지 않았다고 웹 발급으로 자동 전환하지 않는다. 초기 웹 로그인·키 발급과 이후 API 인증은 구분한다.
- 리틀리는 아래 사용자가 제시한 실제 웹 UI의13단계를 기준으로 Playwright 등록을 기획한다. 공개 등록 API가 있다고 가정하지 않는다.
- 연결 설정은 공통 설정에, 게시물별 상품·링크·본문·수익화 진행 상태는 개별 게시물에 둔다. 영상 완료 상태와 수익화 대기/오류 상태를 분리한다.

### 11.2 레퍼런스 댓글부터 상품 링크 확인까지 단 한 번만 시도

**사용자 확정: “댓글달고 DM받아서 처리하는건 한번으로 끝내. 한번에 안되면 오류로 남겨.”**

이 제한의 단위는 같은 인스타 계정·같은 레퍼런스 게시물의 상품 확인 전체 과정이다. 한 번의 시도 안에서 필요한 정상 두 단계 DM 흐름은 허용하지만, 실패 후 댓글 재작성/DM 재요청/확인 버튼 반복 클릭으로 새 시도를 만들지 않는다.

정상 경로는 두 가지다.

1. **직접 링크형:** 댓글1회 → 상품 링크 버튼이 있는 DM → 링크 페이지 → 해당 상품 확인.
2. **팔로우 확인형:** 댓글1회 → 팔로우 안내 DM → 현재 팔로우 상태 확인, 미팔로우면 팔로우 → ‘팔로우 확인’ 버튼1회 → 후속 상품 링크 DM → 링크 페이지 → 해당 상품 확인.

구현 조건:

- 외부 댓글 제출 전에 계정/레퍼런스 게시물/목적에 결속한 `attempt_count=1`과 실행 identity를 먼저 내구 저장한다. 저장 실패 시 외부 댓글을 보내지 않는다.
- 댓글1회, 필요한 팔로우 동작1회, 팔로우 확인 버튼1회만 허용한다. 이미 팔로우 중이면 새 팔로우 동작을 하지 않는다.
- 일반적인 화면 로딩·새 메시지 도착을 기다리는 것은 같은 처리 안에 포함한다. 첫 DM과 팔로우 확인 후 DM의 응답 대기 기준은 단계별 설정으로 두되, 대기 종료 시 미수신이면 오류로 끝낸다. 수치는 아직 정하지 않았으며 무한 대기를 기본값으로 두지 않는다.
- DM 미수신, 팔로우 확인 실패, 상품 버튼 부재, 링크/상품 대응 불명확, 로그인/CAPTCHA/접근 오류, 제출 결과 불명확, 실행 중단은 해당 시도의 오류다. 추정 성공으로 다음 단계에 넘기지 않는다.
- 댓글 전송 결과가 불명확해도 다시 전송하지 않는다. DM을 기다리며 같은 버튼을 다시 누르지 않는다. 여러 링크 중 어떤 상품인지 모르면 임의 선택하지 않는다.
- 다음 스케줄·worker 재시작·새 세션·job 이름 변경으로 시도 횟수를0으로 되돌리지 않는다. 중단된 시도는 오류 이력으로 남기고 자동 재진입하지 않는다.
- `error`는 자동 댓글 재시도 대상으로 넣지 않는다. 명시적인 새 사용자 지시 없이는 같은 레퍼런스에 다시 요청하지 않는다.
- 오류 시 레퍼런스/계정/시도ID/단계/시각/실제 댓글 내용·ID/대화·메시지ID/마지막 동작/실제 오류와 화면 근거 경로를 저장한다. 비밀번호·토큰·대량 DM 본문·base64는 로그로 출력하지 않는다.
- 상품 확인 오류라도 이미 완성한 영상·음성·선택 대본은 보존한다. UI에는 `영상 완료 / 상품 확인 오류`로 표시한다.

### 11.3 쿠팡 링크 발급과 검증

확인된 쿠팡 상품 URL을 본인 계정의 파트너스 API 키로 변환한다. 상품명 재검색만으로 다른 상품/옵션을 선택하지 않는다. 발급 성공 응답과 URL 형식뿐 아니라 실제 연결된 상품·옵션이 확인한 대상과 일치하는지 확인한 뒤 리틀리 입력에 사용한다.

보관할 항목은 연결 계정 참조, 원 상품 URL/상품·옵션 identity, 발급 URL, 검증 결과·시각이다. API 성공·정상 상품 연결과 실제 매출/수수료 발생은 구분하며, 수익 실적은 별도 확인한다. 상품/옵션 불일치나 링크 검증 미확인은 그 단계의 오류이며, 다른 상품으로 몰래 대체하지 않는다.

### 11.4 리틀리 등록: 사용자가 제공한13단계 고정 루틴

대상 페이지: **https://app.litt.ly/marketing/instagram**

다음 단계·문구는 사용자가 직접 제공한 절차다. 이번 기획 작업에서 페이지에 로그인하거나 실제 생성 동작을 검증한 것은 아니다. 구현 시 화면의 실제 label/role/입력값으로 locator를 확인하고, 다른 화면이면 추정 클릭으로 진행하지 않는다.

- 같은 이름의 ‘다음’ 버튼이 여러 단계에 있으므로 현재 단계·보이는 버튼 범위를 고정한다. 단계 변경을 확인한 뒤 다음 동작을 수행한다.
- 12번의 답글 추가2회는 사용자가 요구한 정상 동작이며 오류 재클릭과 구분한다. 필수 답글 값 누락 등으로 진행할 수 없다면 사용자에게 없는 내용을 임의 채우지 않고 해당 단계의 오류로 남긴다.

### 11.5 이전 제안에서 명시적으로 변경된 부분

- **기존 제안의 ‘나도’ 키워드 조건을 리틀리에 적용하지 않는다.** 리틀리 발송 조건은 사용자 최신 지시대로 **모든 댓글**이다. 기존 영상 대본의 ‘나도’ CTA를 이 설정 변경만으로 재작성하라는 뜻은 아니다.
- **기존 제안의 ‘우리 게시물 발행 후 게시물ID가 있어야만 생성 가능’을 선행조건으로 두지 않는다.** 사용자가 지정한 ‘다음에 올릴 게시물’ 모드로 게시 전에 자동화를 만든다.
- 설정 완료와 실제 발송 완료는 다르다. 다음 우리 게시물이 올라간 뒤 의도한 영상·제품의 자동화와 연결됐는지 확인하고, 실제 댓글→DM 전달은 별도의 종단 검증 결과로 기록한다.
- 설계상 한 인스타 계정에서는 한 상품의 다음 게시물 자동화를 준비하고, 해당 게시물과의 연결을 확인한 뒤 다음 상품을 처리한다. 상위3 상품의 ‘다음 게시물’ 자동화를 동시에 생성해 상품 링크가 섞이는 구성을 피한다. 서비스의 실제 예약 연결 방식은 구현 시 확인한다.
- 리틀리 단계 오류를 이유로 인스타 레퍼런스 댓글/DM 시도를 다시 시작하지 않는다. 기존에 확인한 상품·파트너스 링크·완성 영상은 재사용한다.

### 11.6 리틀리 완료 판정과 중복 생성 방지

13번 클릭만으로 성공 처리하지 않는다. 실제 생성 결과를 읽어 연결 인스타 계정, 다음 게시물 모드, 모든 댓글 조건, 최종 메시지의 제품명, 버튼 문구 길이, 발급 URL, 답글 설정, 표시된 활성/예약 상태를 확인한다. 서비스가 제공하는 자동화ID/목록 항목/결과 화면 근거를 기록한다.

등록 여부를 확인할 수 없으면 `리틀리 등록 결과 미확인` 오류로 남기고 새 자동화를 처음부터 중복 생성하지 않는다. 부분 결과와 마지막 성공 단계를 보존한다. 이 절은 인스타 댓글/DM에 대한 1회 제한을 리틀리의 사용자 지정 정상13단계 클릭 횟수와 혼동하지 않도록 한다.

### 11.7 첫 검증과 미확인 사항

첫 실증은 실제 영상/레퍼런스/상품 하나로 한다. 댓글1회와 선택된 DM 경로, 본인 파트너스 API 발급·상품 일치, 리틀리13단계와 저장값을 확인한다. 인스타1회 시도가 실패하면 오류를 남기고 그 레퍼런스를 재요청하지 않는다. 미확인인 단계별 DM 대기값, 리틀리의 실제 locator·답글 기본값·완료 표시·다음 게시물 연결 방식은 구현 시 화면 근거로 확인한다.

이번 작업은 **기획 반영만** 수행한다. 실제 댓글·팔로우·DM 요청/버튼 조작·API 링크 발급·리틀리 자동화 생성·영상 재개·코드 배포·커밋은 하지 않는다.
