## 목표와 경계

완성 릴스와 반드시 같은 원본을 찾는다고 보장하지 않는다. 릴스의 장면·제품과 유사하면서
재가공하기 좋은 **후보**를 찾고, 원 URL·권리 상태를 `manifest.json`에 남긴다.
다운로드 가능하다는 사실은 상업적 이용 허가가 아니다. 로그인·CAPTCHA는 사용자가
전용 브라우저에서 처리하며 DRM 또는 봇 차단을 우회하지 않는다.

## TikTok 현재 브라우저 다운로드 (2026-10-11)

### 2026-10-12 실제 구간 활용 보완

- 파일의 처음·중간·끝 표본만으로 필요한 동작이 없다고 단정하지 않는다. 대사에 맞는 동작이 경계에 걸리면 밀집 프레임으로 전후 구간을 확인하고, 그 구간을 분리해 기존 자막·기능·세로 화질 검토를 거친다. 매트의 실제 닦기 동작이 기존 4초 검토 구간 끝부분 밖에 있었던 사례를 `data/source-recovery-20261012-v1`에 보존했다.
- 기능 검토는 시간 순서와 디코드 PTS, 전체 레퍼런스 개요, 원문 제품 설명을 함께 사용한다. 다기능 제품의 특정 보조 기능도 해당 동작과 구조가 확인되면 핵심 장면으로 분류할 수 있다. 그 승인으로 다른 기능·효과·정확한 SKU까지 인정하지 않는다.
- 신규 일별 편집은 `diverse-sequential-v2-semantic-first` 정책을 쓴다. 재생 가능한 미사용 구간 안에서는 직접 맞는 장면을 먼저 고르고, 그 안에서 원본 집중과 연속 사용을 줄인다. 이전 v1 계획과 완성 파일은 보존한다. 점수 우선순위 변경만으로 미확인 동작이나 잘못 분류한 표본을 고칠 수는 없다.
- 새 승인 소스가 추가되면 재편집 큐의 키에도 소스 ID·SHA 서명을 반영한다. 같은 초안과 보완 회차라는 이유로 이미 완료하거나 보류한 작업을 재사용하지 않는다.
- 수동 대사·장면 연결도 기존 승인 구간 안에서만 가능하며, 원본 부모 해시·워터마크 정보·기능별 사용 제한을 유지한다. 모든 발화에 근거가 연결돼야 하고, 최종 실제 프레임 검토는 별도로 수행한다.

장면 확보 검토는 실제 승인 대사·인접 대사에 맞는 증명 목적을 명시한다. 제품 소개나 제형 교정은 `product_support`로 독립 검토한 실제 외형 프레임 하나를 보존하며, 짧은 명사구에 소스의 전체 동작·완료 과정을 강제하지 않는다. 직접 전환 시연(`direct_transition`)은 모든 필수 전후 상태를, 상태·구조 시연(`direct_state`·`structural_detail`)은 그 주장을 입증하는 실제 프레임을 보존한다. 미확인 목적·반대 동작은 승인하지 않고, 과거 영수증의 여러 필수 프레임을 임의로 줄이지 않는다. 렌더 전 선택 실패는 원래 시각 결함의 이유·범위를 유지하며 별도 `failure_reason`을 남긴다. 실제 파일 SHA·native 프레임 노출·승인 구간·대사 길이 검증은 그대로 적용한다.

표지 후보가 얼굴 때문에 모두 불가하면 기존 실제 사용 프레임의 제품 중심 크롭을 먼저 검토한다. 모델은 정규화 bbox만 제안하고, 코드는 동일 소스·사용 timestamp에서 실제 프레임을 추출해 기본 표지 기하·텍스트 마스크·명시 크롭 순서로 새 이미지를 만든다. 원 이미지·소스·native 프레임·새 이미지 SHA와 좌표·마스크를 영수증에 결속한다. 변경된 이미지의 제품 보존·얼굴 없음·실제 삽입 문자 차폐·미해결 호기심을 정상 배치 검토와 단독 최종 검토에서 모두 확인한 경우에만 엔진의 기존 표지 crop 경계로 전달한다. 제안·기존 본문 승인·마스크 승인만으로 통과시키지 않으며 실패하면 기존 표지 보완 흐름으로 반환한다. 동일 입력의 제안·실제 이미지·검토 체크포인트는 모델 용량 대기 후에도 보존한다.

운영 확인은 `tools/inspect_recovery_20261012.py`, 받은 파일의 구간 검토 등록은 `tools/stage_recovery_scenes_20261012.py`, 원인·전체 18건 진행 기록은 `tools/record_recovery_progress_20261012.py`를 사용한다. 비교 페이지에는 최종 QA와 실제 이미지 검토가 모두 있는 결과만 `tools/share_recovery_progress_20261012.py`로 공개한다. CAPTCHA 중지 상태를 변경하는 도구가 아니다.

CAPTCHA는 즉시 접근을 중지하며, 저장된 429 휴식·Retry-After를 다운로드에도 적용한다.

206 바이트 조각은 동일한 응답 URL의 Content-Range 위치에 채운다. 전체 크기·ETag 및
겹치는 부분의 내용이 같아야 하며, 누락이 있으면 저장하지 않는다. 서로 다른 URL이나
영상 버전은 섞지 않는다. blob 재생 주소는 해당 게시물 ID의 브라우저 내 메타데이터에서

연결·별도 음성 트랙의 합성 및 빠진 조각을 추가 요청하는 기능은 아직 없다.

처리는 로컬 회귀 테스트로 검증했다. 다운로드 성공을 편집 적합성·권리 검토 통과로 집계하지 않는다.

## 반복 검색의 이력과 중지 기준 (2026-10-07)

빈 검색어가 발생하던 원인은 검색 이력을 플랫폼 구분 없이 제거하고, 다섯 묶음의
추가 의도를 회차 번호로 순환하면서 해당 묶음이 소진되면 빈 계획을 그대로 실행한 것이다.
현재는 근거 있는 검색어 풀을 유지하고 공급자별로 미사용 검색어를 고른다. 언어·행동·
클로즈업·준비·소분 등 유한한 의도를 전환하며, 요리에는 제품 언박싱을 붙이지 않는다.
텍스트 검색 경로가 소진되면 `query_exhausted`, 근거/지원 언어가 없으면
`no_supported_queries`로 기록한다. 빈 문자열을 텍스트 검색 요청으로 보내지 않는다.

`source_search/planner.py`는 회차 번호의 접미사 순환 대신 이전 결과로 다음 목적을 고른다.
첫 검색은 관찰한 핵심 행동을 우선하며, 검증 탈락은 원본·무자막 조건 또는 다른 클로즈업으로,
다운로드 실패는 다른 수신 플랫폼으로 전환한다. 전 회차에 후보가 전혀 없거나 요청이 모두
실패한 경로는 다음 회차에서 제외한다. 회차 안 추가 탐색도 조건을 바꾸며 사용 이력을 공유한다.
모델이 행동을 놓쳐도 캡션·음성·화면에 명시된 보관·냉장·소분·숟가락 동작을 사전 번역으로
검색한다. 언급 없는 냉장·재료·제품 기능은 만들지 않는다. 요리·보수 작업은 판매처 영상 검색을
제외한다. `search_strategy`에 목적·이전 실패 수·경로·제외 이유를 기록하며 화면에도 표시한다.

동일 공급자와 정규화된 동일 검색어의 실제 시도는 자동으로 반복하지 않는다.
확인 가능한 동의어·행동 분류도 공유 키로 비교하므로 `preparation process`와
`hands on preparation` 등의 말 바꾸기는 재시도로 쓰지 않는다. 무자막·클로즈업 등 영상 조건,
검색 언어 및 검색 대상 범위는 보존한다. 미등록 표현은 정확한 문자열 비교를 유지하며,
모든 임의의 문장을 의미적으로 동일 판정한다고 보장하지 않는다.
공급자가 달라지거나 공개 TikTok 색인처럼 검색 범위가 달라지면 별도 조건이다.
Google Lens·Yandex·선택적 Vision API는 이미지 SHA-256과 작은 색상 표본·dHash로
동일 파일 및 재압축·미세 변화한 유사 장면을 제외한 뒤 대표 이미지를 고른다.
색상 거리까지 확인해 해시만 같은 서로 다른 단색 장면을 잘못 합치지 않는다.
기존 이름 기반 이력도 존중하며, 보존된 기준 프레임에서 과거 유사도 표본을 한 번 복원한다.
최근 500개만 보관하던 사용 이력을 영속 검색 키로 변경했고, 업데이트 전 완료 회차의
manifest에서 이력을 한 번 복원한다. 브라우저 요청은 탐색·업로드 직전에 체크포인트를 저장해
프로세스 종료가 실제 시도를 미시도 기록으로 바꾸지 않도록 한다.

2026-10-14 현재 자동 수집은 고정 무성과 횟수·회차·총시간으로 새 범위를 차단하지 않는다.
기존 설정/진단 카운터/실패 이력은 보존한다. 실제 실행 시간은 관측 정보이며
동일 근거의 고정 계획·소비한 플랫폼/페이지 범위·검사 확정 탈락 URL을 실행 전에 대조한다.
메타데이터 탈락도 `inspected_urls`에 저장하되 네트워크 시도 회계에는 넣지 않는다.
실제 미사용 범위가 소진되면 hold로 보존하고 재시작으로 초기화하지 않는다.
인증·로그인·429·브라우저/서비스 대기는 실패·범위 소진과 구분하여 not_before로 이어간다.
실제 소스/검토 결과가 증가해야 진전이며 후보 수 증가만으로 편집을 승인하지 않는다.
수신·완료 검토 체크포인트를 유지하고 과거 completed·중지 작업을 일괄 재개하지 않는다.
정책과 한계는 [전체 흐름 감사](workflow_reliability_audit.md)를 따른다.

## 현재 처리 순서

같은 레퍼런스에서 이미 확보한 소스와 미검증으로 남은 후보를 먼저 다시 검증한다.
`source_search/library.py`는 다른 레퍼런스용으로 보관한 실제 파일도 제품명·다국어
동의어·후보 자체의 관찰 행동으로 찾아 미검증 후보로 제안한다. 이전 선택·기능 승인·
블러 승인은 승계하지 않으며, 현재 레퍼런스 기준으로 모두 다시 검사한다.
현재 묶음에서 검사한 URL은 다시 제안하지 않고, 사용자 설정으로 제외한 플랫폼과
원본 레퍼런스 파일·저장 경로 밖의 파일은 후보에서 제외한다.
`acquisition=local-cache`, `reused_from`은 보관 파일 재사용 근거이며 외부 다운로드
시도에 포함하지 않는다. `platform_outcomes.local_reuses`와 `network_received`로
재사용과 새 수신을 구분한다. 과거 기록에 이 필드가 없으면 새 다운로드로 추정하지 않는다.
실제 파일이 없는 과거 기록과 이미 검사한 URL은 제외하고, 부족분은 새 외부 검색으로
보충한다. 저장 소스도 현재 레퍼런스의 기능·장면·중복·블러 기준을 통과해야 사용한다.
기존 원본 레퍼런스 영상이나 전사문을 새 수집의 분석 자료로 다시 쓰는 것은 별도의
초기화 캐시 규칙으로 제한한다.

자동 제작은 아래 탐색을 한 번으로 끝내지 않고 `studio_sources.py`의 저장 가능한 수집 라운드로 이어간다. 새 제작·수집 목표는 검토된 핵심 장면과 충분한 사용 가능 분량이다. 선택한 대본의 음성이 있으면 음성 길이, 없으면 원본 길이의 기본 1.25배(`source_coverage_ratio`)를 확보한다. 길이를 확인하지 못하면 임시 30초(`source_default_duration`) 기준을 화면에 표시한다. 핵심 장면은 기본 4초(`source_core_min_seconds`, 출력 길이가 더 짧으면 그 길이) 필요하다. TikTok 5개는 선호 목표이며 다른 플랫폼으로 충분한 장면과 분량을 확보하면 완료한다. 깨끗한 승인 영상은 파일 길이, 블러 영상은 승인된 구간 합집합만 초수에 포함하며 중복 파일·장면은 이중 합산하지 않는다. 소스 확보와 원본 기반 대본·개인 복제 음성은 병렬 진행하며 편집은 목표 확보 후 시작한다. 사용자 수동 선택과 과거 완성본은 보존한다. 현재 장면 충족은 핵심 기능 검토 기준이며 대본의 모든 문장별 장면을 매핑하는 별도 보장은 아니다.

자동 수집의 장면 검토는 실제 검토를 마친 소스만으로 위 목표가 충족되면 종료하고 다음 제작 단계로 넘긴다. 미검토 후보는 사용 가능 수에 넣지 않는다. 추가 다운로드와 원본 manifest는 그대로 보존하여 이후 검색·재검토 후보로 사용하고, 라운드의 `review_completion`에 검토 수·미검토 수·달성 근거를 저장한다. 사용자 수동 수집·명시적 새로고침은 요청된 후보 전체의 검토를 유지한다.

1. `data/hotpost.db`의 릴스 메타데이터를 읽고, 같은 shortcode의 정상적인 저장 영상이 있으면
   소스·대본 작업 폴더에서 재사용한다. 없으면 `collection_source=browser`에서는 로그인·수집과
   같은 전용 Chrome 프로필로 해당 게시물(`/p/<shortcode>/`)을 열고, shortcode가 일치하는
   응답의 영상만 받는다. SHA별 전체 영상/음성 디코드 영수증으로 재사용을 검증한다.
   새 수신은 임시 파일을 검증한 뒤 원자 저장하며 실패해도 기존 정식 파일을 덮지 않는다.
   예전 세션 파일은 필요하지 않다. 다른 수집 방식에서는 기존 세션을 사용한다.
2. 실제 음성 전사를 확보하고 ffmpeg로 균등 프레임과 장면 전환 프레임을 합친다. 캡션, 음성 전사, 기준 프레임 OCR,
   선택적 Vision 라벨에서 제품·브랜드·특징·명시된 품번을 추출한다. 제품을 식별하지 못하면
   OpenCLIP 카탈로그로 보완한다. 제품/브랜드 제외/외형/상세 리뷰/시연/개봉 의도를
   영어·중국어·한국어로 확장하고 검색어마다 근거·언어·신뢰도를 남긴다.
3. 로그인된 기존 수집용 Chrome의 동일 페이지·세션에 연결해 TikTok 영어·한국어·중국어 및 관찰 근거가 있는 일본어 검색을 먼저 수행하고,
   Google Lens·Yandex 역이미지, Douyin·Xiaohongshu·Bilibili 검색을 이어간다.
   중국 플랫폼은 중국어 검색어만 허용하며 미사용 중국어 검색어가 없으면 건너뛴다.
   검색 플랫폼별로 사용자가 로그인해 둔 기존 브라우저 페이지를 사용한다.
   별도 검색 API나 다른 로그인 프로필로 자동 대체하지 않는다. 로컬 후보 캐시는
   파일 해시·실제 제품 동작·사용 제한을 검토한 뒤 재사용할 수 있다.
   같은 플랫폼 검색 시작 사이 기본 10초 최소 간격(`source_browser_search_interval`)을 둔다.
   과거 CAPTCHA 기록은 현재 기존 플랫폼 탭을 다시 읽어 점검한다. 현재 CAPTCHA가 없고 로그인 차단도 없으면 해당 CAPTCHA 차단만 해제하고 같은 세션에서 이어가며, 실제 CAPTCHA가 남아 있으면 해당 플랫폼 요청을 중지한다. 현재 화면을 읽을 수 없으면 상태 미확인으로 기록한다.
   HTTP 429는 서버의 Retry-After를 우선 따르며 안내가 없으면 최대 10분(`source_browser_block_cooldown`) 쉰다. 휴식 상태는 로컬 파일에
   저장하여 검색 프로세스가 바뀌어도 유지한다. 접근 대기는 검색 실패·품질 보완 사용량으로
   계산하지 않는다. 연결·응답·브라우저 결과 확보 감시는 유지하되 유효 수신 중인 작업에
   상위 잔여 시간을 전체 완료 시한으로 전달하지 않는다. 이 간격이 CAPTCHA 방지를 보장하지는 않는다.
   Bing·DuckDuckGo·YouTube·Vision·Pexels 요청, 영상/썸네일 다운로드, Instagram 상세 탐색·스크롤에는
   `request_pacing.py`의 1~3초 무작위 대기를 추가한다. yt-dlp 내부 메타데이터 요청은 최소 1초,
   다운로드 전 1~3초, 내부 재시도는 2초 대기를 사용한다. 이미 저장된 파일과 로컬 연산에는 대기하지 않는다.
4. 영상 상세 URL을 검증하고 중복 URL을 제거한다. 초기 최대 40개 후보를 플랫폼별로 배분한다.
   다운로드 실패는 성공 검사 한도를 소모하지 않는다. 기본 성공 다운로드 30개, 총 시도 60회는
   한 회차의 후보 배치 크기이며 품질 중단이나 전체 제작 완료 조건이 아니다. 실제 미시도 접근 대기는
   시도량에서 제외하고, 소비 범위와 확정 검사 이력을 저장해 다음 회차가 같은 실패를 반복하지 않게 한다.
   기존 다운로드/검증 900초 총시간 배분은 사용하지 않는다. 유효 media bytes·디코드 진전과
   무진전을 구분하며 진행 중인 다운로드에 비현실적인 하위 완료 시한을 만들지 않는다.
   유효 소스가 목표보다 적으면 미사용 검색어와 검증된 후보 제목으로 한 번 추가 검색해 최대 12개를 보완한다.
   장면 점수는 dHash 55% + OpenCLIP 45%다. 기본 functional 모드는 색·일부 디자인 차이를
   허용하며 핵심 기능이 실제 영상 프레임에서 같다고 검토된 후보를 보존한다. 단순한 제품군·제목
   일치만으로 채택하지 않는다. 유사도·제목 불일치는 `similarity_warnings`에 남기며 실제 검토 전의 탈락 조건이 아니다.
   확보한 후보는 제작실에서 실제 프레임을 Codex로 검토하고, 이전의 최대 3개 구제 제한은 사용하지 않는다.
   관찰 행동·차이점·프레임·파일 해시를 functional_review에 남긴다. product 모드는 의미 유사도 0.82 이상인
   대체영상도 보존한다. scene 모드는 기존 장면·제품 복합 게이트를 사용한다.
5. 후보 프레임의 자막·워터마크를 Tesseract 또는 저장된 EasyOCR ko+en 모델로 검사해 `clean-source`, `light-overlay`,
   `edited-with-text`, `unknown`으로 구분한다. 재가공 적합도(`source_score`)는
   깨끗한 화면 55% + 제품 의미 유사도 30% + 장면 dHash 15%다.
6. 관련성·길이·영상 스트림·파일/장면 중복 검사를 통과한 후보 중 기본 상위 20개를 ZIP에 넣는다. ZIP 선정은 검토 대기 후보이며 최종 편집 승인이 아니다.
   `clean_sources/`, `review_needed/`, `unclassified/` 폴더로 유형을 구분한다.
   자막이 많은 `edited-with-text`도 소스 후보로 보존하며 `blur_required`를 표시한다. 최종 편집은
   실제 프레임에서 확인한 `watermark_masks` 영역이 있어야 진행한다. CapCut의 흐리게 효과와
   직사각형 효과 파일을 확인하고 네이티브 편집 가능한 효과를 넣는다. 미리보기도 같은 영역을 가린다.
   효과 파일이나 검토 영역이 없으면 완료 처리하지 않는다. 같은 제품의 다른 촬영을 보존하기 위해
   의미 임베딩 유사도만으로 재업로드 중복이라고 판정하지 않는다.
   ZIP에는 미리보기·`manifest.json`이 있지만 분석용 기준 Instagram 릴스는 없다.

## 결과 해석

TikTok 검색은 HTTP 200이나 쿠키 존재만으로 성공 처리하지 않는다.
검색 화면의 초기 3초 뒤에도 결과가 없으면 같은 페이지에서 최대 15초 더
기다리며 결과·명시적 빈 결과·인증 차단을 구분한다. 새 검색 요청은 보내지 않는다.
영상 주소는 페이지가 이미 받은 `/api/search/item/full/` 또는
`/api/search/general/full/` 응답 중 검색어가 일치하는 실제 video 항목에서만 읽는다.
문서 전체의 알림·활동·추천 영상 주소와 사용자 항목은 검색 후보로 세지 않는다.
결과가 확인되지 않으면 `page_unresolved`이며 `no_results`와 다르다.
`result_wait_seconds`와 `result_method`를 남긴다. 검색 후보 수·다운로드 성공 수·
핵심 기능이 검토된 제작 가능 소스 수는 서로 별도로 보고한다.

페이지 판독 실패는 인증 실패와 별도로 `search_readiness/<platform>.json`에 보존한다.
같은 판독기 버전에서는 검색어만 바꾸어 다시 방문하지 않는다. 판독기 수정 또는 사용자의
명시적인 세션 저장 후 한 번 재확인하며, 다시 판독에 실패하면 경로를 중지한다.
시간 경과만으로 중지를 해제하지 않는다. 별도의 CAPTCHA·로그인 차단도 계속 적용한다.

후보 제목의 주제·핵심 행동 일치는 검사 순서를 정하는 근거다. 제목만으로 제작 가능 판정을
내리지 않으며 제목이 없는 후보도 유지한다. 검색 결과에서 초 단위 길이가 확인된 후보는
기존 길이 기준을 먼저 검사한다. 길이를 모르면 다운로드 후 실제 파일을 확인한다.
후보별 완료 시한을 미검증 후보 수와 플랫폼·전체 잔여 시간으로 나누지 않는다.
예전 `source_candidate_download_budget`·플랫폼 300초 설정은 현재 완료 배분에 사용하지 않는다.
실제 플랫폼 사용 시간과 검사 순서는 진단으로 보존한다. 회차 배치 때문에 미검증한 URL은
다음 라운드에서 재검색 없이 먼저 이어받고, 현재 CAPTCHA·429 등 접근 대기는 확정 다운로드
실패와 구분해 재개한다. 확정 검사 탈락·이미 검사 완료한 후보는 같은 조건으로 이월하지 않는다.
검사 순서 근거·검색 결과 길이·실제 검사 및 미시도 사유는 제작실 검색 내역에 표시한다.

`similarity` 0.82 이상이며 dHash 0.80 이상일 때 `same-scene-likely`, 0.72 이상은 `close-match`다.
제품 모드에서 의미 유사도 0.82 이상이지만 dHash가 0.72 미만이면 `product-related`로 표시한다.
그 밖은 `topic-related`다. 점수는 확률이 아니며 임계값은 대표 데이터셋으로 보정할 필요가 있다.
모두 자동 추정이며 원본 일치나 사용 권리를 보장하지
않는다. `source_quality`도 OCR 보조 판정이라 제품 포장·현장 간판을 자막으로
오인할 수 있다. 저신뢰 텍스트가 반복되는 영상은 OCR 결과가 비어도 클린으로 단정하지 않는다.
EasyOCR ko+en은 중국어 등 다른 언어를 완전히 읽지 못한다. 최종 선택 전 영상과 원 출처·권리 상태를 확인한다.

직접 플랫폼 검색은 앞쪽 4개 문자열을 잘라 쓰지 않고 언어별 검색 계획을 사용한다. 기본 플랫폼당
검색어 6개, 후보 12개이며 TikTok은 기본 후보 15개(사용 가능 목표의 3배)를 확보하도록
배분한다. TikTok은 첫 세 검색을 영어·한국어·중국어에 배정하며 후보 상한에 도달해도
계획한 언어 검색을 생략하지 않는다. CAPTCHA·요청 제한·브라우저 무진전 감시는 계속 우선한다.
`manifest.json`에는 제품 근거, 검색어 계획, 추가 검색 근거, 예산 중단 사유, 플랫폼별
발견/다운로드/선정 개수를 기록한다. 추가 검색은 직접 플랫폼·YouTube·Bing 경로로 한 차례 수행한다.

현재 제품 식별과 번역은 규칙·다국어 사전 및 기존 OpenCLIP 카탈로그, 텍스트 근거 기반 모델 확장을 사용한다.
임의의 제품 모델을 추론하는 범용 비전 언어 모델이나 전체 라이브러리의 벡터 검색은 구현하지 않았다.

설정 기본값은 `hotpost/config.py`, 실제 점수·ZIP 구현은 `hotpost/source_finder.py`,
브라우저 검색은 `hotpost/browser_search.py`, 텍스트 오버레이는
`hotpost/text_overlay.py`가 기준이다. 이 문서와 코드가 다르면 코드 구현을 확인하고
문서도 함께 갱신한다.

## 검색 개선 및 실행 기록 (2026-09-26)

- 신규 제작은 실제 음성 전사와 화면 OCR을 확보한 다음 소스 검색을 시작한다. 독립 소스 검색도 기존 전사가 없으면 분석을 먼저 시도한다. 음성과 화면 글자는 별도 근거로 유지하며, 실패 시 캡션·이미지 검색으로 진행하고 진단을 남긴다.
- 주제 사전은 요리와 보수 작업에 언박싱 대신 조리 과정·보수 과정 검색 의도를 적용한다. 설정된 모델(Gemini 또는 script_auto 로컬 모델)로 실제 캡션/음성/OCR의 인용 근거를 확인한 한국어·영어·중국어 검색어를 추가한다. 모델 검색어는 `model_inferred`이며 원본·제품 일치를 보증하지 않는다. 모델 미설정/실패는 사전과 이미지 검색으로 대체하고 명시한다.
- 언어별 검색어는 플랫폼에 맞게 배분한다. 중국 플랫폼에는 중국어를 우선한다. 후보 배분과 요청 제한은 YouTube/Bilibili를 각각 취급한다.
- `yt-dlp[default]`로 해당 버전과 호환되는 EJS 구성요소를 설치한다. `source_ytdlp_js_runtime` 또는 `HOTPOST_SOURCE_YTDLP_JS_RUNTIME`에 `node:실행파일절대경로`를 지정하면 예약 실행의 PATH 차이에도 같은 런타임을 사용한다. 미지정 시 PATH/가상환경의 Deno, Node를 찾는다. 공식 설치 안내: https://github.com/yt-dlp/yt-dlp/wiki/EJS
- Bilibili 다운로드는 90초 후 한 번만 150초 범위에서 이어받기를 시도하며 남은 전체 다운로드 시간 예산을 넘기지 않는다. 로그인·CAPTCHA·DRM 오류와 요청 제한은 기존 중단 원칙을 유지한다.
- 라운드의 후보 묶음이 `source_max_downloads`(20)에 못 미치면 한 차례 추가 검색한다. TikTok 선호 목표 미달만으로 추가 검색하지 않는다. 최종 사용 가능 분량·핵심 장면 검토 후 부족분은 영속 큐에서 다음 전략으로 보충한다. `source_refine_max_candidates`(12), 회차 시도 60회, 성공 다운로드 검사 30개는 배치 크기로 유지한다. 예전 900초 총시간 및 플랫폼별 300초를 하위 작업의 완료 예산으로 사용하지 않는다. 실제 시도·플랫폼 사용 시간은 진단으로 보존하고 연결/응답/수신 무진전 감시와 플랫폼 접근 대기를 구분한다.
- 180초 초과, 최대 `source_long_video_max_seconds`(1800) 영상은 8개 구간에서 각각 3프레임을 검사한다. 기능 일치 모드는 점수 하한 없이 가장 유망한 구간을 `source_segment_seconds`(30)초로 추출한다. 점수가 없으면 프레임이 확보된 구간을 제안한다. 제품/장면 일치 모드는 기존 0.82 기준을 유지한다. 이는 후보 구간 제안일 뿐이며 실제 기능·자막·해상도·중복 검사를 다시 적용한다. 전체 영상의 모든 장면을 검사하는 것은 아니다. 원본 URL, 원본 파일, 시작/끝 시점을 결과에 보존한다.
- 길이와 정상 영상 크기 확인을 먼저 검사한다. 원본 가로 360/세로 640 미만 또는 가로가 세로의 2배 초과인 경우는 `format_warnings`에 남기며 점수만 소폭 낮춘다. 세로 크롭 후 유효 해상도·확대 비율·보존 면적도 기록한다. 숫자 경고만으로 탈락시키지 않는다. 영상 스트림 크기를 확인할 수 없거나 긴 영상에서 유효 구간을 얻지 못한 경우에는 무거운 검사를 생략한다.
- `source_presentation.py`는 신규 후보를 현재 편집기의 1080×1920 중앙 채움/크롭과 같은 필터로 실제 디코딩해 화질과 동작 보존 여부를 Codex로 검토한다. 깨끗한 영상은 시작·중간·끝의 3프레임, 구간 승인 영상은 각 승인 구간 3프레임을 확인한다. 파일 해시·편집 구간·크롭 좌표계·관찰 행동과 검토 결과를 연결한다. 낮은 원본 해상도도 실제 필요한 활동이 읽히면 허용하며, 고해상도라도 필요한 손·도구·동작이 잘리면 제외한다. 미확인·검토 실패는 승인으로 처리하지 않고 같은 입력의 실패를 무한 재시도하지 않는다. 기존 완성본과 직접 촬영 영상은 새 검토 조건으로 소급 변경하지 않는다. 샘플 검토는 전 프레임 보장이 아니며 이후 추가 확대나 다른 크롭의 적합성을 보장하지 않는다.
- 새로 승인된 소스의 자동 편집은 검토한 크롭을 유지하도록 자동 확대를 적용하지 않는다. 사용자가 명시적으로 요청한 확대 수정은 보존하며, 그 새 구도의 적합성은 원래 수집 검토가 보장하지 않는다.
- `manifest.json`의 `query_details`는 검색 계획, `search_audit`는 실제 실행 기록이다. 공급자, 검색어, 언어, 결과 수, 오류·로그인 필요 등을 구분한다. 후보·다운로드·채택 개수와 탈락 사유는 제작실에서 조회할 수 있다. 이전 실행에 기록이 없으면 없다고 표시한다.
- 브라우저 검색은 별도 프로세스에서 수행하고 단계마다 중간 결과를 저장한다. `source_browser_timeout`(360초)은 유효 결과의 무진전 감시로 사용하며, 실행 중인 검색에 상위 잔여 시간을 완료 시한으로 나누지 않는다. 추가 검색도 유효 후보·완료 검색·단계 결과를 관찰한다. Chrome은 작업 프로세스 밖에서 유지된다. 작업자가 유효 진전을 내지 못할 때 해당 프로세스를 종료하고 완료된 후보·실행 기록을 회수하여 다운로드를 이어간다. 멈춘 사이트를 성공으로 기록하지 않으며 로그인 쿠키와 사용자 파일은 삭제하지 않는다.
- TikTok 선호 목표는 `source_tiktok_min_usable`(기본 5, 0 이상)다. 실제 편집 가능 파일만 센다. 후보 탐색에서는 TikTok을 우선 배분하고 최종 선택은 적합도 순이며 동점에서 TikTok을 선호한다. 필수 자리를 예약하지 않는다. `platform_preferences.tiktok`에 확보 수와 언어별 검색 상태를 남기되 `required:false`이며, TikTok 미달은 완료를 막지 않는다.
- 검색어 확장은 내장 Codex 연결을 사용한다. script_auto 서비스나 로컬 집필 모델에 의존하지 않는다. 생성 실패 또는 검증 가능한 인용 근거가 없으면 사전 검색어만 사용하고 누락 언어를 기록한다. 번역이 준비되지 않은 언어를 검색했다고 표시하지 않는다.
- 플랫폼 검색·다운로드는 로그인된 기존 수집용 Chrome 페이지에 연결한다. TikTok/YouTube는 같은 페이지의 실제 미디어 응답을 우선 수신하며 조각 파일은 검증 가능한 완성 영상으로 조립한다. TikTok 미디어 수신만 실패한 경우 승인된 tikvideo 입력·다운로드 UI를 대체 경로로 사용할 수 있다. CAPTCHA·429·로그인 차단은 다른 경로로 우회하지 않는다. `yt-dlp` 설정만으로 플랫폼 접근 성공을 판단하지 않는다. 검색 작업 프로세스만 종료하고 기존 탭·Chrome은 유지한다.
- 제작실의 **다국어 추가 수집**은 영속 큐의 `refresh_sources` 작업이다. 기존 대본·음성·편집본과 소스는 유지하며 신규 소스만 추가한다. 추가 소스는 다음 편집 실행부터 사용된다. 기존 편집본의 장면을 자동 교체하지 않는다.

## 플랫폼 로그인 버튼과 세션 재사용

TikTok·더우인·샤오홍슈·Google·YouTube 로그인과 소스 검색은 `source_browser_profile`의 같은 Chrome을 사용한다.
Chrome은 컨트롤러가 별도로 실행하고 검색 프로세스는 로컬 CDP로 연결한다. 검색 완료·시간 초과·프로세스 종료 후에도
창과 플랫폼별 검색 탭을 유지한다. 사용자가 직접 연 탭은 이동하거나 닫지 않는다. Instagram 계정 수집은 기존 계약을 유지한다.
설정 → 연결 → 플랫폼 로그인 관리에서 플랫폼을 선택하고, 열린 Chrome에서 인증 후 `세션 저장 완료`를 누른다.
이 버튼은 Chrome을 닫지 않고 로그인 작업의 잠금만 해제한다. 검색 중에는 로그인 작업을 새로 시작하지 않으며,
프로세스 간 잠금으로 같은 브라우저의 중복 조작을 막는다. 캡차 화면도 그대로 남겨 사용자가 해결할 수 있다.
브라우저를 직접 닫으면 다음 작업에서 같은 프로필로 다시 열고 인증 상태를 확인한다. 설정 화면은 Chrome 연결 여부를 표시한다.
기존 별도 로그인 쿠키는 최초 연결 시 한 번만 가져온다. 이후에는 동일 Chrome의 살아 있는 세션을 사용하며,
다운로더는 `platform_sessions/<platform>.json`의 최신 쿠키를 작업별 비공개 사본으로 받는다. 쿠키 존재만으로 인증 성공을 표시하지 않는다.

플랫폼 검색은 검색창에 검색어를 입력하고 Enter로 제출한다. 검색창을 찾을 수 없으면 실패를 기록하며 URL 검색으로 몰래 대체하지 않는다.
같은 플랫폼의 요청 시작 간격은 기본 10초이고 지난 시간을 차감한다. 첫 요청은 즉시 실행한다.
페이지 이동 제한 `source_browser_navigation_timeout`과 결과 표시 제한 `source_browser_result_timeout`은 각각 기본 30초로 독립적이다.
결과가 늦게 나타나도 수집을 마치기 전에는 다음 검색어로 넘어가지 않는다. 일시적 실패는 20초 후 최대 한 번 재시도한다.
CAPTCHA와 로그인 요구는 시간이 지났다는 이유로 자동 해제하지 않는다. 2026-10-12 사용자 변경에 따라
과거 CAPTCHA 기록이 있으면 요청 전에 로그인된 기존 수집용 Chrome의 해당 플랫폼 탭을 읽기 전용으로 점검한다.
현재 CAPTCHA와 로그인 차단이 없으면 관찰 기록을 남기고 과거 CAPTCHA 중지를 해제해 이어간다.
실제 CAPTCHA가 남아 있으면 해당 플랫폼 요청만 중지한다. 기존 탭을 특정하거나 읽을 수 없으면
현재 상태 미확인으로 기록하며, 새 CAPTCHA 발생으로 세지 않는다. 새 탭·프로필 생성, 화면 새로고침,
CAPTCHA 자동 해결이나 시간 만료로 확인을 대신하지 않는다. 429·Retry-After는 별도로 유지한다.
자동 수집 전체를 장기 휴식시키지 않고
다른 공급자로 진행한다. 근거와 운영 방향은 [검색 인증 반복 문제 점검](search_access_reliability.md)에 있다.
TikTok 후보는 사이트 검색과 공개 검색의 직접 영상 링크에서 먼저 확보한다. 선호 목표는 5개이며
관련성·화질·중복 기준이나 차단 중지 규칙을 완화해서 채우지 않는다.

## 수량 정책과 실패 근거 보존

`source_policy.py`가 새 수집의 장면·분량 기준과 TikTok 선호 목표를 버전 3으로 만든다. 새 작업과
미완료 자동 제작에 적용하며, 기준이 없던 과거 완성 버전은 버전 1로 읽고 버전 2의 완성본도 보존한다.
기존 결과물을 다시 수집하거나 미완료로 바꾸지 않는다. 이후 새 제작·추가 수집에는 새 기준을 적용한다.
전체 수량은 URL 정규화, 파일 SHA 및 프레임 중복 검사를 거친 서로 다른 영상 수다.

`manifest.json`은 준비 시작과 후보 검사 중간에도 원자적으로 저장한다. `source_acquisition.rounds`
에는 라운드별 manifest 경로·정책·`platform_outcomes`와 완료 판단 당시 `goal`(사용 가능 초수·필요 초수·핵심 분량·TikTok 선호 수)을 남긴다. 원본 준비 단계에서 실패했다면
전역 실패로 기록하며 아직 방문하지 않은 TikTok에 CAPTCHA 실패를 만들어 붙이지 않는다.

`platform_outcomes`는 `search_attempts`, `download_attempts`, `skipped_searches`, `skipped_reasons`,
`search_evidence`를 구분한다. 저장된 인증 차단으로 건너뛴 항목은 새 요청·새 CAPTCHA가 아니다.
`not_attempted`, `no_candidates`, `captcha`, `auth_required`, `rate_limited`, `access_denied`,
`download_failed`, `quality_rejected`, `duplicate`, `budget_exhausted`를 근거에 따라 기록한다.
단순 HTTP 403은 로그인 실패로 단정하지 않는다. Bing 등의 `site:` 검색은 해당 플랫폼을 대상으로
한 검색엔진 채널로 기록하며, 플랫폼 내부 검색 방문으로 표시하지 않는다.

## 기존 파일 재검토와 사용 구간

예전 기능 판정에서 제외된 파일도 원본 SHA와 실제 프레임을 유지한 채 최신 판정으로 재검토할 수 있다.
외관 중심 상품은 제품을 보여주거나 착용하는 장면 자체가 검토 대상이다. 다른 색상·모델의 보조
장면은 정확한 색상·제품·성능의 증거로 사용하지 않는다. 명시적인 사용 제외 기록
(`manual_usage_review.editing_eligible=false`)은 이후 자동 기능 판정으로 해제하지 않는다.

삽입 문구가 있는 파일은 `source_mask_review.py`에서 실제 시간·파일 해시·1080×1920 화면에
연결된 프레임과 블러 영역을 검토한다. 문구가 없는 구간을 택할 경우에도 모든 표본을 직접
확인하고 `no_overlays_confirmed=true`를 기록한다. 빈 OCR 결과만으로 승인하지 않는다.
`reviewed_intervals`는 편집에 허용한 구간이며 전체 파일의 승인을 뜻하지 않는다. Auto CapCut의
장면 추출·캐시 재사용·렌더링은 이 구간 밖의 장면을 거부한다. 원본 파일과 원 URL은 보존한다.

자동 수집은 `source_overlay_review.py`로 이 검토를 수행한다. 파일 앞·중간·끝의 최대 4초
구간을 실제 캔버스와 시간으로 추출한다. 새 검증은 구간마다 시작·끝과 중간 세 시점의
총 다섯 프레임을 사용하여, 종전 세 표본 사이에 길어진 자막도 더 확인한다. 원본과 가림
미리보기는 좌표·해상도를 유지하고 JPEG 전송량만 줄여 호출 크기 제한을 지킨다.
첫 Codex 시각 호출이 영역을 제안하며 별도의
호출이 모든 표본·영역의 가림 범위와 제품 가시성을 검토한다. 승인된 구간만 편집에
포함하고 핵심 기능도 그 구간의 프레임으로 다시 확인한다. 불확실하거나 제품이 가려지는
구간은 사용하지 않는다. 기존 저장 파일에 이 검토만 누락된 경우 외부 검색 전에 검토하며,
그 과정은 새 검색 요청·실패·검색 회차로 세지 않는다. 동일 입력의 거절/실패를 무한 반복하지 않는다.

독립 검토에는 원본 프레임과 동일 픽셀 좌표에 제안 영역을 회색으로 가린 미리보기를
함께 전달한다. 숫자 좌표만 보고 승인하지 않고 글자 끝·외곽선이 영역 밖에 남는지와
제품·동작이 가려지는지를 비교한다. 원본 증거는 수정하지 않는다. 실제 출력에서 남은
글자를 발견하면 기존 결과를 보존하고, 필요한 구간을 더 좁혀 별도 제안·독립 승인과
새 제작 버전으로 보정한다. 잘못 승인된 구간은 같은 파일의 공유 검증 캐시에서도 제외한다.
새 정책은 종전 정책의 공유 캐시를 그대로 재사용하지 않으며, 이미 저장된 제작 결과는
보존한다. 표본 검토가 전체 프레임의 완벽한 가림을 보증하지는 않는다.
# 플랫폼 수집 제외 설정

## 동일 파일의 글자·블러 검사 재사용

다른 제작 작업에 저장된 `source-mask-checks/<SHA256 앞 20자리>`의 완료 검사를
자동으로 찾는다. 현재 파일의 전체 SHA256, 검사 정책, 원본 파일과 모든 표본 프레임의
해시, 제안 지문, 캔버스와 승인된 정확한 구간을 다시 확인한 경우만 재사용한다.
깨진 JSON, 누락·변경·삭제된 증거, 다른 정책이나 파일의 검사는 캐시 미스로 처리하고
일반 시각 검사를 수행한다. 현재 작업의 ID·파일 경로·출처·권리 기록은 유지하며,
완료 표시는 제안과 승인 기록을 저장한 뒤 마지막에 쓴다.

재사용 대상은 동일 영상의 글자 영역과 검사 구간이다. 이전 레퍼런스에 대한 기능
승인을 옮기지 않는다. 현재 대본·주제의 핵심 기능은 승인된 구간에서 별도로 검사하며,
소스 개수나 플랫폼 최소 수량을 이 캐시만으로 충족 처리하지 않는다.

## 빈 화면과 구매 페이지의 장면 선택

실제 첫 표본이 거의 균일한 흰색·검은색 전환 화면이면 그 구간을 우선 선택하지
않는다. 흰 배경 위 실제 제품처럼 대비와 물체가 보이는 프레임은 이 조건에 해당하지
않는다. 시각 관찰은 제품·인물·쇼핑 웹 인터페이스·전환 화면을 구분하고, 쇼핑 페이지나
빈 전환 구간을 대본의 장면 순위에서 제외한다. 특정 유명인을 언급할 때 확인되지 않은
다른 인물의 모습으로 대신 표현하지 않고 실제 제품 장면을 보조로 사용한다.

이는 대본을 다시 쓰거나 중간 승인·제작 보류를 만드는 기준이 아니다. 일반 제품·사용
상황의 대체 장면을 선택하고, 모든 표본이 부적합한 예외에서는 미확인 임시 배치임을
명시한다. 완성 영상에서 실제 누락을 확인하면 이전 결과를 보존하고 별도 버전으로
장면을 교체하거나 잘못 승인된 구간을 철회한다. 철회는 새 구간 승인을 부여하지 않는다.
출력 화면 검토에서 결함이 확인된 소스 구간은 `data/source_review_withdrawals/<SHA-256>.json`에 실제 출력 근거와 함께 보존한다. 이 제외 기록은 검토 정책 버전과 독립적으로 같은 파일의 수집 검토 및 저장된 편집 계획에 적용한다. 제외 범위와 겹친 승인 구간은 잘라서 자동 승인하지 않고 전체 구간을 제외하며, 남은 구간의 기능 검토는 다시 수행한다. 기존 완성 MP4와 과거 검토 기록은 보존한다.

## 2026-10-11 TikTok 재수집·재제작

현재 로그인된 수집용 Chrome의 기존 TikTok 탭을 CDP로 연결해 19개 검색어,
중복 제거 후보 237개를 확인했다. 검색·상세 페이지 이동을 함께 최소 30초 간격으로
직렬 실행했다. 25개 다운로드 시도에서 세로 영상 22개를 저장했고 모두 FFmpeg로
끝까지 디코딩했다. 저장은 편집 적합성 또는 재사용 권리 승인과 구분한다.

`tiktok_download.py`는 해당 영상의 실제 브라우저 응답을 사용한다. 206 응답은 동일
URL·총 길이·표현 식별자, 겹치는 바이트와 빈 구간을 검사해 완전한 MP4일 때만
저장한다. 이번 실수집은 완전한 200 응답이었으므로 206 조립의 실제 플랫폼 검증을
완료했다고 주장하지 않는다. 누락 조각의 임의 요청이나 DRM·인증 우회는 하지 않는다.

사용자가 지정한 `tikvideo.app/ko`의 화면 입력·다운로드를 `tikvideo_download.py`의
제한된 대체 경로로 구현했다. 직접 MP4를 확보하지 못한 경우만 적용하며 로그인,
CAPTCHA, 429, 연결 실패에는 적용하지 않는다. 실제 두 대체 시도는 폼 제출 전에
`ERR_BLOCKED_BY_RESPONSE`로 실패했다. 응답 차단을 저장하고 이후 자동 반복하지
않는다. 이 사이트에서 파일을 저장한 실적은 없다.

검색 입력창의 표시 검색어와 URL이 다르거나 React가 `fill()` 값을 되돌리는 문제도
확인했다. 실제 표시 검색 컨트롤을 열고 전체 선택 후 순차 입력하며, 실제 응답의
검색어를 검사한다. 검색어가 제대로 적용되지 않은 결과를 새 검색 성과로 세지 않는다.

`data/tiktok-rework-20261011/`에 다운로드 원 URL, 진단, 원본 해시·사용 구간, 장면
프레임, 대본 9안, 음성, 새 편집 계획과 검증을 보존했다. 수면텐트는 3개 소스 파일
9장면, 패딩은 3개 파일 8장면으로 재제작했다. 동일 원본 시간 구간 반복은 각각 0초다.

파일홀더는 원본의 다이소 6매 벨크로 미니 홀더를 확보하지 못했다. TikTok 포켓
3개와 기존 YouTube의 벨크로 구조 예시를 사용한 11장면의 예시본이며, 전 구간에

`tools/share_tiktok_rework.py`는 이 예시본에만 명시적 비교 범위를 부여한다. 기본

출력 파일과 review 표시가 있어야 공개한다. 8796 포트는 파일 허용 목록만 제공하고
Studio API를 노출하지 않는다. 기존 출력·프로젝트 레지스트리·이전 공유는 보존한다.

## 기존 YouTube 탭에서 조각 영상 수신

일반 `download_candidate()`의 YouTube 경로도 `youtube_download.py`를 사용한다.
기존 수집용 Chrome의 YouTube 탭 한 개에 연결하며 새 브라우저·프로필이나 쿠키
파일 다운로더로 대체하지 않는다. 로그인·CAPTCHA·429 중지는 브라우저 검색과
같은 저장 상태를 확인하고, 페이지 이동에는 같은 플랫폼 간격과 잠금을 적용한다.

실제 플레이어의 MP4 응답 또는 `application/vnd.yt-ump` 응답만 받아 조립한다.
UMP는 정확한 영상 ID·형식 버전·바이트 구간·조각 종료를 검사하며 다른 영상의
미리 불러온 응답과 빈 구간, 충돌·암호화된 응답은 완료 파일로 쓰지 않는다.
표시된 플레이어의 길이와 해상도가 일치하고 FFmpeg 전체 디코드가 성공해야 저장한다.
전체 디코드의 정상 종료만으로 끝난 것으로 판단하지 않는다. 실제 디코딩한 영상의
마지막 시각(`out_time_us`)이 플레이어 전체 길이와 0.25초 이내로 일치해야 한다.

21.133초까지만 수신된 상태에서 정상 종료했다. 이 파일은 별도 보존하고 같은

수신 기록에 남긴다. 끝난 뒤 해당 플레이어 재생을 멈춘다.

## 현재 제작 품질 계약 (2026-10-14 대조·갱신)

각 레퍼런스는 독립적으로 제품과 동작을 분석한다. 같은 브랜드만으로 소스 풀을 합치거나 이전 실패 대본의 표현을 재사용하지 않는다. 집필의 단일 계약은 `hotpost/writing/RULES.md`이며 A/B/C 세 안은 심리 메커니즘과 갈등 구조를 구분한다. 특정 색·부위·가족 구성은 공통 필수 요소가 아니다.
