## 제품 매력 중심 검수와 레퍼런스 보정 (2026-10-13)

영상은 제품의 매력을 보여주고 대본은 재미·호기심을 전달한다. 전체 주제가 분명하고
사용·설치·디테일·장점이 자연스럽게 이어지면 문장마다 같은 사건이나 인물을 재현할
필요가 없다. 여행·친구·가족 이야기, 특정 음식물이나 감정 장면의 부재는 단독으로
수집·재편집을 유발하지 않는다. 관련 제품 장면을 맥락·지원 장면으로 사용할 수 있다.
동작 자체를 직접 시연한다고 제시할 때에는 그 동작의 실제 핵심 상태를 남기지만,
지원 장면에는 보이지 않은 이야기 동작을 증명하도록 요구하지 않는다.

새로운 구도·기능·사용 과정·마무리를 추가하는 제품 재등장은 자연스럽게 허용한다.
제품을 알아볼 수 없거나 매력이 드러나지 않는 흐름, 실제 다른 기능·부품을 제품의
직접 시연으로 오인시키는 연결, 실제 반대 동작과 구체적 사실 오류는 검토한다.
단순한 문장 일치 보완 의견은 `advisories`에 보관하며 실패·재수집·보완 횟수로 세지 않는다.
원본 시간 재사용 지표와 정지 프레임 유지 표시도 검토 참고 정보로 보관한다. 숫자만으로
불합격을 추가하지 않으며 실제로 제품 전달을 해치는 반복·정지 화면은 검수 결과로 보완한다.

`product_appeal_review.py`의 공통 계약을 순위 선택·소스 확보 검사·완성본 검수에
적용한다. 소스 승인·실제 파일/구간·핵심 프레임 검증은 보존하고 검토 정책 버전을
바꿔 과거 승인·거부 캐시를 새 해석으로 자동 승격하지 않는다.

`tools/calibrate_reference_quality.py`는 현재 터진 게시물의 실제 원작 10개를 읽기
전용으로 비교한다. 6개로 규칙을 보정하고, 규칙을 저장한 뒤 사전 분리한 4개를
검수한다. 전체 영상의 실제 원본 PTS를 약 0.5초 간격으로 추출하고 별도 실제 첫
프레임을 제공한다. 원작 제작자의 워터마크·얼굴 표지·댓글 문구 등은 우리 신규
제작 계약과의 차이로 따로 기록한다. 실제 Instagram 업로드 포스터가 제공되지
않은 경우 소스 첫 프레임을 그 포스터라고 주장하지 않는다. 이 비교는 완전한
청감·자막 시간축 검사가 아니며 인기 게시물이라는 이유만으로 통과를 강제하지 않는다.

## 대기·진전·누적 보완 계약 (2026-10-13)

플랫폼·후보·수집 회차의 누적 시간을 하위 작업의 실행 시한으로 배분하지 않는다.
기존 시간 예산 설정은 구 설정을 읽기 위한 호환 필드이며 실행 제한에 사용하지 않는다.
TikTok 최종 검색 경계는 검토한 제품 명사·번역·수식어 사전을 사용하고, 모델의 제품 분류
표시만으로 검색어를 승인하지 않는다. 사전에 없는 제품이나 번역·수식어의 실제 근거를
확인하지 못한 문구는 TikTok에서 생략하며 다른 플랫폼의 장면 검색어는 유지한다.
새 제품 범위를 늘리려면 검토한 명사 번역과 수식어 대응을 사전에 추가해야 한다.
직접 지정한 검색어도 원본 근거로 검사한 뒤 실제 TikTok 공급자 검색 목록에 전달한다.
명시한 조건이 있으면 승인한 해당 명사구만 사용하며, 기본 모델 검색어로 덮어쓰지 않는다.
L자·엘자·L-shaped 등 형상 수식어는 원본에서 해당 형태를 확인한 경우에만 허용한다.
요청 간격·브라우저 사용·모델 서비스 대기는 실패가 아니며 실제 실행과 분리한다.
다운로드는 선택한 영상의 유효 수신 데이터가 증가하면 계속 진행하고, 같은 데이터나
단순 생존 알림만 반복되는 경우에는 진전으로 인정하지 않는다. 작업자의 상위 감시도
총 경과 시간이 아니라 유효 단계 진전 이후의 무응답을 검사한다.

로컬 검토의 무진전도 중지 기준에 포함한다. 실패한 같은 입력·정책의 검토는 다시
호출하지 않으며 전송 정책 개선 등 입력 조건이 바뀌면 새 정책에서 한 번 검토한다.
검토 프레임은 원래 해상도와 좌표를 유지하고, 전송이 어려운 프레임만 여유 첨부 용량을
사용한다. 프레임별 1 MiB 및 전체 분석 요청 12 MiB 검사는 유지한다.

장면 부족·반복·워터마크 보완은 대사별 요구와 검토된 영상 프레임·사용 제한을 대조한
`scene_requirements`가 충족된 뒤에만 재편집한다. 파일 확보 자체는 장면 충족 증거가 아니다.
일부 요구라도 새로 충족되면 진전으로 기록하며, 미충족이 계속되면 새 후보를 기다린다.

품질 보완은 [품질 진전 기반 중단 계약](quality_progress_policy.md)을 따른다. 실제 결함
해결과 관련 새 근거가 있으면 계속하며, 같은 실패 방법·A→B→A 순환은 실행 전에 차단한다.
실제 새 보완 편집본이 생성된 때만 누적 사용량이 증가한다. 이전 3회 설정과 회계는
호환·역사 기록으로 보존하고 품질 중단 한도로 쓰지 않는다.
수집 대기·실행 전 실패·모델 장애·JSON 형식 보정은 횟수를 소비하지 않는다.
같은 편집 입력을 다시 렌더하지 않고, 변경된 구간·마스크·썸네일 등 실제 입력을
해시로 기록한다. 복구 도구가 한도를 늘리는 동작은 제거한다.

모델 처리 용량 부족은 같은 CLI 기본 모델의 공통 대기 상태를 SQLite에 보존한다.
복구 확인은 한 요청으로 수행하고, 재시도는 간격을 늘려 분산한다. 실제 실패 재시도는
작업별 최대 3회로 제한하며 콘텐츠 보완 횟수와 별도로 관리한다. 원본 JSON 응답을
보존하고 형식 보정 호출은 최대 한 번 수행한다. 기존 완료 결과와 세션을 재생성하지 않는다.

2026-10-13 독립 검증 보완: 품질 대본 재작성 뒤 일반 편집도 새 보완 렌더로 누적한다.
실행 직전에 실제 편집 입력과 요구 장면 구간을 고정하고, 검토 문구·시각만 바뀐 경우
새 입력으로 세지 않는다. 장면 승인은 원본·프레임의 실제 SHA, 현재 요구 해시,
관찰한 프레임 사이의 시간 범위와 최종 선택 구간까지 대조한다. 동일 입력의 승인과
거부는 파일·증거가 바뀌기 전까지 재사용한다. 큰 영상 증거는 요청당 전송 상한에
맞춰 구간별로 분할하며, 의미 있는 CLI 진전을 상위 집필 대기에도 전달한다.
CAPTCHA·휴식 때문에 실제 영상 요청을 하지 않은 후보는 다운로드 미시도로 남긴다.

`tools/validate_latest_failed_production.py`는 사용자가 명시적으로 요청한 최근 실패 영상의
실제 검증용 1회 제작 도구다. 자동 보완 횟수·상한·이전 결과를 초기화하지 않으며,
별도 승인 영수증과 수동 렌더 한도 1회를 저장한다. 실제 장면 충족 전에는 렌더하지
않고, 완료한 로컬 검토·재수집의 같은 입력 확정 실패 및 새로운 유효 방법 소진을 중지한다.
브라우저·모델 대기는 실패 횟수에서 분리한다. 자동 보완 한도를 늘리는 복구 도구가 아니다.
추가 수집 완료 결과는 입력 키·파일 SHA와 함께 체크포인트에 저장한다. 후속 검토에서
모델 혼잡이 발생하면 받은 파일의 검토부터 재개하며 외부 검색·다운로드를 반복하지 않는다.
이 검증에서 원본에 있던 형상 수식어 전달 오류를 교정한 경우에는 이전 무진전 기록을
보존한 채 변경 조건 1회를 별도 영수증에 기록한다. 같은 조건의 완료 시도를 재실행하지 않는다.
필요 장면이 미충족이면 원본 영상에 장면이 없는 경우와, 장면이 검토 구간 밖에 있는 경우를
구분한다. 이미 받은 영상의 밀집 프레임에서 새로운 동작이 실제 관찰되면 원본 SHA·시간
범위를 보존한 새 구간으로 한 번 검토한다. 앞선 거부와 무진전 이력을 초기화하거나
진단 프레임을 사용 승인으로 승격하지 않는다. 장면 검토에는 승인된 실제 시간 프레임을
충분히 전달하고, 모든 필요한 장면의 파일·구간 근거가 확보되면 남은 비교 호출을 중지한다.

실제 검증 초안에서 발견한 보완: 장면 확보 검토는 승인 대본의 해당 대사·인접 대사와
원본 제품 근거, 소스의 실제 사용 제한을 함께 비교한다. 같은 기능의 별도 부품을
대본이 설명하는 제품의 일체형 끝부분으로 승격하지 않는다. 기능 모드의 색상·사소한
디자인 차이는 허용하되 제품과 부품의 관계가 맞지 않으면 직접 대사 증거로 승인하지 않는다.
필요 동작이나 완료 상태를 입증하는 실제 핵심 프레임과 이유도 별도로 결속한다.
최종 선택 구간에서 그 프레임이 실제 보이는지 렌더 전에 검사하며, 가능한 보정만
원래 대사 길이·승인 범위·원본 재사용 제한 안에서 수행한다. 불명확한 경우 보류한다.
실제 디코드 프레임의 노출 끝은 다음 PTS·명시된 native duration으로 확인하며 출력
프레임레이트를 원본 노출 시간으로 추정하지 않는다. 외부 렌더의 재선택에도 선택 구간을
유지하도록 좁은 구간을 고정하고, 이전 검토·실패 초안·보완 횟수를 보존한다.
품질 대본 재작성으로 승인 대본·음성이 바뀐 경우에는 이전 편집의 대사 구간을 새
대본의 문맥으로 사용하지 않는다. 렌더와 분리한 로컬 분석 계획을 현재 입력에 결속해
준비하고, 과거 시각 문제의 대상 구간을 새 실제 대사로 명시해 연결한 뒤 장면을 검토한다.
이 준비는 보완 렌더 횟수를 소비하지 않으며, 구간 대응이 불명확하면 보류한다.

## 신규 일별 자동 제작의 완성본 검토 (2026-10-11)

`studio_auto_top_enabled`는 자동 제작, `studio_daily_quality_enabled`는 새 자동 선정 작업의
완성본 검토를 활성화한다. `studio_auto_start_date_kst` 이전에는 자동 등록하지 않는다.
2026-10-12부터 적용하도록 설정했으며, 기존 수동 작업이나 이전 완성본을 소급 재개하지 않는다.

수집 → 공식 Codex 대본 3안·선정 → 개인 목소리 → 정책 v3 소스 확보 → 편집 →
실제 완성 영상 검토 → 필요하면 문제 장면 재수집·새 편집본 → 재검토 순서다.
완성본 전체에 고르게 분포한 12프레임과 레퍼런스 전체 12프레임, 각 대사 구간의

2026-10-12 변경: 과거 CAPTCHA 기록이 있으면 그때의 기존 수집용 Chrome 화면을 다시 읽어

페이지 이동·이미지 업로드는 같은 플랫폼에서 시작 시각 기준 최소 10초 간격을 적용하며 이미 경과한 시간을 차감한다. 첫 요청은 즉시 실행하고, 네트워크 실패는 20초 후 최대 한 번 재시도한다. 인증 확인에서 CAPTCHA나

기본 2장으로 줄이고, 실제 요청 시각과 작업 종류를 검색 감사 기록에 남긴다.

시각부터 10분으로 제한한다. 휴식 만료가 자동 재시도를 등록하지는 않으며, 다시
인증이 요구되면 해당 검색을 멈추고 다른 공급자나 확보한 소스로 진행한다.
쿠키 초기화나 인증 우회는 하지 않으며, 이 간격이 CAPTCHA를 없앤다고 보장하지 않는다.

줄바꿈 또는 쉼표로 구분한다. 다진 마늘은 일반 요리나 달걀 검색어 대신 실제로

영상으로 사용할 수 있다. 실제 파일 해시·검토 프레임·사용 제한을 저장하고
`context_only`로 구분한다. 마늘이 들어 있다는 사실이나 마늘 보관·변색·안전성의
증거로 승격하지 않는다. 편집 AI와 저장된 후보 모두 직접 시연(`direct`) 대신
맥락 장면(`context`)으로 제한하며 삽입 문자의 블러 검토는 계속 필요하다.
