# 인스타 모바일 업로드

완성된 영상 한 편에 기존 설정·로그인·초안·검증 결과를 재사용해 **리틀리 → Edits → Instagram → 본인 고정댓글**을 진행한다. 영상 제작·새 PC 이전·VPN 서버 구축으로 범위를 넓히지 않는다.

## 시작

스킬명 없이 “이 영상 리틀리부터 업로드랑 고정댓글까지 진행해줘”라고 요청할 수 있다. “업로드 준비”는 최종 공유 전까지, “초기 연결만”은 설정·연결 확인까지만 진행한다. 문서/스킬 정리는 실제 게시 재개 지시가 아니다.

현재 폴더의 실제 insta_auto clone을 찾아 `AGENTS.md`, `docs/COLLABORATION.md`, `docs/WORKFLOW.md`, `docs/MOBILE_REELS_WIREGUARD.md`와 최신 로컬 중지/작업 기록을 확인한다. 세부 실행·검증·재개는 저장소 문서가 원본이다. 처음 사용할 때만 `docs/MOBILE_UPLOAD_START.md`를 읽는다.

[사전 확인](scripts/preflight.py)을 저장소 Python으로 실행해 기존 설정·공유 이력·고정댓글 상태를 조회한다.

```powershell
.venv/Scripts/python.exe <이 스킬 폴더>/scripts/preflight.py --repo <실제 clone> --shortcode <영상 ID>
```

영상·계정·폰은 대화와 기존 작업에서 먼저 찾고, 여러 대상 중 선택이 필요한 경우만 묻는다. 저장된 설정은 로그인/연결 성공이 아니다. 기존 Chrome 탭과 실제 계정을 확인하고, 빠진 Instagram(상품 확인용)·리틀리(게시 계정 연결)·쿠팡 인플루언서 ‘내 스토어’ 로그인만 요청한다. 웹 상품 확인 계정과 폰 게시 계정은 다를 수 있다. 비밀번호·인증 코드는 받지 않으며 기존 프로필을 유지한다. 폰에서만 가능한 잠금 해제·로그인·연결 승인만 사용자에게 맡긴다.

## 한 편 진행

1. **준비물 재사용.** 현재 완성 영상·표지·본문·고정댓글·게시 계정·폰과 기존 초안을 확인한다. 게시 문구는 `docs/POST_COPY_RULES.md`를 따른다. 동일 계정/영상이 `submitting`·`unknown`·`submitted`면 재게시하지 않고 남은 확인/고정댓글 단계만 이어간다.
2. **상품과 우리 원링크.** 기존 검증/수신 DM/링크 기록 → 원작 본문·프로필의 공개 링크/상품 번호 → 그래도 미확정일 때만 승인된 키워드 댓글 1회·모바일 수신 DM 버튼 순서로 상품/옵션을 확인한다. PC에 DM 버튼이 없다고 재댓글하지 않는다. `docs/POST_PREPARATION_UI_20261022.md`와 `hotpost.coupang_onelink`의 우리 시스템으로 본인 `AFFSDP / CREATOR` One-Link를 확보하고 태그·상품/옵션·실제 랜딩을 대조한다. `/a/` 단축 링크로 대체하지 않으며 범위 밖 스토어 상품을 복구하지 않는다.
3. **리틀리 먼저.** 기존 자동화/다음 게시물 예약과 소유권을 확인해 재사용한다. 다음 게시물·모든 댓글·최신 고정 DM·후킹 버튼·검증한 One-Link, 자동 답글 ON·팔로우 요청 OFF를 설정한다. 새 자동화는 기본 답글 3개에 추가 2회로 총 5개이며 기존 답글을 또 추가하지 않는다. 저장 후 다시 열어 계정·문구·링크·조건·답글·활성 상태를 확인한 뒤에만 모바일 업로드를 진행한다. 실제 UI 단계는 `docs/MONETIZATION_PLAN_20261015.md`의 13단계 중 현재 모바일 문서가 채택한 조건을 따른다. 저장 결과 불명/예약 충돌은 중복 생성하지 않는다.
4. **폰과 Edits.** 등록 기기·연결·게시 계정을 확인하고 기존 작업/프로젝트/미디어를 이어 쓴다. 새 Wi-Fi·새 폰은 `docs/PHONE_SETUP.md`를 따라 기존 등록을 보존한다. 필요한 새 연결 포트/폰 승인만 요청한다. 분위기에 맞는 음악을 선택해 **추가 음악 볼륨 70%**를 실제 화면에서 확인하며 내레이션·‘모든 오디오 클립에 적용’은 유지한다. 기존 검증이 유효하면 다시 만들지 않는다. 선행 누락 복구에는 기존 패키지를 보존하고 `bind-littly`로 결속한다.
5. **Instagram 게시.** 전달된 게시 계정·정확한 Unicode 본문·실제 표지를 확인하고 `review-cover` → `ready`로 현재 증거에 결속한다. 요청에 실제 게시가 포함되면 현재 `approval_sha256`으로 공유를 한 번 실행한다. 같은 범위의 승인을 반복 요청하지 않는다. 완료 안내 부재/연결 끊김은 `unknown`을 보존하고 실제 본인 게시물을 읽기 확인하며 필요하면 `confirm-result`로 마무리한다. 다른 폰으로도 재공유하지 않는다.
6. **본인 댓글 작성·고정.** 실제 우리 게시물/작성 계정과 준비된 댓글을 확인한다. 기존 동일 댓글·제출 시도를 먼저 조회해 중복을 피한다. 없을 때만 Unicode/줄바꿈 대조와 시도 기록 후 한 번 작성한다. 해당 댓글을 **길게 누르기 → 고정 → 목록을 다시 열어 핀 표시 확인**까지 진행한다. 이미 고정됐으면 반복하지 않으며 필요하면 메뉴의 ‘고정 취소/해제’를 읽기 확인한다. 제출 불명은 목록 확인만 하고 재댓글하지 않는다. 고정 실패 때문에 영상을 다시 올리지 않는다.
7. **결과 확인.** 리틀리가 의도한 실제 우리 게시물에 연결됐는지 확인한다. 업로드·댓글 작성/고정·리틀리 연결·실제 이용자 댓글→DM 전달을 구분해 보고한다. 본인 고정댓글을 DM 전달 증거로 쓰지 않는다. 자연 댓글이 없으면 DM 전달은 미검증으로 남기며 테스트 댓글/DM이나 다음 영상을 임의 시작하지 않는다.

상태·외부 동작 전 시도·실제 저장/게시/핀 확인 근거는 기존 Git 제외 작업 폴더에 남긴다. 화면이 다르면 현재 UI부터 확인하고 추측 좌표나 이 스킬 작성 대화의 일회성 스크립트·개인 ID를 재사용하지 않는다. 시각 확인을 청감 승인으로 표현하지 않는다.
